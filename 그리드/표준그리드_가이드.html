JEIL_AX 표준 편집 그리드 — 사용 가이드 (단일 출처)

이 문서는 jeil_ax의 모든 편집 가능한 화면 그리드가 따라야 하는 표준이다. 컴포넌트: app/lib/grid.js + app/lib/grid.css · 데모: 그리드/index.html(빌드 주입으로 자기완결 — file:// 더블클릭으로 바로 열림) · 샘플: 그리드/샘플양식.csv 관리 에이전트: grid-standardizer(로컬). 표준이 바뀌면 이 문서·데모·샘플을 함께 갱신한다.

0. 핵심 원칙

  1. 편집 가능한 그리드는 직접 <table> + innerHTML로 만들지 않는다. createGrid()를 쓴다. (순수 읽기 전용 대시보드 표는 예외 — 표준화 대상이 아니다.)
  2. grid.js는 UI만 담당한다. 데이터 조회·저장·발급은 app/lib/api.js(portalApi) 또는 Edge Function 호출을 콜백(onSave/onBulkAction/onRowAction)에서 처리한다. DB·인증 로직을 grid.js에 심지 않는다.
  3. CSS는 .grid__ 스코프만. 전역 table/th/td를 재정의하지 않는다(같은 화면의 다른 표 보호).
  4. 외부 라이브러리·CDN 금지. 바닐라 ESM. 내보내기는 CSV(UTF-8 BOM).
  5. 비밀값·운영 데이터 직접 노출 금지(CLAUDE.md §1). 한국어 UI.

1. 빠른 시작

<link rel="stylesheet" href="./lib/grid.css">
<div id="myGrid"></div>
<script type="module">
  import { createGrid } from "./lib/grid.js";
  const grid = createGrid("#myGrid", {
    keyField: "id",
    selectable: true, search: true, columnFilter: true,
    editable: true, editToggle: true, paste: true, exportCsv: true, copy: true,
    rows: await portalApi.getSomething(),
    columns: [
      { key:"code", label:"코드", pasteKey:"code" },
      { key:"email", label:"이메일", type:"email", editable:true, pasteKey:"email",
        validator:(v)=> !v || /^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(v) || "이메일 형식 오류" },
      { key:"name", label:"담당자", editable:true, pasteKey:"name" },
    ],
    bulkActions: [{ id:"save", label:"💾 저장", btnClass:"ok" }],
    onBulkAction: (id, g) => { /* g.getDirty() / g.getSelected() 로 처리 */ },
  });
</script>

주의(ESM): 위 예제처럼 import를 쓰는 실제 화면은 file://로 직접 열면 모듈 로드가 막힌다 — 정적 서버로 서빙(루트에서 python -m http.server 후 http://localhost:8000/...) 또는 Vercel 배포본에서 확인한다. (데모 그리드/index.html은 예외다 — 빌드가 컴포넌트를 인라인 주입해 자기완결이라 file:// 더블클릭으로도 열린다. 컴포넌트 수정 후엔 python 그리드/_build_html.py 재실행으로 데모를 최신화한다.)

5. 엑셀 붙여넣기 규약

편집 모드에서 편집 셀에 Ctrl+V 하면 탭/개행을 파싱해 채운다. 자동 인식: - @ 포함 값 → pasteKey:"email" 컬럼 - keyField 값과 일치하는 값 → 그 행에 정확 매칭(행 순서가 달라도 OK) - 나머지 → pasteKey:"name" 컬럼 - 거래처코드 열이 없으면 붙여넣기 시작 행부터 순서대로

샘플: 그리드/샘플양식.csv (거래처코드,담당자이메일,담당자명).

5.1 왼쪽 고정열(가로 스크롤이 필요한 넓은 표)

열이 많아 가로로 밀어야 하는 표는 앞쪽 한두 칸을 왼쪽에 붙여 두면 어느 행인지 놓치지 않는다. 표준 그리드는 고정열 기능을 따로 갖지 않고 cssClass 한 줄로 화면이 얹는다.

columns: [
  { key:"no",    label:"NO.",  width:"54px", cssClass:"pl-fix1", filter:false, sortable:false },
  { key:"gubun", label:"구분", width:"74px", cssClass:"pl-fix2" },
  ...
]

#myGrid{--w1:54px; --w2:74px;}                 /* columns 의 width 와 **같은 값**이어야 한다 */
#myGrid .pl-fix1, #myGrid .pl-fix2{position:sticky; z-index:2; background:#fff;}
#myGrid .pl-fix1{left:0;          width:var(--w1); min-width:var(--w1); max-width:var(--w1);}
#myGrid .pl-fix2{left:var(--w1);  width:var(--w2); min-width:var(--w2); max-width:var(--w2);}
#myGrid .grid__th.pl-fix1, #myGrid .grid__th.pl-fix2{z-index:5; background:var(--navy);}
#myGrid .grid__filter-row th.pl-fix1,
#myGrid .grid__filter-row th.pl-fix2{z-index:5; background:var(--soft);}

지켜야 할 것 — 하나라도 빠지면 표가 깨진 것처럼 보인다.

규칙 어기면
층 순서 일반 td 0 · 고정 td 2 · 필터행 th 3 · 헤더 th 4 · 고정 헤더/필터 th 5 고정열 td 가 헤더보다 위면 세로 스크롤 때 지나간 행이 네이비 헤더를 뚫고 보인다(2026-09-22 실측)
폭 width/min-width/max-width 셋 다 못박고 columns 의 width 와 같은 값 두 번째 고정열의 left 오프셋이 어긋나 열이 겹치거나 틈이 생긴다
배경 고정열은 불투명 배경이 필수. 줄무늬·호버도 고정열에 다시 지정 밑으로 지나가는 셀이 비쳐 보이거나, 고정열만 줄무늬가 빠져 다른 행처럼 읽힌다
좁은 화면 @media (max-width:1100px){ .pl-fix1,.pl-fix2{position:static} } 화면 폭의 절반을 고정열이 차지한다

grid.css 의 .grid__filter-row th 는 top:var(--g-head-h) 를 쓰고, grid.js 가 실제 헤더 높이를 재어 이 변수를 채운다. 고정값이면 글꼴·패딩이 조금만 달라져도 틈이 생겨 그 사이로 본문이 비친다.

대용량 목록의 입력 반응 — 검색·컬럼필터는 입력이 멎고 120ms 뒤에 한 번만 다시 그린다. 수천 행에서 글자마다 렌더하면 그대로 입력 지연이 된다(5,609행 렌더 1.9초 실측).

5.2 넓은 목록 — 폭 조절 · 화면맞춤 · 항목간 이동

열이 20개를 넘으면 가로 스크롤이 기본값이 된다. 세 가지를 옵트인으로 켤 수 있다. 켜지 않은 화면은 동작이 종전과 완전히 같다.

createGrid("#myGrid", {
  columns: [...], rows,
  resizable: true,   // 열 경계를 끌어 폭 조절(두 번 누르면 그 열만 원래대로)
  fitWidth: true,    // setFit(true) 로 화면 폭에 맞추기
  cellNav: true,     // 방향키로 셀 커서 이동 · Enter 로 onCellActivate
  onColResize: (key, px, all) => savePref(all),   // 저장은 호출측이 한다
  onCellActivate: (row) => openDetail(row),
});
인스턴스 메서드 하는 일
setFit(on) 화면맞춤 켜기/끄기
getFitOverflow() 맞춤을 켰는데도 화면 밖에 남은 px(0 이면 다 들어옴)
refitWidths() 창 크기가 바뀌었을 때 다시 계산
getColWidths() / setColWidths(w) 사람이 정한 폭 읽기/복원
scrollToColumn(key) 그 열까지 스르륵 이동 + 잠깐 강조(열 점프)
focusTable() 표에 키보드 초점(모달을 닫고 방향키로 이어 갈 때)

반드시 알아야 할 것

  1. table-layout:fixed 는 표 폭이 auto 면 무시된다. 그래서 renderColgroup() 이 열 폭 합계를 인라인 width 로 표에 직접 박는다. CSS 에서 .grid__table--fixed 에 width 를 주면 안 된다 — 2026-09-22 실측에서 <col> 에 600px 을 줘도 열 폭이 1px 도 안 변했고, 폭 제어 전체가 조용히 죽어 있었다.
  2. 고정열에는 fixedWidth: true 를 준다. 맞춤이 폭을 바꾸면 화면이 계산해 둔 sticky left 오프셋과 어긋나 고정열이 겹친다(§5.1).
  3. 직접 끌어 정한 폭은 맞춤이 덮지 않는다. 사람이 정한 열은 그대로 두고 나머지가 남는 자리를 나눠 갖는다 — 조절한 의미가 사라지지 않게.
  4. fitMin 을 열마다 준다. 없으면 46px 까지 줄어 값을 알아볼 수 없다. 최소폭 합이 화면보다 크면 가로 스크롤이 남는다 — getFitOverflow() 로 얼마나 모자란지 화면이 말하게 한다. 조용히 실패하지 않는다.
  5. 셀 커서와 모달의 방향키가 부딪히지 않게 한다. 모달을 열 때 초점을 모달로 옮기고 (focus()), 닫을 때 focusTable() 로 돌려준다.

5.3 항목 고르기 — 표에 넣을 열을 사람이 고른다 (피벗식)

열이 많아지면 "다 보여 주기"와 "필요한 것만 보기"가 부딪힌다. 화면마다 프리셋 버튼을 만들지 말고 표준 열 선택기를 켠다. 한 화면에 진실이 하나만 남는다.

createGrid("#myGrid", {
  columns: [
    { key:"no",   label:"NO.",   width:"54px", cssClass:"pl-fix1", required:true },  // 못 빼는 열
    { key:"memo", label:"비고",  width:"200px", hidden:true },                        // 처음엔 빼 둔 열
    ...
  ],
  columnPicker: true,            // 툴바에 「▦ 항목 10/12」 버튼이 생긴다
  columnPickerLabel: "▦ 항목",   // 라벨을 바꾸고 싶을 때만
  onColumnsChange: (st) => localStorage.setItem(KEY, JSON.stringify(st)),
});
// 복원
const st = JSON.parse(localStorage.getItem(KEY) || "null");
if (st) grid.setColumnState(st);

화면에 보이는 것 — 툴바 버튼을 누르면 두 칸 패널이 열린다. 왼쪽이 표에 넣은 항목(표의 순서 그대로), 오른쪽이 뺀 항목. 항목을 누르면 반대편으로 건너가고, 끌어다 놓으면 순서까지 바뀐다. 체크박스 한 줄짜리 목록이 아니라 두 칸으로 나눈 이유는 무엇이 빠져 있는지가 한눈에 보여야 하기 때문이다 — 체크가 풀린 줄은 눈에 띄지 않는다.

columns 속성 뜻
required: true 항목 고르기에서 뺄 수 없다. 🔒 로 표시된다. 키 열, 그리고 §5.1 왼쪽 고정열에 준다 — 고정열이 빠지면 뒤 열의 sticky left 오프셋이 어긋난다
hidden: true 처음부터 빼 둔 상태로 시작
인스턴스 메서드 하는 일
getColumnState() / setColumnState(st) {order, hidden} 읽기·복원. 복원은 onColumnsChange 를 다시 부르지 않는다(저장 루프 방지)
resetColumns() 처음 상태(=columns 정의)로
showColumn(key, on) 한 열만 넣기/빼기
getVisibleColumns() 지금 보이는 열 키 배열
openColumnPicker(on) 패널 열기/닫기

반드시 알아야 할 것

  1. 빼 둔 열은 화면에서만 빠지는 게 아니다. 검색·컬럼필터·CSV·복사·방향키 이동이 전부 보이는 열만 본다. 안 보이는 열에서 검색이 맞아 행이 나오면 왜 나왔는지 알 수 없고, 화면과 내려받은 파일이 다르면 그게 더 혼란스럽다.
  2. 저장은 화면이 한다(§13.3). grid.js 는 저장소를 모른다. onColumnsChange 로 받아 화면이 보관한다. 금액·개인정보가 실린 화면은 localStorage 대신 sessionStorage 를 쓰거나 저장하지 않는다(§1.7 · §6).
  3. 저장해 둔 뒤에 열이 늘 수 있다. setColumnState() 는 모르는 키를 버리고, 저장본에 없던 새 열을 뒤에 붙인다 — 배포 뒤에 새 열이 사라져 보이지 않게.
  4. 화면맞춤과 같이 쓰면 열을 넣고 뺄 때마다 남는 폭을 다시 나눈다. 따로 부를 것 없다.
  5. 패널은 .grid 를 기준으로 툴바 오른쪽 아래에 뜬다. 표 위 두세 줄을 잠깐 덮지만 닫으면 바로 보인다 — 표를 밀어내지 않는 쪽을 골랐다.

5.4 2단 헤더 — 열 그룹(옵트인)

엑셀 서식을 그대로 옮겨야 하는 표는 상위 그룹(예: 계약금/중도금/잔금)이 하위 열 여러 개를 묶는다. 하위 열 이름이 그룹마다 같으면(예: 「비율」이 세 번) 한 줄 헤더로는 라벨을 길게 늘여 써야 해서 열이 좁아진다. groupHeader:true 를 켜면 헤더 맨 위에 그룹 행이 하나 더 생긴다 — 켜지 않으면(기본값 false) 기존 화면의 DOM·CSS·스크롤이 한 픽셀도 달라지지 않는다.

createGrid("#el", {
  groupHeader: true,
  columns: [
    { key:"vol",      label:"권" },                                 // group 없음 → 빈 칸
    { key:"dp_rate",  label:"비율",     group:"계약금" },
    { key:"dp_amt",   label:"발행금액", group:"계약금" },
    { key:"dp_slip",  label:"전표번호", group:"계약금" },

columns 속성 뜻
group 상위 그룹 라벨. 표에 보이는 열 순서를 훑어 값이 같은 열이 연달아 있으면 colspan 으로 묶는다. 없으면 빈 칸(연달은 빈 칸도 하나로 묶인다). 같은 group 이 열 순서상 떨어져 있으면 묶지 않고 각각 별 칸으로 그린다
groupClass 그 그룹 칸(th.grid__gth)에 붙는 CSS 클래스(색 구분용) — 같은 그룹의 열 중 하나라도 지정하면 그 그룹 칸에 적용
exportLabel CSV/복사 헤더에 쓸 이름을 직접 지정한다(있으면 항상 최우선)

동작 규칙

  1. 열 순서가 「항목 고르기」(columnPicker)로 바뀌면 그룹 묶음도 그때그때 보이는 순서로 다시 계산한다 — 결과를 저장해 두지 않는다.
  2. CSV/복사 헤더는 계속 한 줄이다. groupHeader 가 켜져 있고 그 열에 group 이 있으면 헤더 이름을 "계약금 비율"(그룹 + 공백 + 라벨)로 낸다 — 안 그러면 같은 하위 열 이름이 여러 번 나와 구분이 안 된다. exportLabel 이 있으면 그게 항상 최우선이다.
  3. 「항목 고르기」 목록은 그룹 · 라벨로 보여 준다(그룹 없는 열은 라벨만).
  4. 화면맞춤(fitWidth)·열폭 드래그(resizable)와 같이 써도 된다 — 폭은 colgroup 이 맡고 그룹 칸은 colspan 만 맞추면 되므로 그대로 동작한다.

sticky 층 — §5.1 왼쪽 고정열과 같이 쓸 때

행 top z-index
그룹 행 .grid__group-row th 0 5
헤더 행 .grid__th var(--g-group-h,0px) 4
필터 행 .grid__filter-row th calc(var(--g-group-h,0px) + var(--g-head-h,32px)) 3

--g-group-h 는 groupHeader 가 켜졌을 때만 실제 그룹 행 높이로 채워진다(syncHeadOffset()). 꺼져 있으면 이 변수를 아예 설정하지 않아 CSS 기본값 0px 이 그대로 먹고, 위 표의 top 값은 그룹 행이 없던 기존 화면(§8 적용 사례)과 완전히 같아진다. 왼쪽 고정열(§5.1)의 pl-fix1 류 셀렉터를 groupHeader 화면에서 쓸 때는 .grid__gth.pl-fix1 도 함께 position:sticky;left:… 로 고정해야 가로 스크롤 때 그룹 칸이 밀리지 않는다.

6. 새 편집 화면 추가 레시피

  1. 화면에 <div id="xGrid"> + grid.css 링크, <script type="module">에서 createGrid import.
  2. 데이터는 portalApi/Edge Function으로 받아 rows로 전달(또는 setRows).
  3. 편집/일괄 작업의 실제 저장은 콜백에서 portalApi.* 또는 callFn(...) 호출 후 setRows로 갱신.
  4. 변경 후 이 가이드의 사례 표에 추가하고, 표준이 바뀌면 python 그리드/_build_html.py로 HTML 재생성.
