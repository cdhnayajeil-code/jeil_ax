원천 UNIERP MS SQL(사외 IDC · DB JEILMNS) → ODBC 읽기전용 조회(SELECT … WITH (NOLOCK), 화이트리스트 SQL) → ETL이 Supabase 중간DB(erp_ro)에 적재 → 사내 전용 뷰(v_erp_*)로 화면·챗봇에 제공. 실행은 수동 배치(자동 스케줄러 미도입)이며, 접속 서버·계정은 실행 환경 .env에만 보관하고 소스·문서에 남기지 않습니다. 급여는 민감 스키마(erp_secure)로 분리되어 이 표에는 연동 시점·건수만 표시됩니다.

자세히 — 숫자의 출처와 계산법
  • 벤더 청구 기준 = 벤더 사용량 API 가 알려 준 청구액(사용량 조회 키 필요). 추정치 = 우리 기록(chat_log·agent_turn)의 토큰 × 카탈로그 단가. 캐시 할인·도구 비용·낡은 단가 때문에 둘은 다를 수 있어 합산하지 않습니다.
  • 두 벤더 다 남은 잔액을 알려 주는 API 가 없습니다(2026-09-29 확인). 남은 예산 = 월 예산 − 이번 달 사용, 지금 잔액 = 콘솔에서 본 잔액 − 본 날짜 이후 사용. 월 예산 0 = 미설정(소진율 계산 안 함). 본 날짜가 90일을 넘으면 계산하지 않고 재확인을 요청합니다.
  • 토큰 = AI 가 글을 세는 단위(한글 약 1~2자). 단가는 백만 토큰당 달러이며, 같은 글이라도 모델마다 세는 수가 달라 「토큰 계수」(×1.30 등)로 보정합니다. 질문 1천건 환산 = 서버 가정값으로 계산한 참고치. 캐시 단가의 * = 공식 단가 미확인(입력의 0.1배 가정).
