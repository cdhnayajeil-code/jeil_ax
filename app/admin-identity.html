ERP 연동 현황
왜 한 곳에 모았나 — 계정 대사와 부서 매핑은 같은 원천(Z_USR_MAST_REC)을 다른 각도로 보는 화면입니다. 따로 열면 같은 사람을 두 번 찾아야 하고, 퇴사 처리처럼 두 화면의 결과를 함께 봐야 하는 일은 어느 쪽에도 자리가 없었습니다. 모듈은 각자 독립 화면이라 단독 주소(/admin/accounts · /admin/user-dept)로도 그대로 열립니다.
퇴사자는 세 시스템에서 각각 정리해야 합니다. 한 곳만 빠져도 계정이 살아 있고, 그 사실은 어디에도 오류로 뜨지 않습니다 — 2026-09-07 그룹웨어 퇴사자 13명 중 9명이 이 상태였습니다. 아래 목록은 인사상 퇴사인데 계정이 아직 살아 있는 사람입니다.

축별 자동화 상태

ERP — 자동 실증 완료

SharePoint 목록 「ERP 퇴사처리 RPA」에 등재하면 기존 Power Automate 흐름이 1분 내 처리합니다. 진행구분을 - 로 채워야 실행됩니다(비우면 조용히 지나갑니다).

그룹웨어 — 자동 실증 완료

화면 자동화 스크립트로 처리합니다. 기준일자·퇴사일 복원·메일 삭제 방지까지 코드가 매번 확인합니다.

MS(Entra) — 수동 권한 대기

Graph 쓰기가 403입니다(User.ReadWrite.All 미부여). 지금은 Entra 관리센터에서 로그인 차단 + 표시이름 [퇴사] 접두를 직접 넣어야 합니다.

실행 방법

되돌리기 어려운 작업입니다. ERP 흐름은 사용자 역할을 DELETE 하고 무엇이 있었는지 남기지 않습니다. 등재 전에 역할 목록을 따로 적어 두세요. 그룹웨어의 「메일 삭제여부」 체크박스는 절대 켜지 마세요(메일계정·메일정보 일괄 삭제).

그룹웨어 — 러너 호스트에서 실행합니다. --apply 없이 먼저 돌리면 저장 직전 상태만 보여줍니다.

python 10_ERP_DB연계/etl/gw_offboard.py -i wc.kim -n 김우철 -d 2023-12-22          # 점검
python 10_ERP_DB연계/etl/gw_offboard.py -i wc.kim -n 김우철 -d 2023-12-22 --apply  # 실제 처리

ERP — SharePoint 목록에 한 줄 등재하면 끝입니다.

사용자 ID = 이메일 · 사용자명 = 부서_이름 · 퇴사일자 = 실제 퇴사일 · 진행구분 = -

MS — Entra 관리센터에서 직접(권한 부여 시 자동화 예정).

로그인 차단(accountEnabled=false) + 표시이름 앞에 [퇴사] 접두
처리 후 「데이터 업데이트」(ERP 연동 현황)를 한 번 돌리면 ERP·MS·그룹웨어를 다시 받아와 이 목록에서 자동으로 빠집니다. 기획 정본은 10_ERP_DB연계/21_퇴사처리_일괄적용_기획 입니다.
