이 화면은 키 값을 표시하지 않습니다 — 서버가 알려 주는 것은 등록 여부 · 글자 수 · 접두어 일치뿐입니다(CLAUDE.md §1.1·§1.8). 값을 확인해야 한다면 Supabase 대시보드에서 직접 보세요.

1 키는 4개 — 「부르는 키」와 「사용량 보는 키」가 다릅니다

가장 자주 막히는 지점입니다. 모델을 호출하는 키로는 사용량·비용을 조회할 수 없습니다(401·403이 납니다). 사용량 조회는 조직 관리자(Admin) 권한 키가 따로 필요합니다.

시크릿 이름벤더역할없으면 무엇이 안 되나
OPENAI_API_KEYOpenAI호출 챗봇(jeil-chat)·부서 에이전트가 GPT 모델을 부르지 못합니다. 현재 등록되어 운영 중입니다.
OPENAI_ADMIN_KEYOpenAI사용량 조회 「💳」 탭의 OpenAI 금액이 벤더 실측이 아니라 내부 추정으로만 표시됩니다.
ANTHROPIC_API_KEYAnthropic호출 Claude 모델을 아예 부를 수 없습니다(모델 카탈로그에 호출 불가로 표시).
ANTHROPIC_ADMIN_KEYAnthropic사용량 조회 「💳」 탭의 Claude 금액이 내부 추정으로만 표시됩니다.
권장 — 호출 키와 조회 키를 분리하세요. 조회 키(Admin)는 조직 전체 청구 정보를 읽을 수 있는 강한 권한이라, 챗봇이 매 질문마다 쓰는 키와 같은 값을 쓰지 않는 편이 안전합니다.
다만 OPENAI_API_KEY 자체를 Admin 키(sk-admin-…)로 발급했다면 서버가 그 키로 조회도 시도합니다(별도 등록 없이 동작).

2 OpenAI 키 발급

호출 키 — OPENAI_API_KEY

  1. platform.openai.com › API keys 로 들어갑니다(회사 조직으로 로그인).
  2. Create new secret key → 이름을 jeil-ax-chat 처럼 용도가 보이게 적습니다.
  3. Project 는 운영 프로젝트를 고르고, Permissions 는 Restricted → Model capabilities: Write 만 켭니다.
  4. 만들면 그 화면에서만 한 번 값이 보입니다 — 복사해서 4단계(Supabase 등록)로 바로 넘어가세요.

사용량 조회 키 — OPENAI_ADMIN_KEY

  1. Settings › Organization › Admin keys 로 들어갑니다.
  2. Create admin key → 이름 jeil-ax-usage. 값은 sk-admin-… 로 시작합니다.
  3. 이 메뉴는 조직 소유자·관리자만 보입니다. 안 보이면 계정 권한 문제입니다(개인 계정은 조직 설정이 먼저 필요).
  4. 아래 5단계 키 검증에서 OpenAI · 사용량 조회 로 먼저 확인한 뒤 등록하세요.

이 키로 읽는 것: GET /v1/organization/costs(일별 청구액) · GET /v1/organization/usage/completions(모델별 토큰). 결제·잔액을 바꾸는 권한은 이 화면에서 쓰지 않습니다.

3 Anthropic(Claude) 키 발급

호출 키 — ANTHROPIC_API_KEY

  1. platform.claude.com › Settings › API keys 로 들어갑니다.
  2. Create Key → 이름 jeil-ax-agent, Workspace 는 운영 워크스페이스 하나를 고릅니다. 여러 워크스페이스에 걸친 키(all workspaces)는 요청마다 anthropic-workspace-id 헤더로 워크스페이스를 지정해야 하는데, 지금 호출 코드에는 그 헤더가 없어 400 이 납니다(2026-09-30 실측 · 아래 6단계).
  3. 값은 sk-ant-api… 로 시작합니다. 한 번만 보입니다.
  4. 등록하면 모델 카탈로그의 claude-sonnet-5·claude-haiku-4-5 가 호출 가능으로 바뀝니다.

사용량 조회 키 — ANTHROPIC_ADMIN_KEY

  1. Settings › Admin keys → Create Admin Key.
  2. 값은 sk-ant-admin01-… 로 시작합니다. Workspace 에 묶인 키는 안 됩니다 — 조직 단위 키여야 합니다.
  3. 개인 계정에서는 Admin API 를 쓸 수 없습니다. Console › Settings › Organization 에서 조직을 먼저 만들어야 메뉴가 나타납니다.
  4. 아래 5단계에서 Anthropic · 사용량 조회 로 확인 후 등록.

이 키로 읽는 것: GET /v1/organizations/cost_report · GET /v1/organizations/usage_report/messages. 데이터는 호출 후 보통 5분 안에 반영됩니다.

4 Supabase Edge Function 시크릿에 등록 여기가 실제 적용 단계

키는 코드·문서·이 화면에 적지 않습니다. 서버 시크릿에만 둡니다 — 코드 변경·재배포 없이 바뀝니다.

  1. Supabase 대시보드 → 해당 프로젝트 → 왼쪽 Edge Functions → Secrets 탭.
  2. Add new secret → Name 에 시크릿 이름을 철자 그대로 적습니다(예 OPENAI_ADMIN_KEY). 대소문자·밑줄이 하나만 달라도 서버는 「미등록」으로 봅니다.
  3. Value 에 복사한 키를 붙여 넣습니다. 앞뒤 공백·줄바꿈이 섞이지 않게 하세요(가장 흔한 401 원인입니다).
  4. 저장 후 이 화면에서 「다시 확인」 → 해당 카드가 등록됨 으로 바뀌는지 봅니다.
  5. 관리자 콘솔 「💳 AI 비용·예산」 탭 → 새로고침 → 출처 배지가 내부 추정 에서 벤더 실측 으로 바뀌면 끝입니다.
시크릿을 새로 넣거나 바꾸면 Edge Function 이 다음 호출 때 새 값을 읽습니다. 바로 반영되지 않는 것 같으면 1~2분 뒤 다시 확인하세요. 「다시 확인」은 실제 서버에 물어보는 것이라 캐시가 없습니다.

5 키 검증 — 등록 전에 살아 있는지 확인

이 칸에 넣은 키는 저장되지 않습니다. 서버가 벤더에 조회 1건을 보내 응답 코드만 확인하고 값을 버립니다 — DB 에 쓰지 않고, 로그·응답에도 남기지 않습니다. 실제 적용은 4단계(Supabase 시크릿 등록)로만 됩니다. 이 화면에서 키를 입력하는 것은 「등록」이 아닙니다.

검증이 끝나면 입력칸을 비우세요. 브라우저 주소창·개발자도구 기록에 남지 않도록 URL 이 아니라 본문으로 보냅니다.

6 자주 나는 오류

코드원인해결
401키가 틀렸거나 폐기됨 · 값에 공백·줄바꿈이 섞임시크릿 값을 지우고 다시 붙여 넣습니다. 앞뒤 공백 확인.
401호출 키로 사용량 API 를 부름(가장 흔함)Admin 키를 따로 발급해 *_ADMIN_KEY 로 등록합니다(1단계 표 참고).
403Admin 키인데 권한 범위가 부족 · Workspace 에 묶인 키조직(Organization) 단위 Admin 키로 재발급합니다.
400호출 키가 워크스페이스에 묶여 있지 않음(개인·서비스계정 키를 all workspaces 로 발급) — 요청마다 anthropic-workspace-id 헤더가 필요한데 호출 코드가 보내지 않음. 「키 검증」도 같은 이유로 실패합니다. 가장 쉬운 해결은 워크스페이스 하나를 지정해 키를 재발급하는 것입니다. 그대로 쓰려면 Console › Settings › Workspaces 의 wrkspc_… ID 를 시크릿으로 등록하고 호출 코드가 헤더를 붙여야 합니다(REQ-0094 2단계 · 관리자 확인 대기).
404개인 계정이라 조직 API 가 없음벤더 콘솔에서 조직을 먼저 만들고 관리자 권한을 확인합니다.
429조회가 몰림(사용량 API 는 분당 1회 권장)잠시 뒤 다시 누릅니다. 「💳」 탭을 연속으로 새로고침하지 않습니다.
금액 0키는 정상인데 이번 달 사용이 없음, 또는 다른 조직의 키벤더 콘솔의 Cost 화면과 같은 조직인지 확인합니다.
숫자 불일치「사용량 설정」 탭(내부 추정)과 「💳」 탭(벤더 실측)이 다름정상입니다 — 아래 7단계 설명을 보세요.

7 화면의 숫자를 읽는 법 — 왜 두 가지 금액이 있나

표시어디서 온 값주의
벤더 실측벤더 Usage/Cost API — 실제 청구 기준 캐시 할인·배치 할인·웹검색 같은 서버도구 비용까지 포함된 금액입니다. 이 값을 기준으로 판단하세요.
내부 추정우리 DB(chat_log·agent_turn)의 토큰 × ai_model 단가 Admin 키가 없을 때 대신 보여 줍니다. 단가가 낡으면 그만큼 틀립니다 — 벤더가 가격을 바꾸면 「모델 설정」 탭에서 갱신해야 합니다.

「잔여」는 계산한 값입니다

두 벤더 모두 잔여 크레딧을 알려주는 API 가 없습니다(2026-09-29 확인). 그래서 관리페이지의 잔여는 두 가지 역산값입니다.

  • 예산 잔여 = 관리자가 적은 월 예산 − 이번 달 실사용. 예산을 0 으로 두면 「미설정」으로 표시하고 계산하지 않습니다.
  • 잔액 역산 = 벤더 콘솔에서 확인한 충전 잔액 − 확인일 이후 실사용. 그래서 금액과 확인일을 함께 적어야 하고, 확인일이 90일을 넘으면 역산하지 않고 재확인을 요청합니다.

즉 잔액을 정확히 보려면 가끔 벤더 콘솔에서 실제 잔액을 보고 날짜와 함께 갱신해 주어야 합니다. 추측으로 채우지 않고 「—」로 두는 편이 낫습니다.

8 하지 말아야 할 것

  • 키를 소스·문서·엑셀·메신저에 적지 않습니다. 저장소에 올라가면 즉시 폐기·재발급해야 합니다.
  • 키를 셸에서 echo 하거나 명령줄 인자로 넘기지 않습니다 — 명령 기록에 남습니다(CLAUDE.md §1.8).
  • .env 를 source 로 읽지 않습니다 — 값이 오류 메시지로 화면에 찍힌 실제 사고가 있었습니다.
  • 협력사·외부 인력에게 관리자 콘솔 접근을 주지 않습니다. 이 화면은 포털 전체관리자만 열립니다.
  • 퇴직·담당 변경 시 키를 폐기하고 재발급합니다. 이름에 용도를 적어 두면 어느 키를 지울지 알 수 있습니다.
