10. 결의전표 반복전표 자동화 — ERP 실측 분석·기획

작성일: 2026-08-10 · 최종 갱신: 2026-08-20(v1.5 — B2 개정: 결정 C-14로 부가세 자동계산 도입, 원천징수는 계속 범위 제외. 이전 v1.4 · 2026-08-12 P1·P3 구현완료 / v1.3 · 2026-08-12 B1 실적재 / v1.2 · 2026-08-11 승인 게이트 결정 반영) · 관리: 최동혁 · 전담 에이전트: erp-db-link-manager 매달 같은 형태로 반복 작성되는 결의전표를 한 번 등록해 두고 변동값만 고쳐 재사용하는 자동화 툴의 분석·기획 문서. ERP운영DB 2026년 수기 결의전표 2,287건 전수를 읽기전용으로 분석해 실측 근거로 기획했다(추측 없음). 본문 수치는 분석 도구(etl/analyze_repeat_gl.py) 출력으로 전부 재현 가능하다. 기존 결의전표 파일럿(06·07·08·09)과 템플릿 플랫폼 v1(09 §3.4) 위에 얹는 v2 확장이다. 비밀값(접속 IP/ID/비밀번호) 기록 금지 — 서버 지칭은 별칭 "ERP운영DB" 만 사용.

1. 30초 요약

무엇을 확인했나 — 2026년 1~8월 수기 결의전표(TG) 2,287건 중 42.2%(964건)가 "동일 부서 + 동일 계정 조합 + 동일 거래처"로 3개월 이상 반복되는 156개 패밀리에 속한다. 월평균 약 134건이 매달 거의 같은 내용을 다시 입력하는 전표다. 이 중 34개 패밀리는 금액까지 완전 고정(예: (주)쿠콘 275,000원, KT 968,000원, 거산엔지니어링 임대료 27,500,000원)이라 날짜만 바꾸면 그대로 재사용 가능하다.

무엇을 만들려 하나 — 템플릿 플랫폼 v1(구조만 완성, 등재 0건)을 확장해: ① ERP 기작성 전표에서 시드 템플릿을 자동 생성(분석으로 후보 확보 완료), ② 사용자는 "이번 달 작성" 클릭 → 전월 값이 채워진 폼에서 변동값만 수정 → 제출, ③ 계정별 관리항목(공급가액·계산서일·부가세액 등 — 이번 분석으로 체계 실측 완료)을 자동 생성·자동 제안.

핵심 발견(보너스) — 승인 대기 중이던 A5(회계 규칙) 중 "계정 후보 좁히기" 항목의 실측 근거가 확보됐다. 반복 패밀리가 실제 사용하는 계정은 691개 중 88개(3개 패밀리 이상 반복 등장하는 핵심 계정은 44개)로 실측됐고, 계정별 필수 관리항목 규칙도 ERP 설정 테이블(A_ACCT_CTRL_ASSN 997건)에서 그대로 가져올 수 있다. 단 A5의 나머지 항목(기본 상대계정·부가세 처리·마감 기준)은 여전히 회계 담당 결정이 필요하다 — §8.

4. 분석 결과 ② — 관리항목 체계 실측 (이번 기획의 열쇠)

ERP 결의전표 화면 하단의 "관리항목" 그리드(공급가액·계산서일·거래처코드…)는 A_TEMP_GL_DTL(전표번호+라인순번+관리항목코드 CTRL_CD+값 CTRL_VAL)에 저장되며, 어느 계정에 어떤 관리항목을 입력해야 하는지는 ERP 설정 테이블 A_ACCT_CTRL_ASSN(997건)이 계정×차/대변 단위로 정의하고 있다. 관리항목 종류는 A_CTRL_ITEM 52종.

현 포털 파일럿(gl_draft)에는 관리항목 개념이 아예 없다 — 세금계산서 매입형(T1·T2, 반복 전표의 45%)을 지원하려면 이 구조가 반드시 필요하다.

4.2 파생 계산 규칙 (실측 검증 결과 — 전부 '제안값'이며 실물 증빙이 정답)

규칙 실측 근거와 한계
V8(부가세액) ≈ V1(공급가액) × 10% — 과세(V4=A). 면세(K)는 V8=0 다수 패밀리에서 성립하나 정확히 10%가 아닌 실전표가 실존 — 렌탈료 전표는 품목별 부가세 절사 후 합산이라 최대 10원 수준 차이, 통신료 전표는 청구액 절사 단수차를 잡이익 라인(9원)으로 처리. 따라서 V8은 자동 계산 '제안값' + 수기 수정 가능으로 설계하고, 서버 검증은 경고(soft) 또는 계산서당 ±10원 허용으로 한다. 수입(C)·불공제(B)는 10% 관계 자체가 불성립 — 1차 범위 제외
미지급금(대변) = Σ(V1+V8) — 계산서 그룹 단위 한 전표에 계산서 여러 건(예: 코로케이션 2건, 렌탈 5건)이 실존 — 라인·전표 단위가 아니라 계산서 그룹별 대응이며, 단수차 잔액(잡이익/잡손실 라인) 허용이 필요. 데이터 모델에 계산서 그룹 키(§6.3 invoice_seq) 필수
V6(거래처코드) = 미지급금 라인 BP 전 세금계산서형 패밀리에서 일치
V5(신고사업장) = TX1(이천)/TX2(김해) — 부서로 유추 불가 김해 관련 패밀리 18개 중 TX2 단독 9 · TX1 단독 6 · 혼재 3으로 전표별로 갈린다. 규칙 강제 금지 — 템플릿별 전월 실측값 프리필로만 처리
프리랜서 원천징수: 소득세=총액×3% → 주민세=⌊소득세×10%⌋(10원 미만 절사) → 미지급급여=잔액 헝가리법인 케이스에서 '총액×0.3%' 단순식은 6원 과대(실측 10,740 vs 계산 10,746) — 절사 규칙 포함식이 실전표와 일치. 소액부징수(1천원 미만) 경계는 검증 규칙에 주석으로 유지
V2(계산서일)·C1(만기일)은 매월 유사 일자로 +1개월 이동 동일 일자가 아니다(휴일·월말 보정 실존). +1개월 제안 시 월말은 말일로 클램프(1/31→2/28), 항상 '변동' 취급으로 잠금 제외, 제안값 배지 표시 + 제출 전 확인(§6.1)
적요 월 표기: 당월형 84% · 전월형 11%(월표기 전표 623건 실측) 전역 기본값 없음 — 패밀리별 실측 오프셋(month_offset 0/-1)을 분석 도구가 자동 판정해 템플릿에 저장

5. 현 템플릿 플랫폼(v1)과의 갭 — 왜 v2가 필요한가

v1(2026-08-05, 09 §3.4)은 "케이스별 분개 형태 등록 → 골라서 총액 입력" 구조를 만들었지만 등재 0건으로 미가동이다. 이번 분석 기준으로 부족한 것:

# 갭 영향
G1 관리항목(CTRL) 구조 부재 — 초안·템플릿 모두 저장 불가 반복 전표의 45%(세금계산서형)를 표현 못함. 회계 담당자가 ERP 하단 그리드를 결국 수기로 다시 입력
G2 부가세 케이스 미지원 — 파일럿은 부가세 미사용 케이스 한정(확정 결정 C-2) T1·T2 유형 지원 불가. C-2 범위 개정은 승인 사항(§8 B2)
G3 기작성 전표 기반 생성 부재 — 템플릿을 백지에서 수작업 등록해야 함 등재 0건이 증명하는 병목. 실측 후보 156개가 있는데 활용 경로가 없음
G4 월반복 워크플로 부재 — "지난달 것 이번 달 것으로" 개념 없음 사용자가 매달 템플릿을 찾아 총액부터 다시 입력. "이번 달 미작성" 파악 불가

6. 기획 — 반복전표 자동화 (템플릿 플랫폼 v2)

6.0 설계 원칙

  1. "초안은 포털, 확정은 ERP"(C-1) 불변 — 이 기획은 입력 단계 자동화이며 ERP 쓰기(E3)와 무관하게 성립한다.
  2. 전표 이력은 중간DB에 적재하지 않는다(C-7 유지) — 중간DB에는 코드 마스터 2종만 추가한다(§6.5). 단 시드 템플릿의 고정 금액(T1형 fixed 값) 저장은 v1 "실적 금액 미저장" 원칙의 명시적 변경이며 §8 B2 승인 범위에 포함한다. 변동 금액의 프리필은 ERP 값이 아니라 포털이 스스로 만든 데이터(본인 최근 확정 초안) 를 참조한다(§6.2 F2).
  3. 템플릿을 적용해도 서버 재검증은 전부 통과해야 한다(v1 원칙 유지) + 관리항목 검증 추가. 단 부가세 관계식은 hard가 아닌 soft(경고) — 실물 계산서가 정답이다(§4.2).
  4. 자동 제출은 없다 — 어떤 자동화 수준에서도 사람이 확인·제출한다(§1.6 실거래 액션 금지).

6.2 기능 명세

# 기능 내용
F1 월반복 홈 「전표 작성」 탭 상단(또는 별도 「월반복」 탭)에 내/내부서 반복 템플릿 카드. 배지 4상태: ⚠미작성 / ✏️작성중(작성자 표시) / 📤제출됨 / ✅확정됨 — 판정은 gl_template_usage(초안 생성 시점 기록, 상태 동기 갱신 §6.4). 미확정 초안이 있으면 [이어서 작성] 버튼 + [이번 달 작성] 클릭 시 "이미 ○○○님이 8/1 제출한 건이 있습니다" 중복 경고. 정렬 기본 = 미작성 우선 → 최근 사용순, 거래처·유형 검색, 카드 20개 초과 시 그룹 접기. 주차·수시 반복 케이스는 월1회 배지 대신 "이번 달 3건 · 최근 8/4(7일 경과)" 카운터 표시
F2 전월 프리필 프리필 정본 이원화: 라인 구성·고정값·파생 규칙은 템플릿 정의에서, 변동 필드 기본값은 요청자 본인의 최근 확정(posted) 초안에서 가져온다(부서 공유 템플릿이어도 타인 초안은 참조하지 않음 — 본인 이력이 없으면 규칙값만 프리필). EM·BA 등 개인 식별 관리항목은 부서 템플릿의 프리필·카드 표시 대상 제외. 결의일자=오늘, 적요 월 표기는 템플릿 토큰({YY}년{M}월)+실측 오프셋(month_offset)으로 자동 갱신, 날짜형 관리항목(V2·C1)은 직전 회차 값+1개월(월말 클램프)을 '제안값' 배지로. 일회성 수정이 다음 달로 전이되지 않도록 스냅샷 갱신은 자동이 아니라 "이번 값을 다음 달 기본으로 저장" 명시 선택
F3 변동 필드 하이라이트 템플릿 라인·관리항목마다 고정/변동 플래그(시드는 실측 amt_distinct로 자동 판정, 날짜형은 항상 변동). 변동 필드만 입력 활성·강조, 고정 필드는 잠금 + 눈에 보이는 해제 아이콘 + 최근 3개월 값 툴팁(요금 인상 감지 근거). 고정액을 해제·수정해 제출하면 "템플릿의 고정값도 갱신할까요" 선택 제공(다음 달 재발 방지). 오제출 방어는 반복 모달 대신 제출 전 요약의 "전월과 달라진 점 n건 / 같은 점" 차이 리스트로(습관적 통과 방지)
F4 총액 자동 배분 v1 배분 규칙(input/pct/fixed/balance) 재사용 — 비용 판/제/연 비율 배분·차액(balance) 채움만 수행. [B2 결정 2026-08-11] 부가세·원천징수 자동계산은 범위 제외 — V8(부가세액)·원천징수액은 자동 계산하지 않고 사용자가 실물 증빙 값을 직접 입력(전월값 프리필만). §4.2의 파생식은 향후 승인 시를 위한 실측 기록으로만 유지
F5 관리항목 자동화 계정 선택 시 acct_ctrl_assn_s 기준 관리항목 필드를 차/대변 구분 반영해 자동 생성(필수검증은 플래그 'Y' 항목만). 파생값(V1·V6·V8)은 자동 계산 제안 + 수정 가능. 「ERP 입력용 요약」에 관리항목 표 추가 — acct_ctrl_assn seq 순서(ERP 입력 순서)로 정렬, 항목별·전체 TSV 복사 버튼(그리드 표준 §13 규약 재사용) — 회계 담당자가 ERP 하단 그리드까지 그대로 옮겨 붙이게
F6 라인 복사·증감 표준 그리드에 행 복사 버튼(관리항목 세트 동반 복제, 에스원형 다라인 대응). 행 삭제 시 관리항목 동반 삭제 + balance 라인 자동 재계산, pct 라인 증감 시 비율 재정규화(또는 수동 모드 전환 안내), 신규 행 기본 플래그=변동. 구조가 템플릿과 달라지면 초안·카드에 "템플릿과 다른 구성" 표시
F7 전표→템플릿 승격 v1 「현재 전표를 템플릿으로」 확장: 확정(posted)된 내 초안에서 원클릭 승격 + 월반복 여부·제목 토큰·고정/변동 플래그 지정 UI. 일반 사용자 승격분은 공개범위 user 고정 — dept/org 전환은 관리자·회계 담당자 승인 시에만(v1 거버넌스 유지)
F8 시드 일괄 등재 분석 도구가 만든 후보(1차: 월1건형 36개 → 검수 후 5개월+ 73개로 확대)를 회계 담당 검수(§8 B2) 후 erp_case_cd=패밀리 ID로 일괄 등재. V4가 B·C·L·Q인 패밀리는 자동 제외(§3.3). month_offset·고정/변동 플래그는 실측 자동 판정. 공개범위 기본 dept, 작성자가 특정인인 케이스는 user — user 범위 템플릿은 담당자 교체 시 관리자·회계 담당자가 범위를 dept로 변경하는 이전 절차를 함께 규정. 찾는 템플릿이 없으면 "일반 작성 + 부서 공유 요청" 안내 경로 제공
F9 처리 현황 보드 회계 담당자 탭에 미처리(제출됨) 초안 대기열 + 건별 완료 체크오프 뷰를 추가하고, 월별 반복전표 처리율은 그 파생으로 계산. 미작성 알림은 후순위(L3)
