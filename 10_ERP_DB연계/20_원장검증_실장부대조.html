20. 원장 검증 — 실제 장부와 1:1 대조

AX 로 만든 전표가 사람이 손으로 만든 전표와 장부상 똑같은가. 적재 2026-08-26 · 관리: 최동혁 · 배치 LEDGERSET-2026-08-26 도구 etl/seed_ledger_cases.py(복제 적재) · etl/verify_ledger.py(대조) 선행 19_연동테스트_전표세트(가드 검증) · 14_AX전표_테스트범위_및_케이스설계

0. 19번과 무엇이 다른가

19번 세트 20번 세트(이 문서)
묻는 것 가드가 잘 막는가 장부에 똑같이 반영되는가
전표 출처 설계해서 만든 것 실제 승인 전표를 복제
보는 곳 전표 안(투입 라인 대조) 전표 밖 — 채무·부가세·선급·선수·미결 원장
판정 통과/차단 원본과 한 줄도 어긋나지 않는가

릴레이가 투입 직후 하는 라인 대조는 전표 안만 본다. 회계가 실제로 쓰는 것은 전표가 아니라 그 전표가 만들어 낸 원장이다. 채무 잔액이 서고, 부가세 신고자료가 잡히고, 선급이 정산 대기에 올라가는 — 그 결과를 본다.

왜 실제 전표를 복제하나

발명한 전표로는 이 비교를 할 수 없다. 대조할 원본이 없기 때문이다. DEMO2 에 이미 승인돼 있는 수기 전표를 골라 계정·차대·금액·관리항목을 그대로 복제하면, 같은 분개가 두 경로(수기 / AX)로 들어간 셈이 되고 원장 결과를 나란히 놓고 뺄 수 있다.

DEMO2 승인 전표 500건을 원장 조합으로 분류해 조합마다 하나씩 골랐다.

AX 경로가 수기 경로와 장부상 구별되지 않는다 — 7건 전건에서 확인됐다.

V4·V5 는 처음에 막혔다가(§2) 부서를 현행으로 바꿔 다시 보냈다. V4 영업팀(5100·폐지) → 사업운영팀(6110), V5 CM2파트(6630·폐지) → 사업관리팀(6120) — 둘 다 현행 조직이고 상위가 사업부문(6700)이라 원 전표 성격에 맞다. 코스트센터도 함께 바꿨다(C016110·C016120). 부서가 달라도 대조는 유효하다 — 비교 대상은 계정·차대·금액·관리항목·원장 금액이고 부서는 거기 들어가지 않는다.

V3 에서 43000514 → ADJMNT/DZ 가 또 확인됐다 — 원본이 생산팀(C017100) 소속이라 직접 코스트센터 경로를 자연스럽게 탔다.

사전점검은 7/7 통과였지만 V4·V5 는 실제 전송에서 막혔다. 사전점검이 못 보던 구간이 있었다는 뜻이고, 그것이 이 세트의 최대 수확이다(§2).

2. ★ 새로 찾은 결함 — 없어진 부서로는 전표를 만들 수 없다

V4(부서 5100)·V5(부서 6630)가 서브원장 생성 단계에서 A05191 로 거부됐다.

A05191 = 조직개편과 부서정보가 맞지 않습니다 (ERP 메시지 마스터 B_MESSAGE)

무엇이 문제였나

ORG_CHANGE_ID 는 조직개편 버전이고 현행은 20264 다. 릴레이는 「그 부서가 속한 가장 최신 조직」을 골랐는데, 없어진 부서는 그 값이 현행보다 과거다.

부서 소속 조직 릴레이가 고른 값 결과
3200 · 6700 · 7100 · 2300 … 20251, 20264 20264 = 현행 ✅
5100 … 20244, 20251 20251 🚫 A05191
6630 20244 뿐 20244 🚫 A05191

현행에 남아 있는 부서는 「최신 = 현행」이라 우연히 맞아떨어졌다. 없어진 부서에서만 어긋난다 — 그래서 여태 드러나지 않았다.

더 나쁜 점 — 만들었다가 되돌린다

거부는 전표를 다 만든 뒤 서브원장 단계에서 온다. 롤백되므로 ERP 에 흔적은 남지 않지만, 전표번호(AG)는 소모되고 사용자는 한참 뒤에야 실패를 안다. 사전점검(--precheck)도 못 잡았다 — 쓰기 직전에서 멈추므로 그 SP 를 부르지 않기 때문이다.

조치 — 쓰기 전에 막는다

check_dept_org() 를 신설해 거래유형 확인 직후(채번·투입 이전)에 현행 조직 소속을 본다. 이제 사전점검에서도 잡히고, ERP 에는 아무것도 들어가지 않는다.

부서 5100 는 현재 조직에 없습니다 (조직개편 20251 까지만 쓰던 부서입니다)
→ 전표 상단에서 지금 쓰는 부서로 바꾸세요

운영 전환에 미치는 영향: 폐지 부서로 전표를 넣을 수 없다는 것은 정상 동작이다. 문제는 그 사실을 알려 주는 시점과 문구였고, 그것을 고쳤다. 과거 전표 재현·소급 정산처럼 폐지 부서가 필요한 업무는 ERP 화면 소관으로 남는다.

2.1 파생 문제 — 화면이 폐지 부서를 아직 고르게 한다 (미결)

릴레이는 이제 막지만, 입력 화면은 여전히 폐지 부서의 코스트센터를 보여준다. gl_master_get() 의 코스트센터 목록이 조직 버전을 보지 않기 때문이다 (제외 조건은 org_change_id='19801' 과 이름의 '사용금지' 뿐).

실측하면 이렇다.

값
화면에 지금 노출되는 코스트센터 91개
그중 현행 조직 부서 소속 36개
폐지 부서 소속(고르면 전송 실패) 55개 — EPC그룹·전사혁신팀·원가회계팀·IT팀·영업팀·PM팀 …

그런데 단순히 필터를 걸면 안 된다. 두 가지가 걸린다.

  1. 코스트센터는 조직개편 때 전량 재생성되지 않는다. ERP 실측: 조직 20264(현행)에 코스트센터가 4건뿐이고, 실제 쓰는 C013200(총무팀) 같은 것들은 20244·20251 에 남아 있다. → 「코스트센터의 조직 버전」으로 거르면 4건만 남아 화면이 못 쓰게 된다. 올바른 기준은 소속 부서가 현행 조직에 있는가 다.
  2. 중간DB 미러가 한 세대 뒤처져 있다. 미러(erp_ro.dept_master_s)의 최신 조직은 20261, ERP 원본은 20264 다. 잘못된 기준으로 55개를 없애는 셈이 된다.

결정 필요: ①먼저 중간DB 조직 미러를 현행(20264)까지 동기화하고, ②그다음 gl_master_get 을 부서 기준으로 거른다 — 이 순서여야 한다. 화면에서 55개가 사라지는 변화라 업무 영향이 있어 임의로 바꾸지 않았다(CLAUDE.md §4·§10).

지금 당장 데이터 사고는 없다 — 릴레이 가드가 막고, 사전점검이 보내기 전에 알려 준다. 남은 것은 「고를 수는 있는데 보내면 막힌다」는 불편이다.

3. 무엇을 대조하나

verify_ledger.py 가 AX 전표(AG…)와 원본(TG…)을 나란히 놓고 비교한다.

# 대상 비교 방식
① 전표 라인 계정·차대·금액을 다중집합으로 — 엔진이 순서를 바꾸므로 순서는 보지 않는다
② 관리항목 (계정·차대·코드·값) 다중집합. 날짜형은 제외 — 복제할 때 오늘로 옮겼다
③ 부가세 A_VAT 건수 · 과세표준 · 세액
④ 채무 A_OPEN_AP 건수 · 금액 · 거래처 수
⑤ 선급 F_PRPAYM 건수 · 금액
⑥ 선수 F_PRRCPT 건수 · 금액
⑦ 미결 A_OPEN_ACCT 건수 · 금액 · 관리값(사번) — 승인 후에만 생긴다(GL_NO 기준)

미결은 승인 시점에 서므로, AX 쪽이 아직 승인 전이면 차이가 아니라 「아직」 으로 표시한다.

4. 복제 규칙 — 무엇을 그대로 두고 무엇을 옮기나

처리
계정 · 차대 · 금액 원본 그대로. 비교 대상이 바로 이것이다
거래처(BP) · 사번(EM) · 프로젝트(PC) · 발주(PO) 원본 그대로
전표일자 오늘로 이동 — 닫힌 회계기간에는 넣을 수 없다
날짜형 관리항목(계산서일 V2·만기일 C1·XC1) 전표일자에 맞춰 이동 (그래서 대조에서 제외)
적요 ax검증_Vn <원본적요> (원본 TG…) — 추적 가능하게

민감값을 저장소에 두지 않는다

거래처·사번·계좌·프로젝트 값은 코드에 없다. 실행할 때 원본 전표에서 읽어 온다. 저장소에 남는 것은 원본 전표번호뿐이다(CLAUDE.md §1). 화면 출력도 앞 2자리만 보인다.

주의: 같은 분개가 DEMO2 에 두 번 들어간다(원본 + 복제). 비용이 이중 계상된다. DEMO2 는 테스트 DB 이므로 의도된 것이지만, 운영에서는 절대 이렇게 하지 않는다.

5. 옮길 수 없는 형태 — 실제 사례로 확인됨

TG202505270017(스웨덴법인 급여, AP+AR)은 복제 대상에서 빠진다. 1·2번 줄이 음수(−25,922 / −26,650)인데 포털은 gl_draft_item 에 CHECK (item_amt > 0) 이 걸려 있어 저장할 수 없다.

19번 §4.1 에서 「마이너스 전표는 만들 수 없다」고 적은 한계가 실제 장부 전표로 확인된 것이다. 차감 조정이 섞인 급여·정산 전표가 이 형태이고, DEMO2 수동입력 중 939전표가 마이너스 라인을 갖는다. 운영 전환 전 결정이 필요하다(19번 §4.1).

6. 사용법

python 10_ERP_DB연계/etl/seed_ledger_cases.py --plan    # 무엇을 복제할지 보기

#  → 화면 [ERP 전송] 탭에서 보내기 → ERP 화면에서 승인

python 10_ERP_DB연계/etl/seed_ledger_cases.py --purge   # 정리(적용된 건은 보존)

7. 실측 조건

  • 대상 JEILMNS_DEMO2 · 운영(JEILMNS) 미접근 · 대조 쿼리는 전부 WITH (NOLOCK) 읽기
  • 원본 선정: 승인 완료(CONF_FG='C') · 2~6줄 · 서브원장 연결번호 전건 채움 · 10만~2천만원
  • TG 접두 = 수기, AG 접두 = AX — 이 구분으로 원본에서 AX 생성분을 제외했다
  • DEMO2 는 2025-06-25 스냅샷이다. 운영 전환 전 같은 대조를 운영 마스터로 재수행해야 한다 (17_운영전환_게이트 G7)
