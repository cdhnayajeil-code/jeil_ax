## 1. ERP 접속정보가 바뀌면 (계정·비밀번호·포트)

**고칠 곳: `E:\ai.jeil\.env` 의 `ERP_DB_CONN` 한 줄. 그것뿐이다.**

```
ERP_DB_CONN = DRIVER={ODBC Driver 17 for SQL Server};SERVER=localhost;DATABASE=JEILMNS;UID=...;PWD=...;TrustServerCertificate=yes;
```

- **EXE 재빌드 불필요.** 접속정보는 번들에 들어 있지 않다.
- 바꾼 뒤 확인: `gl_relay.exe --list` → 대기 건이 나오면 정상.
- `DATABASE=` 는 무엇으로 적어도 된다. 릴레이가 접속 시 `JEILMNS_DEMO2` 로 강제 치환하고,
  붙은 뒤 실제 DB명을 재확인해 다르면 **아무것도 실행하지 않고 중단**한다(가드 2).

> 워크스테이션에서 쓰던 `%USERPROFILE%\.erp\` DPAPI 저장소는 **계정·장비에 묶여 있어
> 서버에서 복호화되지 않는다.** 서버는 `ERP_DB_CONN` 경로만 동작한다.

## 2. 실행 서버가 바뀌면 (다른 장비로 이전)

새 장비가 갖춰야 할 조건 5가지 — **전부 만족해야 한다.**

| 조건 | 확인 방법 |
|---|---|
| 항상 켜져 있음 | 상시 가동 장비인지(기획서 D2-a 필수 조건) |
| ERP MSSQL 접근 | `sqlcmd -S <서버> -Q "select db_name()"` |
| Supabase 아웃바운드 443 | `Test-NetConnection <프로젝트>.supabase.co -Port 443` → `TcpTestSucceeded : True` |
| ODBC 드라이버 17 또는 18 | `Get-OdbcDriver -Name "*SQL Server*"` |
| x64 Windows | EXE 는 x64 빌드 |

옮기는 절차:

1. `gl_relay.exe` · `relay.cmd` 복사 → 새 배포 루트
2. `.env` 를 **새 서버에서 직접 작성**(OneDrive·메일 경유 금지) + ACL 잠금
3. **`relay.cmd` 의 `set "GL_RELAY_ROOT=..."` 한 줄**을 새 경로로 수정
   (경로는 **ASCII 로만** — 한글이 들어가면 cmd.exe 파싱이 깨진다)
4. `gl_relay.exe --list` 로 연결 확인
5. `register_task.ps1 -Account <계정> -Root <새경로>` 로 등록
6. **구 서버의 작업을 먼저 해제**한다 — `register_task.ps1 -Remove`
   (두 곳에서 동시에 돌아도 선점(`gl_apply_claim`)이 중복 투입을 막지만,
   로그가 갈라져 추적이 어려워진다)
7. 이 문서 §0 표와 `실제구축준비 자료/이관/00_현재시스템_상태스냅샷` 갱신

## 3. Supabase 프로젝트·키가 바뀌면

**고칠 곳: `.env` 의 `SUPABASE_URL` · `SUPABASE_SERVICE_ROLE_KEY`.**

- **EXE 재빌드 불필요.**
- 서비스 롤 키 회전 시에는 **워크스테이션 `.env` 와 서버 `.env` 를 함께** 바꿔야 한다.
  한쪽만 바꾸면 다른 쪽이 조용히 401 로 실패하고, 큐는 계속 쌓인다.
- 키 회전 후 확인: 양쪽에서 `--list` 가 대기 건을 보여주는지.

---

## 4. 대상 DB를 바꿔야 하면 (DEMO2 → 운영)

**`.env` 로는 바뀌지 않는다. 코드 변경 + 승인이 필요하다.**

`gl_apply_demo2.py` 의 `TARGET_DB = "JEILMNS_DEMO2"` 가 하드코딩이고 CLI 파라미터가 없다.
운영(`JEILMNS`) 쓰기는 **결정 C-1 로 금지**되어 있다. 바꾸려면:

1. 경영/관리자 승인 + 유니포인트 협의 (C-1 개정)
2. 미결 **U-F** 해소 — `AX001` 계정매핑이 `A_JNL_ACCT_ASSN` 에 미등재(회계팀 등재 필요)
3. **되돌리기 절차 확보** — DEMO2 는 `--cleanup` 으로 지울 수 있지만 운영은 불가.
   전표 취소 절차가 먼저 정의돼야 한다.
4. 화면 단계 **중복 경고** 도입 — 멱등 방어는 *같은 초안번호* 기준이라
   내용이 같은 별개 초안은 두 장 다 들어간다(2026-08-24 실사례: 동일 적요·금액 2건).
5. 코드 수정 → **EXE 재빌드** → 재배포

## 5. 릴레이 코드가 바뀌면 (EXE 재빌드가 필요한 경우)

**재빌드 필요**: `gl_apply_demo2.py` · `_env.py` · `_erp_conn.py` 수정 시

```powershell
python 10_ERP_DB연계\etl\deploy\build_exe.py
#   산출물: 10_ERP_DB연계\etl\deploy\dist\gl_relay.exe
```

교체 절차(운영 중 무중단):

```powershell
Disable-ScheduledTask JEIL_AX_GL_Relay        # 새 회차 진입 차단
#   진행 중인 건이 끝날 때까지 로그로 확인
Copy-Item .\gl_relay.exe E:\ai.jeil\ -Force
E:\ai.jeil\gl_relay.exe --list                # 새 EXE 동작 확인
Enable-ScheduledTask JEIL_AX_GL_Relay
```

**재빌드 불필요**: `.env` 변경, 주기 변경, `--max` 변경, 작업 계정 변경

> 실행 중 EXE 는 파일 잠금이 걸린다. 교체가 거부되면 작업을 먼저 Disable 하고
> 진행 중인 회차가 끝나기를 기다린다.

## 6. 실행 계정이 바뀌면

```powershell
.\register_task.ps1 -Remove
.\register_task.ps1 -Account <새계정>
```

`.env` ACL 에 새 계정 읽기 권한을 반드시 추가한다. 빠뜨리면 작업은 도는데
`SUPABASE_URL 가 없습니다` 로 매번 실패한다.

```powershell
icacls E:\ai.jeil\.env /grant:r "<새계정>:(R)"
```

## 7. 장애 진단 순서

| 증상 | 먼저 볼 곳 |
|---|---|
| 전송대기가 안 줄어든다 | `Get-ScheduledTask JEIL_AX_GL_Relay \| Get-ScheduledTaskInfo` → `LastTaskResult` |
| 〃 (작업은 정상) | `logs\relay_YYYYMM.log` 마지막 회차 |
| `SUPABASE_URL 가 없습니다` | `.env` 위치(EXE와 같은 폴더인지) · ACL 에 실행 계정 있는지 |
| ODBC 오류 | `Get-OdbcDriver` · `ERP_DB_CONN` 의 DRIVER 이름 철자 |
| 특정 전표만 계속 실패 | 화면 [ERP 전송] 탭의 실패 사유 — 대개 분개코드 미등재(회계팀) |
| `sending` 에 갇혔다 | 30분 뒤 `gl_apply_reclaim` 이 자동 반납. 급하면 다음 회차를 기다린다 |

포털 쪽 원장으로도 볼 수 있다 — `public.gl_erp_apply_log`(mode·status·detail),
`public.gl_draft.erp_apply_msg`.
