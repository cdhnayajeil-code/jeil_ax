19. ERP 연동 테스트 전표 세트 — 정상 6 · 오류 8

다양한 전표형태와 오류 유형을 한 배치로 덮는 재현 가능한 테스트 세트. 적재 2026-08-25 · 관리: 최동혁 · 배치 TESTSET-2026-08-25 생성기 etl/seed_test_drafts.py · 선행 14_AX전표_테스트범위_및_케이스설계(케이스 정의) · 15_AX전표_입력검증_및_차단규칙(차단 규칙)

0. 무엇을 왜 만들었나

지금까지 테스트는 한 번에 한 케이스씩, 손으로 넣었다. 그래서 두 가지가 없었다.

  1. 재현성 — 무엇을 왜 넣었는지가 남지 않아 같은 시험을 다시 돌릴 수 없다.
  2. 오류 쪽 커버리지 — 정상 경로만 봤다. 「잘못된 전표가 들어오면 어떻게 되는가」는 릴레이 로그로만 확인했고, 화면에서 어떻게 보이는지는 확인한 적이 없다.

이 세트는 둘을 함께 푼다. 케이스 정의가 코드에 있고(seed_test_drafts.py), 기대 결과가 케이스마다 붙어 있다. 적재는 제출됨 까지만 하고 전송은 사람이 누른다.

seed_test_drafts.py --load        →  제출됨 14건
        ↓
gl_apply_demo2.py --precheck      →  보내기 전 판정(ERP 무투입)   ← 지금 여기까지 완료
        ↓
화면 [ERP 전송] → 선택 전송        →  정상 6건 AG 채번 / 오류 8건 사유와 함께 차단

1. 사전점검 결과 (2026-08-25 실측)

정상 6건 전건 통과 · 오류 8건 전건 차단 — 설계대로다.

건수 결과
정상(P) 6 전건 통과 — 분개코드 해석·가드 모두 정상
오류(E) 8 전건 차단 — 의도한 규칙이 정확히 잡았다

가장 큰 수확은 PD 에서 43000501 → ADJMNT/DZ 가 확인된 것이다. 거래항목 결정(C-15)에서 서브원장 무관 계정은 코스트센터 직간접으로 IZ/DZ 가 갈리는데, 지금까지 테스트는 전부 간접(C013200·IZ)이었다 — DZ 는 한 번도 안 타 봤다.

E5·E6 이 특히 중요하다. usp_a_check_acct 에 TP/TR 전용 블록이 없어 ERP 가 막지 않는 구간이고, DEMO2 수동입력분에 위반 8라인이 실재하며 그 건들은 A_VAT 가 비어 있다. E7 도 같다 — ERP 의 113119 차대검증은 GL_INPUT_TYPE='GL' 한정이라 결의전표는 대상 밖이다. 즉 E5·E6·E7 은 AX 가 막지 않으면 아무도 안 막는다.

4. 이 세트가 덮지 못하는 것 — 포털의 구조적 한계

설계서 케이스 중 둘은 전표를 만들 수 없어서 넣지 못했다. 빠뜨린 것이 아니라 막힌 것이다.

4.1 T8 마이너스·수정계산서 — item_amt > 0 제약

gl_draft_item 에 CHECK (item_amt > 0) 이 걸려 있어 음수 라인을 저장할 수 없다.

방향을 뒤집는 우회(차변 −50,000 ≡ 대변 +50,000)는 G1/G5 가 막는다 — 부가세대급금 대변이 정확히 E5 다. 즉 두 겹으로 막혀 있다.

영향: DEMO2 수동입력 전표 중 마이너스 라인 보유가 939전표다. 오발행 취소·수정계산서는 이 형태이므로, 현재 포털로는 이 유형을 아예 만들 수 없다. 운영 전환 전에 결정이 필요하다 — ①포털이 음수를 허용할 것인가(그러면 G1/G5 예외 규칙도 함께 설계) ②아니면 수정계산서는 ERP 화면 소관으로 남길 것인가. 후자라면 그 사실을 사용자에게 명시해야 한다.

4.2 T10 외화 — 통화·환율 필드 자체가 없다

gl_draft 에 통화·환율 컬럼이 없고, 릴레이는 DOC_CUR='KRW'·XCH_RATE=1.000000 을 하드코딩해 투입한다. DEMO2 외화 전표 900전표가 범위 밖이다.

5. 관리항목 값을 저장소에 두지 않는다

사번(EM)·거래처(BP)·프로젝트(PC)·신고사업장(V5) 값은 코드에 박지 않고 실행 시 DEMO2 에서 해석한다 — 각 계정에서 실제로 가장 많이 쓰인 값을 고른다.

왜 결과
CLAUDE.md §1 — 민감값을 코드·커밋에 넣지 않는다 저장소에는 「어느 계정의 어느 항목을 쓸지」만 남는다
마스터가 바뀌면 하드코딩은 썩는다 다음에 돌려도 그때의 유효값을 쓴다
로그에 값이 남으면 안 된다 출력은 앞 2자리만(52******)

계정별 필수 관리항목은 A_ACCT_CTRL_ASSN 실측 기준이다 — 21100901 BP·C1(양방향 필수) · 21100902 EM(양방향 필수) · 11101701·21101902·11102301 BP(필수) · 11103301 V1·V2·V4·V5·V6(차변 필수) · 21102301 같은 항목(대변 필수) · 43000501 PC(차변 필수).

주의: gl_draft_item.bp_cd·project_no 는 ERP 로 넘어가지 않는다(화면 표시용). ERP 에 전달되는 관리항목은 gl_draft_item_ctrl 뿐이다.

6. 사용법

python 10_ERP_DB연계/etl/seed_test_drafts.py --plan     # 설계만 출력
python 10_ERP_DB연계/etl/seed_test_drafts.py --load     # 포털에 적재(제출됨)
python 10_ERP_DB연계/etl/gl_apply_demo2.py  --precheck  # 보내기 전 판정(ERP 무투입)
#  → 화면 [ERP 전송] 탭에서 선택 전송
python 10_ERP_DB연계/etl/seed_test_drafts.py --purge    # 배치 정리(적용된 건은 보존)

--load 는 이미 ERP 에 적용된 초안이 있으면 중단한다(덮어쓰지 않는다).

6.1 사전점검(--precheck)은 무엇인가

보내기 전에 분개코드 해석과 입력가드를 그대로 돌린다. 쓰기 직전에서 멈추므로 ERP 에 아무 흔적도 남지 않는다(--dry-run 은 전표를 만들었다 되돌려 AG 채번을 소모한다).

결과는 초안에 남아 화면 「사전점검 결과」로 보이고, 막힌 건은 「손봐야 할 건」 패널에 사전점검 차단 으로 올라온다 — 보내 보고 실패를 확인할 이유가 없다.

7. 승인까지 확인할 것 (전송 성공 후)

전송이 끝나면 ERP 화면에서 승인하고 아래를 본다. 판정 기준은 설계서 §6 을 따른다.

8. 실측 조건

  • 대상 JEILMNS_DEMO2 · 운영(JEILMNS) 미접근
  • 계정 속성은 A_ACCT(SUBSYS_TYPE·BAL_FG), 허용 방향은 A_OBJECT(GL_INPUT_TYPE='TG') 조회
  • 관리항목 필수 여부는 A_ACCT_CTRL_ASSN(DR_FG·CR_FG), 대표값은 A_TEMP_GL_DTL 사용빈도 1위
  • 코스트센터 직간접은 B_COST_CENTER.DI_FG — DEMO2 기준 직접 5 · 간접 128
  • DEMO2 는 2025-06-25 스냅샷이다. 운영 전환 전 같은 세트를 운영 마스터로 재수행해야 한다(17_운영전환_게이트 G7)
