11. 결의전표 ERP 직접등록 — 1차(DEMO2) 기획·구축

작성: 2026-08-19(v1.0 → v1.1 → v1.2 → v1.3 전송 E2E 성공 → v1.4 · 2026-08-20 AX001 채택 → v1.5 · 2026-08-20 전송=확정 일원화(C-13) + AX001 기준 2건째 성공 → v1.6 · 2026-08-20 DEMO2 5번째 E2E 성공(AX001 기준 3건째) → v1.7 · 2026-08-25 서브원장 생성 SP 호출 추가) · 관리: 최동혁 · 전담 에이전트: erp-db-link-manager 결정 C-11(2026-08-19 관리자 지시): AI(포털) 생성 결의전표의 ERP 직접 투입을 데모 DB JEILMNS_DEMO2 한정으로 1차 테스트한다. 운영(JEILMNS) 쓰기는 여전히 금지(C-1 유지) — 운영 전환은 기회검토의 착수 게이트 G-1~G-8 통과 + 재심의가 선행돼야 한다. 근거·선행: 사내 OneDrive ERP_DB/회계/260819_AX_결의전표_ERP연동_기회검토/(기회검토 본문 + test_demo2 리허설 킷 — 투입 레시피 리허설 검증 완료)

1. 한 장 요약

상태 — 5건째 투입 성공·AX001 기준 3건째, 전송=확정 자동화(C-13) 완료(2026-08-20): 1차 투입(2026-08-19 오후, DRAFT-20260819-0005→AG202608190006) 이후 화면 [🚀 ERP 전송] 버튼 E2E(2026-08-20, DRAFT-20260820-0007→AG202608200001)·AX001 전환 재성공(2026-08-20, DRAFT-20260819-0006→AG202608190007)·AX001 기준 2건째(2026-08-20, DRAFT-20260820-0008→AG202608200002)를 거쳐, AX001 기준 3건째 성공(2026-08-20, DRAFT-20260820-0009→AG202608200003, 라인 3/3 완전일치·차변 경비계정이 처음으로 53013501(판)소모품비)로 확장)까지 확인됐다. 같은 날 「전송 성공 = 확정」을 일원화(결정 C-13)해 화면의 ERP 결의전표번호 수기 입력칸·[확정 기록] 버튼을 제거했다 — 전표번호는 ERP가 채번해 자동 회기입되므로 사람이 옮겨 적을 이유가 없어졌고, RPC gl_apply_record가 성공 시 초안 상태를 submitted→posted로 자동 전이한다. 잔여는 U-F(AX001 계정매핑 등재 권장 — 수기 TG 상위 25종 경비계정 중 17종은 자기참조 코드 보유 확인됨)·2차 이상 케이스 확대·운영(JEILMNS) 전환 재심의(§6)뿐이다. 상세는 §7 변경이력.

무엇 — 포털에서 작성·제출한 결의전표 초안을, 사람이 ERP에 재입력하는 대신 적용기(관리자 PC 배치)가 DEMO2에 직접 투입해 ERP 표준 엔진으로 전표(TG류)를 생성한다. ERP 계정=MS 계정 1:1(C-3)이므로 전표 등록자는 포털 제출자의 ERP 계정 그대로다.

전표번호(핵심 요구) — AI가 만드는 전표는 전용 접두어 AG 대역으로 채번한다. ERP 표준 채번기(usp_a_tempgl_no_auto_gen 'AG' — B_AUTO_NUMBERING 기존 미사용 유형 재활용)를 쓰므로 중복이 원천 차단되고, TG(수기·기존 자동화) 대역과 완전히 분리되어 ①AI 전표만 골라 조회·회수 가능 ②사고 시 식별 즉시 ③운영 채번과 충돌 0. 포털 측에는 적용 원장(gl_erp_apply_log)이 모든 시도(리허설 포함)와 발급 번호를 기록·관리한다(성공 커밋의 초안·번호 유니크 제약).

A_JNL_ACCT_ASSN(거래유형·계정·차대 → JNL_CD) → A_JNL_FORM(거래유형·JNL_CD → EVENT_CD) 2단 조회. 조회 실패 시 실증 폴백 표(부가세대급금 A/A · 미지급금(거래처) AP · 미지급금(법인카드) AP2/CARDC), 그래도 없으면 중단(fail-closed — 임의 분개 금지, "분개는 AX가 완성하되 코드는 ERP 설정이 정답").

3.3 검증(엔진 호출 후, COMMIT 전)

① A_TEMP_GL 전표 생성 확인 ② 투입 라인 ↔ 생성 라인 완전대조(계정+차대+금액 다중집합 — 엔진이 라인을 재정렬하므로 순번 매칭 금지, 리허설 정정 3) ③ 불일치 시 대차 자동보정 개입으로 판정·ROLLBACK. 관리항목 슬롯 순서는 엔진이 재배치(정정 2 — 코드만 정확히).

3.4 서브원장 생성 (v1.7 신설 — 2026-08-25)

엔진은 전표만 만들고 서브원장은 만들지 않는다. 호출자가 usp_a_create_temp_gl_subsys 를 따로 불러야 채무(A_OPEN_AP)·부가세(A_VAT)가 생기고 라인의 연결번호(SUBSYS_NO)가 역기록된다. 법인카드 래퍼(USP_ACC2103M1_KO174_BATCH_GW)가 쓰는 표준 구조다.

이 호출이 없던 v1.6 까지의 전표는 전표·시산표는 멀쩡한데 채무·부가세 원장이 없는 상태로 만들어졌다 — 겉으로 드러나지 않아 더 위험했다(§7 변경이력 v1.7 참조).

단계 내용
호출 라인 대조 통과 직후, 엔진과 같은 트랜잭션
인자 @GL_NO 자리에 결의전표번호(AG…)를 넘긴다 — 파라미터명이 GL_NO 지만 본문은 temp_gl_no 로 쓴다
실패 시 rc<>1 이면 전표 생성까지 ROLLBACK — "전표만 있고 원장이 없는" 부분성공을 만들지 않는다
결과 검증 호출 성공만 믿지 않는다. 서브원장 대상 라인의 SUBSYS_NO 가 하나라도 비면 ROLLBACK. A_OPEN_AP·A_VAT 행수도 로그·적용원장에 기록

회계전표 직행(GL_POSTING_FG='G')용 usp_a_create_gl_subsys 분기는 두지 않았다 — 거래유형 확인이 'T' 를 이미 강제해 도달할 수 없는 경로다.

4. 실행 절차

4.1 화면 [🚀 ERP 전송] 방식 (v1.2 신설 — 실사용 테스트 경로)

회계 담당자가 화면에서 버튼을 눌러 전송하고, 사내 중계가 자동 투입한다. 포털은 여전히 ERP에 직접 쓰지 않는다 — 버튼은 erp_apply_status='ready' 마킹만 하고, 투입은 중계가 수행(기회검토 채택 구조: 사내 pull).

① 관리자 PC에서 중계를 켠다(감시 모드 — 15초 간격, Ctrl+C 종료)
   ! python "10_ERP_DB연계/etl/gl_apply_demo2.py" --watch
② 회계 담당자: 결의전표 입력 화면 → 「ERP 전송」 탭(v1.5, 구 「회계 담당자」 탭) → 제출된 초안 선택
   → [🚀 ERP 전송 (DEMO2)] 클릭 → 확인
③ 중계가 자동 처리(멱등 확인 → 분개코드 조회 → AG·BT 채번 → A_BATCH 투입
   → 표준 엔진 → 라인 완전대조 → 대조 통과 시 COMMIT)
④ 화면이 4.5초 간격 폴링으로 결과를 자동 감지 → 「ERP 적용」 열에 AG전표번호 표시
   (실패 시 '적용 실패' + 사유. 대기 중 취소는 [전송 취소])

상태머신: null → ready(버튼) → applied(성공, AG번호 회기입) 또는 failed(실패, 사유 기록). 중계를 상시 켜두지 않을 때는 버튼으로 대기만 걸고, 나중에 --queue(대기 건 일괄 처리, 1회 상한 5건)로 처리해도 된다.

4.2 CLI 단건 방식 (리허설·정밀 검증용)

! python "10_ERP_DB연계/etl/gl_apply_demo2.py" --list                      # 적용 대상 확인
! python "10_ERP_DB연계/etl/gl_apply_demo2.py" --draft DRAFT-... --dry-run  # 리허설(ROLLBACK)
! python "10_ERP_DB연계/etl/gl_apply_demo2.py" --draft DRAFT-...            # 확정(COMMIT+회기입)
! python "10_ERP_DB연계/etl/gl_apply_demo2.py" --draft DRAFT-... --cleanup  # 정리(삭제·상태 해제)

새 케이스(처음 쓰는 계정 조합)는 먼저 --dry-run으로 검증한 뒤 화면 전송을 쓰는 것을 권장한다. 화면 전송 경로는 리허설 없이 바로 확정 투입되지만, 라인 대조 불일치 시 자동 ROLLBACK되므로 안전 경계는 동일하다.
