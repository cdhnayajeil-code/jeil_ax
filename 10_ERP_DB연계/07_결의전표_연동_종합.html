한 줄 요약 — 화면이 실제로 동작하기 시작했고, 지금은 관리자만 쓸 수 있는 상태입니다. 전 직원이 ERP 화면에서 각자 입력하던 결의전표를, 케이스 1개(일반 경비 지출결의)에 한해 사내 포털에서 ERP와 동일한 형태로 입력받는 파일럿입니다. 포털 DB·API·입력화면이 배포된 데 이어 2026-08-03 A1 승인으로 회계 코드 마스터가 실적재됐습니다(계정과목 691행·코스트센터 133행) — 계정 드롭다운이 채워지고 마스터 미적재 배너가 사라졌습니다. 권한은 관리자 결정에 따라 테스트 단계 동안 전체관리자에게만 열려 있습니다(accounting 모듈 부서 미부여). 남은 승인은 A2·A5이고, 다음 실행은 전표 1건 E2E 테스트입니다.

1. 무엇을 만드는가 배경과 목표

현재 방식전 직원이 ERP(UNIERP) 결의전표 화면에서 각자 입력. 회계 지식이 없는 직원에게 어렵고, 그룹웨어 전자결재와 따로 움직여 이중 입력·오류가 발생
목표사내 AI 포털에서 케이스 1개를 샘플링해 ERP 결의전표와 같은 형태로 입력받고, 검증된 초안을 회계 담당자에게 넘긴다
대상 케이스일반 경비 지출결의(차변 비용계정 / 대변 미지급금·보통예금) — 부가세 미사용
범위 밖법인카드·세금계산서 매입(부가세 계산 필요), 전사 오픈, ERP 자동 등록 — 전부 파일럿 이후 별도 판단

2. 연동 구조 “초안은 포털, 확정은 ERP”

포털은 ERP에 쓰지 않습니다(CLAUDE.md §1.2·§1.6). 포털이 검증된 초안을 만들고, 사람이 ERP에서 최종 저장한 뒤 전표번호를 되돌려 기입해야 초안이 닫힙니다.

[직원]                  [포털]                        [회계 담당자]         [ERP]
결의전표 입력 화면 ──▶ 포털DB gl_draft/_item ──▶ 회계 담당자 탭 ──▶ ERP 결의전표 화면에
(MS SSO·등록자 자동)    Edge Fn jeil-gl-draft       (ERP 입력용 요약)     직접 저장(A_TEMP_GL)
                        · 차대일치·계정유효 검증                                 │
                        · 등록자 = JWT UPN → ERP USR_ID                          │
                        · 전 접근 감사로그          ◀── TEMP_GL_NO 회기입 ───────┘
                                                        (초안 status=posted)
      ▲
      └─ 마스터(계정과목·코스트센터·부서·거래처)는 중간DB에서 읽기 전용 조회
전표번호 회기입이 이중 입력을 막는 유일한 장치입니다. 사람이 개입하는 구간이라 같은 건이 ERP에 두 번 들어갈 수 있어, DB 제약으로 강제했습니다 — status='posted'이면 erp_temp_gl_no가 반드시 있어야 하고, 같은 전표번호를 두 초안에 기입하면 거부됩니다.

등록자 매핑 — 이 파일럿의 핵심 요구사항

그룹웨어 전자결재가 전표등록자를 기준으로 이뤄지므로, 등록자는 반드시 MS 계정과 동일한 ID여야 합니다. 기존 데이터로 확인한 결과:

  • ERP 사용자 마스터 99명 전원이 @jeilm.co.kr 이메일 형식 계정 → MS 계정(UPN)과 같은 체계
  • 대문자 포함 1건이 있어 lower() 비교로 매핑 (실측: dh.choi@jeilm.co.kr → 총무팀_최동혁 정상 반환)
  • 등록자는 JWT에서만 취득 — 화면 입력값을 신뢰하지 않음
  • 매핑 실패 시 저장 거부 — ERP 계정이 없는 사람 명의로 전표가 만들어지는 것을 원천 차단

6. 의사결정 ③ 미결정 사항 5건 — 결정되면 문서 갱신
