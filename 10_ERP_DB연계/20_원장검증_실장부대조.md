## 0. 19번과 무엇이 다른가

| | 19번 세트 | **20번 세트(이 문서)** |
|---|---|---|
| 묻는 것 | **가드가 잘 막는가** | **장부에 똑같이 반영되는가** |
| 전표 출처 | 설계해서 만든 것 | **실제 승인 전표를 복제** |
| 보는 곳 | 전표 안(투입 라인 대조) | 전표 **밖** — 채무·부가세·선급·선수·미결 원장 |
| 판정 | 통과/차단 | **원본과 한 줄도 어긋나지 않는가** |

릴레이가 투입 직후 하는 라인 대조는 *전표 안*만 본다.
**회계가 실제로 쓰는 것은 전표가 아니라 그 전표가 만들어 낸 원장이다.**
채무 잔액이 서고, 부가세 신고자료가 잡히고, 선급이 정산 대기에 올라가는 — 그 결과를 본다.

### 왜 실제 전표를 복제하나

발명한 전표로는 이 비교를 할 수 없다. **대조할 원본이 없기 때문이다.**
DEMO2 에 이미 승인돼 있는 수기 전표를 골라 계정·차대·금액·관리항목을 그대로 복제하면,
같은 분개가 두 경로(수기 / AX)로 들어간 셈이 되고 **원장 결과를 나란히 놓고 뺄 수 있다.**

## 2. 무엇을 대조하나

`verify_ledger.py` 가 AX 전표(`AG…`)와 원본(`TG…`)을 나란히 놓고 비교한다.

| # | 대상 | 비교 방식 |
|:--:|---|---|
| ① | 전표 라인 | 계정·차대·금액을 **다중집합**으로 — 엔진이 순서를 바꾸므로 순서는 보지 않는다 |
| ② | 관리항목 | (계정·차대·코드·값) 다중집합. **날짜형은 제외** — 복제할 때 오늘로 옮겼다 |
| ③ | 부가세 `A_VAT` | 건수 · 과세표준 · 세액 |
| ④ | 채무 `A_OPEN_AP` | 건수 · 금액 · 거래처 수 |
| ⑤ | 선급 `F_PRPAYM` | 건수 · 금액 |
| ⑥ | 선수 `F_PRRCPT` | 건수 · 금액 |
| ⑦ | 미결 `A_OPEN_ACCT` | 건수 · 금액 · 관리값(사번) — **승인 후에만 생긴다**(`GL_NO` 기준) |

미결은 승인 시점에 서므로, AX 쪽이 아직 승인 전이면 **차이가 아니라 「아직」** 으로 표시한다.

## 3. 복제 규칙 — 무엇을 그대로 두고 무엇을 옮기나

| | 처리 |
|---|---|
| 계정 · 차대 · **금액** | **원본 그대로.** 비교 대상이 바로 이것이다 |
| 거래처(BP) · 사번(EM) · 프로젝트(PC) · 발주(PO) | **원본 그대로** |
| 전표일자 | **오늘로 이동** — 닫힌 회계기간에는 넣을 수 없다 |
| 날짜형 관리항목(계산서일 `V2`·만기일 `C1`·`XC1`) | 전표일자에 맞춰 이동 (그래서 대조에서 제외) |
| 적요 | `ax검증_Vn <원본적요> (원본 TG…)` — 추적 가능하게 |

### 민감값을 저장소에 두지 않는다

거래처·사번·계좌·프로젝트 값은 **코드에 없다.** 실행할 때 원본 전표에서 읽어 온다.
저장소에 남는 것은 **원본 전표번호뿐**이다(`CLAUDE.md §1`). 화면 출력도 앞 2자리만 보인다.

> **주의**: 같은 분개가 DEMO2 에 두 번 들어간다(원본 + 복제). 비용이 이중 계상된다.
> **DEMO2 는 테스트 DB 이므로 의도된 것**이지만, 운영에서는 절대 이렇게 하지 않는다.

## 4. 옮길 수 없는 형태 — 실제 사례로 확인됨

`TG202505270017`(스웨덴법인 급여, `AP+AR`)은 **복제 대상에서 빠진다.**
1·2번 줄이 **음수**(−25,922 / −26,650)인데 포털은 `gl_draft_item` 에
`CHECK (item_amt > 0)` 이 걸려 있어 저장할 수 없다.

19번 §4.1 에서 「마이너스 전표는 만들 수 없다」고 적은 한계가 **실제 장부 전표로 확인된 것**이다.
차감 조정이 섞인 급여·정산 전표가 이 형태이고, DEMO2 수동입력 중 **939전표**가 마이너스 라인을 갖는다.
운영 전환 전 결정이 필요하다(19번 §4.1).

## 5. 사용법

```bash
python 10_ERP_DB연계/etl/seed_ledger_cases.py --plan    # 무엇을 복제할지 보기
python 10_ERP_DB연계/etl/seed_ledger_cases.py --load    # 포털에 적재(제출됨)
python 10_ERP_DB연계/etl/gl_apply_demo2.py  --precheck  # 보내기 전 점검(ERP 무투입)
#  → 화면 [ERP 전송] 탭에서 보내기 → ERP 화면에서 승인
python 10_ERP_DB연계/etl/verify_ledger.py               # 장부 대조
python 10_ERP_DB연계/etl/seed_ledger_cases.py --purge   # 정리(적용된 건은 보존)
```

`verify_ledger.py` 는 **읽기 전용**이고 차이가 있으면 종료코드 1을 돌려준다 — 자동화에 걸 수 있다.

### 판정

| 결과 | 뜻 |
|---|---|
| `✅ 라인·관리항목·원장 전부 일치` | AX 경로가 수기 경로와 **장부상 구별되지 않는다** |
| `❌ <원장>: 원본 N행 … ↔ AX M행 …` | 그 원장에서 어긋났다 — 금액·건수·거래처를 확인 |
| `⏳ 미결 … 승인 후에 생깁니다` | 차이가 아니다. ERP 에서 승인하면 채워진다 |
