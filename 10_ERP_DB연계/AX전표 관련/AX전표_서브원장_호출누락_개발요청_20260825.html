ERP 표준 연동과의 차이는 한 곳뿐

법인카드 연동(USP_ACC2103M1_KO174_BATCH_GW)과 나란히 놓고 본 것이다.

엔진(USP_A_CREATE_GL_BY_BATCH_01)은 서브원장을 만들지 않는다. 호출자가 별도로 불러야 하는 구조다.

빠진 SP 안에 무엇이 있나

-- usp_a_create_temp_gl_subsys 본문 (요약)
DECLARE CUR_SUBSYS_MAKE CURSOR FOR
SELECT A.TEMP_GL_NO, A.ITEM_SEQ, B.SUBSYS_TYPE, …
  FROM A_TEMP_GL_ITEM A
  JOIN A_ACCT     B ON A.ACCT_CD    = B.ACCT_CD
  JOIN A_TEMP_GL  C ON A.TEMP_GL_NO = C.TEMP_GL_NO
 WHERE ISNULL(B.SUBSYS_TYPE,'') <> ''
   AND B.SUBSYS_TYPE NOT IN ('OC','OD')
   AND A.TEMP_GL_NO = @GL_NO

  → EXEC usp_A_Create_Sub_Ledger …   -- A_OPEN_AP · A_VAT 실제 INSERT
  → EXEC usp_z_auto_numbering …      -- 원장번호 채번 (AP… / VT…)
  → EXEC usp_f_create_budget …       -- 예산 반영
  → UPDATE A_TEMP_GL_ITEM
       SET SUBSYS_TYPE = @SUBSYS_TYPE,
           SUBSYS_NO   = @SUBSYS_NO      -- 연결번호 역기록
     WHERE TEMP_GL_NO = @GL_NO AND ITEM_SEQ = @ITEM_SEQ

승인 시점이 아니라 결의 생성 시점이다

"승인하면 만들어지는 것 아닌가"를 확인해 두었다. 아니다.

근거실측
수기 미승인 전표에도 원장이 있다CONF_FG='U' 상태에서 이미 채무 1~4행 존재
생성 시각이 결의 생성과 같다TG202506120005 — 결의 08:52:25 / 부가세 08:52:00 / 채무 08:52:00
AX 전표는 승인해도 0행AG202608240001~3 화면 승인 → GL202608240001~3 전기됐으나 여전히 0행
결의 생성 시점에 만들어야 하며, 승인 경로가 대신 만들어 주지 않는다.

추가할 코드

위치 — USP_A_CREATE_GL_BY_BATCH_01 호출이 성공(rc=1)한 직후, 같은 트랜잭션 안.

-- ① 기존 엔진 호출
EXEC @RTN = dbo.USP_A_CREATE_GL_BY_BATCH_01
            @REF_NO, @USR_ID, @Msg_Cd OUTPUT;

IF ISNULL(@RTN,0) <> 1
BEGIN
    ROLLBACK TRANSACTION;
    RETURN -1;                      -- 기존 실패 처리
END

-- ② ★ 추가 — 서브원장 생성
EXEC @RTN2 = dbo.USP_A_CREATE_TEMP_GL_SUBSYS
             @TEMP_GL_NO,           -- ★ 결의전표번호 (배치번호·REF_NO 아님)
             @USR_ID,
             '', '',                -- DbuserId · DbPwd — 법인카드 래퍼도 빈값
             @Msg_Cd OUTPUT;

IF ISNULL(@RTN2,0) <> 1
BEGIN
    ROLLBACK TRANSACTION;           -- 전표 생성까지 되돌린다
    -- @Msg_Cd 를 gl_erp_apply_log 에 기록하고 '미적용' 상태로 남길 것
    RETURN -1;
END

SP 시그니처

usp_a_create_temp_gl_subsys (
    @GL_NO         nvarchar(18),      -- ★ 이름은 GL_NO 지만 결의전표번호를 받음
    @UPDT_USER_ID  nvarchar(30),
    @DbuserId      sysname,           -- '' 로 호출
    @DbPwd         nvarchar(256),     -- '' 로 호출
    @MSG_CD        nvarchar(100) OUTPUT
)
반환값 : 1 = 성공, 그 외 = 실패
가장 헷갈리는 지점 — 파라미터명이 @GL_NO 라서 정식전표번호로 보이지만, SP 본문은 WHERE a.temp_gl_no = @gl_no 로 쓴다. 결의전표번호(AG…)를 넘길 것.

결의 / 회계 분기

릴레이는 항상 결의전표(GL_POSTING_FG='T')를 만들므로 _TEMP_GL_SUBSYS 하나면 된다. 다만 향후 회계전표 직행 경로가 생길 수 있으니 법인카드 래퍼처럼 분기해 두는 편이 안전하다.

IF @GL_POSTING_FG = 'G'
    EXEC @RTN2 = dbo.USP_A_CREATE_GL_SUBSYS      @GL_NO,      @USR_ID, '', '', @Msg_Cd OUTPUT;
ELSE
    EXEC @RTN2 = dbo.USP_A_CREATE_TEMP_GL_SUBSYS @TEMP_GL_NO, @USR_ID, '', '', @Msg_Cd OUTPUT;

트랜잭션 요건

엔진 호출과 서브원장 생성을 같은 트랜잭션에 두십시오.
지금처럼 "전표는 있는데 채무가 없는" 부분 성공 상태가 다시 생기지 않도록 하는 것이 핵심입니다. 서브원장 생성이 실패하면 전표 생성까지 롤백하고, 포털 쪽 상태를 미적용으로 남겨 재시도 가능하게 해 주십시오.

함께 검토 부탁 (경미)

NULL vs 빈 문자열

릴레이는 미사용 컬럼에 빈 문자열(''), ERP 화면 수기 입력은 NULL 을 남긴다. 차이 21개 컬럼:

PROJECT_NO · IO_FG · BANK_CD · BANK_ACCT_NO · EMP_NO · CREDIT_CD · NOTE_NO
ITEM_CD · USER_DF1~5 · DEAL_BP_CD · CARD_CO_CD · MGNT_VAL1 · MGNT_VAL2
BDG_CD · CTRL_NO · TRACKING_NO · CASH_NO

장부 영향은 없다. 다만 ERP 조회·리포트가 IS NULL 조건을 쓰는 곳이 있으면 AX 전표만 결과에서 빠질 수 있다. 가능하면 NULL 로 맞추는 편이 안전하다.

개발 후 검증

DEMO2 에서 새 전표 1건을 릴레이해 확인한다. 기존 13건 소급은 대상 아님.

#확인정상 기준
1엔진 반환rc=1, MSG_CD 공백
2서브원장 SP 반환rc=1, MSG_CD 공백
3연결번호A_TEMP_GL_ITEM.SUBSYS_NO 가 AP… · VT… 로 채워짐
4채무A_OPEN_AP 1행 — 금액·거래처가 전표 라인과 일치
5부가세A_VAT 1행 — VAT_AMT 가 전표 라인과 일치
6승인 후A_GL_ITEM.SUBSYS_NO 로 승계
7현업채무관리 화면 조회 · 부가세 신고자료 집계

검증 쿼리

새로 만든 전표번호를 넣어 실행하면 된다.

DECLARE @slip nvarchar(18) = 'AG20260901xxxx';

SELECT I.ITEM_SEQ, I.ACCT_CD, I.DR_CR_FG,
       I.SUBSYS_TYPE,
       ISNULL(NULLIF(RTRIM(I.SUBSYS_NO),''),'(비어있음)') AS 연결번호,
       I.ITEM_AMT, I.VAT_AMT
FROM   A_TEMP_GL_ITEM I
JOIN   A_ACCT A ON A.ACCT_CD = I.ACCT_CD
WHERE  I.TEMP_GL_NO = @slip
  AND  ISNULL(A.SUBSYS_TYPE,'') <> ''
ORDER  BY I.ITEM_SEQ;

SELECT AP_NO, DEAL_BP_CD, ACCT_CD, AP_AMT, BAL_AMT, CONF_FG
FROM   A_OPEN_AP WHERE TEMP_GL_NO = @slip;

SELECT VAT_NO, BP_CD, ACCT_CD, NET_AMT, VAT_AMT, VAT_TYPE, IO_FG, CONF_FG
FROM   A_VAT     WHERE TEMP_GL_NO = @slip;
판독 — 연결번호가 (비어있음) 이면 SP 호출이 안 된 것이다. 연결번호는 채워졌는데 원장이 0행이면 그때 다시 봐야 한다.
