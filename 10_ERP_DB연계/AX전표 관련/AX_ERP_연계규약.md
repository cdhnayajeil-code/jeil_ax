# AX ↔ ERP 연계 규약

> 제정 2026-08-25 · 관리 최동혁 · 전담 에이전트 **`ax-erp-bridge`** (`.claude/agents/ax-erp-bridge.md`)
> **이 폴더(`ERP_DB\JEIL_AX연계\`)를 AX 포털과 ERP 를 잇는 모든 작업의 단일 창구로 정의한다.**
> 비밀값(IP/ID/비밀번호/키)은 이 폴더를 포함해 어디에도 기록하지 않는다.

---

## 1. 왜 이 규약이 필요한가

AX(AI포털) 프로젝트와 ERP_DB 프로젝트는 **PC도 폴더도 다르다.**
그런데 둘 사이에는 계속 오가는 것이 있다.

| 방향 | 무엇이 |
|---|---|
| ERP_DB → AX | ERP 실측 분석, 개발요청, 테스트 설계, 입력검증 규칙 |
| AX → ERP_DB | 처리 결과, 테스트 수행 결과, 릴레이 변경 내역 |

지금까지는 사람이 수동으로 복사했다. 그래서 **AX 쪽 문서가 구버전인 채로 남거나,
AX 가 붙인 회신을 ERP_DB 가 모르는** 일이 생겼다.
이 규약은 그 흐름을 고정한다.

## 3. 3단 흐름

```
① 발신          ② 승격                    ③ 회신
ERP_DB          AX 미러                    AX 정식등재본            ERP_DB
JEIL_AX연계 ──→ AX전표 관련\ ──────────→  NN_<제목>.md ──────────→ _회신\
  (원본)         (사본·덮어씀)              (AX 관리·회신블록 부착)   (읽기용)
```

### ① 발신 — 미러 갱신

ERP_DB 에서 문서를 만들거나 고치면 미러로 밀어넣는다. **미러는 사본이므로 항상 덮어쓴다.**

```powershell
.\_sync_ax.ps1 -Push
```

### ② 승격 — 정식 등재

AX 프로젝트가 정식으로 다루기로 한 문서는 **번호를 붙여** `10_ERP_DB연계\` 루트로 올린다.
번호는 그 폴더의 연속 시리즈를 잇는다.

```powershell
.\_sync_ax.ps1 -Promote 16 -Force
```

승격 후 AX 프로젝트 쪽에서 할 일 — `02_진행상태` 등재 · `index.html` 갱신 · `python _build_html.py`

### ③ 회신 — 결과 회수

**AX 는 정식 등재본 맨 위에 회신 블록을 붙인다.** 원문은 건드리지 않는다.

```markdown
> ## ✅ 처리 완료 (2026-08-25)
> …무엇을 했고 결과가 어땠는지…

---

# (여기부터 ERP_DB 원문 그대로)
```

ERP_DB 는 이 회신을 회수해 자료함에 반영한다.

```powershell
.\_sync_ax.ps1 -Pull
```

> **번호 시리즈는 절대 덮어쓰지 않는다.** 회신 블록이 사라지기 때문이다.
> 원문을 고쳐야 하면 ERP_DB 원본을 고치고 → 미러 갱신 → AX 에 "원문 개정" 을 알린다.

## 6. 절대 규칙 (ERP_DB `CLAUDE.md` 상속)

1. **ERP운영DB는 읽기 전용.** 발신 문서의 근거 조사는 `SELECT` 만. 조회도 `doc/db_log_YYYYMMDD_HHMMSS.md` 기록 필수.
2. **비밀값 금지.** IP·ID·비밀번호·Supabase 키를 문서·스크립트·로그 어디에도 쓰지 않는다.
   서버 지칭은 별칭 **"ERP운영DB"**. `_sync_ax.ps1` 이 동기화 전에 자동 점검하고 발견 시 중단한다.
3. **DEMO2 와 운영을 구분해 명시한다.** 실측 수치는 어느 DB 기준인지 반드시 적는다.
4. **원본은 ERP_DB, 회신은 AX.** 각자 자기 것만 고친다.

## 7. 문서 작성 규격

발신 문서는 아래를 지킨다. AX 쪽에서 그대로 읽고 작업할 수 있어야 한다.

| 항목 | 규격 |
|---|---|
| 파일명 | `AX전표_<주제>_<YYYYMMDD>.md` + 같은 이름 `.html` |
| 머리말 | 발신·수신·작성일·근거 DB·배치 제안 번호·선행 문서 |
| 필수 절 | 결론(요약) → 근거(실측) → 요청/조치 → 확인 필요 → 실측 조건 |
| 실측 조건 | 대상 DB · READ-ONLY 여부 · 조사 로그 파일명 · DEMO2 한계 명시 |
| HTML | 탭 구조 · 도식 · 다크모드 대응 (기존 문서 스타일 승계) |
| 요청 | 번호를 매기고 우선순위(상/중/하)를 붙인다 |

## 8. 정기 점검

| 주기 | 할 일 |
|---|---|
| 문서 작성·수정 직후 | `-Push` 로 미러 갱신 |
| AX 작업 요청 후 | `-Pull` 로 회신 확인 |
| 주 1회 | 인자 없이 실행해 미러·회신 현황 점검 |
| 회신 수령 시 | ERP_DB 자료함 반영 → 번호 대응표 상태 갱신 |
