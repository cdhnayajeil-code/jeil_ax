> **발신** ERP_DB 작업환경 (최동혁) · **수신** JEIL_AX 프로젝트 / 릴레이 개발 담당

> **AX 프로젝트 배치 제안** `10_ERP_DB연계/13_AX전표_서브원장_호출누락_개발요청.md`
> **성격** 향후 생성분 정상화. **기존 13건 소급은 대상 아님**(2026-08-25 결정)

## 1. 요청 한 줄

**릴레이가 ERP 전표 생성 엔진을 호출한 뒤, 서브원장 생성 SP 를 한 번 더 호출하도록 추가해 주십시오.**

코드 1블록이면 됩니다. 데이터 보정이나 마스터 등록은 필요 없습니다 — 이미 다 갖춰져 있습니다.

## 2. 현재 무슨 일이 일어나고 있나

릴레이가 만든 전표는 **전표 자체는 완벽한데 채무·부가세 원장이 생기지 않습니다.**

| 항목 | 릴레이 생성분 | 수기 입력분 |
|---|---:|---:|
| 전표 헤더·라인 | 정상 | 정상 |
| 관리항목 전개 | 정상 | 정상 |
| 정식장부 전기 | 정상 | 정상 |
| **`A_TEMP_GL_ITEM.SUBSYS_NO`** (연결번호) | **0 / 26** | 5,483 / 5,483 |
| **`A_OPEN_AP`** (채무) | **0행** | 3,054행 |
| **`A_VAT`** (부가세) | **0행** | 2,519행 |

2025년 이후 ERP 정식전표의 서브원장 대상 라인 4,963건 중 연결번호가 비어 있는 것은 **8건뿐이고 전부 AX 전표**입니다. 다른 예외는 없습니다.

### 업무 영향

| 영역 | 영향 |
|---|---|
| **부가세 신고** | AX 전표의 매입세액이 `A_VAT` 에 없어 신고자료에서 누락 |
| **채무 관리** | 미지급금이 `A_OPEN_AP` 에 없어 지급·반제 대상에서 누락. 거래처별 잔액·연령분석에도 안 잡힘 |
| 재무제표 | **영향 없음** — 전표는 장부에 정상 반영되므로 시산표·재무제표는 정상 |

전표와 시산표가 멀쩡해서 **겉으로 드러나지 않는 결손**입니다. 운영 전환 전 반드시 해소해야 합니다.

## 3. 원인

ERP 표준 연동(법인카드 `USP_ACC2103M1_KO174_BATCH_GW`)과 비교하면 차이가 한 곳뿐입니다.

| 단계 | 법인카드 (표준) | AX 릴레이 (현재) |
|---|---|---|
| ① 전표번호 | `USP_A_TEMPGL_NO_AUTO_GEN` | 직접 지정 (`AG…`) — 무방 |
| ② 투입 | `A_BATCH` / `_GL` / `_ITEM` INSERT | 동일 |
| ③ 전표 생성 | `USP_A_CREATE_GL_BY_BATCH_01` | 동일 |
| **④ 서브원장** | **`USP_A_CREATE_TEMP_GL_SUBSYS`** | **호출 없음** ← 여기 |

**엔진(`USP_A_CREATE_GL_BY_BATCH_01`)은 서브원장을 만들지 않습니다.** 호출자가 별도로 불러야 합니다.

빠진 SP 안에 아래가 전부 들어 있습니다.

```sql
-- usp_a_create_temp_gl_subsys 본문 (요약)
DECLARE CUR_SUBSYS_MAKE CURSOR FOR
SELECT A.TEMP_GL_NO, A.ITEM_SEQ, B.SUBSYS_TYPE, …
  FROM A_TEMP_GL_ITEM A
  JOIN A_ACCT     B ON A.ACCT_CD    = B.ACCT_CD
  JOIN A_TEMP_GL  C ON A.TEMP_GL_NO = C.TEMP_GL_NO
 WHERE ISNULL(B.SUBSYS_TYPE,'') <> ''
   AND B.SUBSYS_TYPE NOT IN ('OC','OD')
   AND A.TEMP_GL_NO = @GL_NO

  → EXEC usp_A_Create_Sub_Ledger …      -- A_OPEN_AP · A_VAT 실제 INSERT
  → EXEC usp_z_auto_numbering …         -- 원장번호 채번 (AP… / VT…)
  → EXEC usp_f_create_budget …          -- 예산 반영
  → UPDATE A_TEMP_GL_ITEM
       SET SUBSYS_TYPE = @SUBSYS_TYPE,
           SUBSYS_NO   = @SUBSYS_NO     -- 연결번호 역기록
     WHERE TEMP_GL_NO = @GL_NO AND ITEM_SEQ = @ITEM_SEQ
```

### 승인 시점이 아니라 결의 생성 시점입니다

혹시 "승인하면 만들어지는 것 아닌가" 하실 수 있어 확인해 두었습니다.

- 수기 **미승인** 전표(`CONF_FG='U'`)에도 채무가 1~4행씩 이미 존재합니다.
- 생성 시각이 결의전표 생성과 같습니다 — `TG202506120005` : 결의 08:52:25 / 부가세 08:52:00 / 채무 08:52:00
- AX 전표를 ERP 화면에서 승인해도(`AG202608240001~3` → `GL202608240001~3`) **여전히 0행**입니다.

**→ 결의 생성 시점에 만들어야 하며, 승인 경로가 대신 만들어 주지 않습니다.**

## 4. 사전 확인 완료 — 데이터 보정은 불필요합니다

호출만 추가하면 되는지, 데이터도 손봐야 하는지 미리 확인했습니다. **호출만 추가하면 됩니다.**

### 4.1 계정 마스터 속성 정상

| 계정 | 재무제표구분 | 계정특성 | 서브시스템 |
|---|:--:|:--:|:--:|
| `11103301` 부가세대급금 | `BS` | `VP` | `TP` |
| `21100901` 미지급금(거래처) | `BS` | `J2` | `AP` |
| 경비계정 (`43…` `53…`) | `MC` / `PL` | — | — (대상 아님) |

`21100901` 의 `ACCT_TYPE='J2'` 는 채무 생성 요건(`AP_POSTING_FG='J'`)을 만족합니다.

### 4.2 전표 라인에 서브시스템이 이미 정상 승계됨

릴레이가 만든 26개 대상 라인 전부 `SUBSYS_TYPE` 이 `AP` / `TP` 로 올바르게 들어가 있습니다.
**비어 있는 것은 `SUBSYS_NO`(연결번호) 하나뿐입니다.**

### 4.3 SP 진입 판정 26/26 통과

SP 내부의 `A_OBJECT` 매칭 조건을 그대로 재현해 전 라인에 적용했습니다.

| 조합 | `A_OBJECT` 행 | 대상 원장 | 라인수 | 매칭 |
|---|---|---|---:|:--:|
| `TG` × `AP` × `CR` | `TG-AP` | `A_OPEN_AP` | 13 | ✅ |
| `TG` × `TP` × `DR` | `TG-TP` | `A_VAT` | 13 | ✅ |

skip 되는 라인이 없습니다.

### 4.4 SP 가 읽는 입력필드도 수기와 동등

| 필드 | 용도 | AX | 수기 |
|---|---|---|---|
| `REF_NO` (라인) | 서브원장 참조번호 | `DRAFT-20260824-0014` | `TG202506250002` |
| `ISSUED_DT` (라인) | 부가세 채번 기준일 | 부가세라인 실제일 / AP라인 `1900-01-01` | 동일 패턴 |
| `VAT_TYPE` | 계산서유형 | `A` | `A` |
| `BP_CD` | 거래처 | 채워짐 | 채워짐 |
| `GL_INPUT_TYPE` (헤더) | `A_OBJECT` 매칭 키 | `TG` | `TG` |

## 5. 요청 내용 — 추가할 코드

### 5.1 위치

`USP_A_CREATE_GL_BY_BATCH_01` 호출이 성공(`rc = 1`)한 **직후**, **같은 트랜잭션 안**.

### 5.2 코드

```sql
-- ① 기존 엔진 호출
EXEC @RTN = dbo.USP_A_CREATE_GL_BY_BATCH_01
            @REF_NO, @USR_ID, @Msg_Cd OUTPUT;

IF ISNULL(@RTN,0) <> 1
BEGIN
    ROLLBACK TRANSACTION;
    RETURN -1;                      -- 기존 실패 처리
END

-- ② ★ 추가 — 서브원장 생성
EXEC @RTN2 = dbo.USP_A_CREATE_TEMP_GL_SUBSYS
             @TEMP_GL_NO,           -- ★ 결의전표번호 (배치번호·REF_NO 아님)
             @USR_ID,
             '', '',                -- DbuserId · DbPwd — 법인카드 래퍼도 빈값
             @Msg_Cd OUTPUT;

IF ISNULL(@RTN2,0) <> 1
BEGIN
    ROLLBACK TRANSACTION;           -- 전표 생성까지 되돌린다
    -- @Msg_Cd 를 gl_erp_apply_log 에 기록하고 '미적용' 상태로 남길 것
    RETURN -1;
END
```

### 5.3 SP 시그니처

```
usp_a_create_temp_gl_subsys (
    @GL_NO         nvarchar(18),      -- ★ 이름은 GL_NO 지만 결의전표번호를 받음
    @UPDT_USER_ID  nvarchar(30),
    @DbuserId      sysname,           -- '' 로 호출
    @DbPwd         nvarchar(256),     -- '' 로 호출
    @MSG_CD        nvarchar(100) OUTPUT
)
반환값 : 1 = 성공, 그 외 = 실패
```

> ⚠️ **가장 헷갈리는 지점** — 파라미터명이 `@GL_NO` 라서 정식전표번호로 보이지만,
> SP 본문은 `WHERE a.temp_gl_no = @gl_no` 로 씁니다. **결의전표번호(`AG…`)를 넘기십시오.**

### 5.4 결의/회계 분기

릴레이는 항상 결의전표(`GL_POSTING_FG='T'`)를 만들므로 `_TEMP_GL_SUBSYS` 하나면 됩니다.
다만 향후 회계전표 직행 경로가 생길 수 있으니 법인카드 래퍼처럼 분기해 두는 편이 안전합니다.

```sql
IF @GL_POSTING_FG = 'G'
    EXEC @RTN2 = dbo.USP_A_CREATE_GL_SUBSYS      @GL_NO,      @USR_ID, '', '', @Msg_Cd OUTPUT;
ELSE
    EXEC @RTN2 = dbo.USP_A_CREATE_TEMP_GL_SUBSYS @TEMP_GL_NO, @USR_ID, '', '', @Msg_Cd OUTPUT;
```

### 5.5 트랜잭션 요건

**엔진 호출과 서브원장 생성을 같은 트랜잭션에 두십시오.**

지금처럼 "전표는 있는데 채무가 없는" 부분 성공 상태가 다시 생기지 않도록 하는 것이 핵심입니다.
서브원장 생성이 실패하면 전표 생성까지 롤백하고, 포털 쪽 상태를 **미적용**으로 남겨 재시도 가능하게 해 주십시오.

```sql
-- 새로 만든 전표번호를 넣으십시오
DECLARE @slip nvarchar(18) = 'AG20260901xxxx';

SELECT I.ITEM_SEQ, I.ACCT_CD, I.DR_CR_FG,
       I.SUBSYS_TYPE,
       ISNULL(NULLIF(RTRIM(I.SUBSYS_NO),''),'(비어있음)') AS 연결번호,
       I.ITEM_AMT, I.VAT_AMT
FROM   A_TEMP_GL_ITEM I
JOIN   A_ACCT A ON A.ACCT_CD = I.ACCT_CD
WHERE  I.TEMP_GL_NO = @slip
  AND  ISNULL(A.SUBSYS_TYPE,'') <> ''
ORDER  BY I.ITEM_SEQ;

SELECT AP_NO, DEAL_BP_CD, ACCT_CD, AP_AMT, BAL_AMT, CONF_FG
FROM   A_OPEN_AP WHERE TEMP_GL_NO = @slip;

SELECT VAT_NO, BP_CD, ACCT_CD, NET_AMT, VAT_AMT, VAT_TYPE, IO_FG, CONF_FG
FROM   A_VAT     WHERE TEMP_GL_NO = @slip;
```

**연결번호가 `(비어있음)` 이면 SP 호출이 안 된 것이고, 채워졌는데 원장이 0행이면 그때 다시 봐야 합니다.**

## 7. 함께 확인해 주실 것 (경미)

### NULL vs 빈 문자열

릴레이는 미사용 컬럼에 **빈 문자열(`''`)**, ERP 화면 수기 입력은 **NULL** 을 남깁니다. 차이 21개 컬럼:

```
PROJECT_NO · IO_FG · BANK_CD · BANK_ACCT_NO · EMP_NO · CREDIT_CD · NOTE_NO
ITEM_CD · USER_DF1~5 · DEAL_BP_CD · CARD_CO_CD · MGNT_VAL1 · MGNT_VAL2
BDG_CD · CTRL_NO · TRACKING_NO · CASH_NO
```

장부 영향은 없습니다. 다만 ERP 조회·리포트가 `IS NULL` 조건을 쓰는 곳이 있으면 AX 전표만 결과에서 빠질 수 있습니다. **가능하면 NULL 로 맞추는 편이 안전합니다.**
