비밀값(접속 IP/ID/비밀번호) 미기재 — 서버 지칭은 별칭 “ERP운영DB”만 사용.

가장 중요한 한 가지 — 포털은 ERP에 쓰지 않습니다. 포털이 하는 일은 검증된 초안을 만드는 것까지입니다. ERP에 실제로 등록하는 행위는 회계 담당자가 ERP 화면에서 직접 합니다. 포털의 “확정”은 전표를 만드는 동작이 아니라, 사람이 이미 등록한 결과(전표번호)를 받아 적는 기록 동작입니다. 이 되받아 적기가 같은 전표가 ERP에 두 번 들어가는 것을 막는 유일한 장치이며, DB 제약으로 강제돼 있습니다.

2. 단계별 데이터 작업 각 단계에서 실제로 무엇이 쓰이나

화면을 열면 서버가 신원·권한·마스터를 한 번에 내려줍니다. 이 응답으로 드롭다운이 채워지고 저장 가능 여부가 결정됩니다.

4회계 담당자 검토회계 담당자 · op: list / get

5ERP 등록 — 사람이 직접회계 담당자 · ERP 화면

포털은 이 단계에 관여하지 않습니다. 회계 담당자가 ERP 결의전표 화면에 요약 값을 입력해 저장하고, ERP가 전표번호를 채번합니다.

ERP 테이블기록되는 것포털 대응
A_TEMP_GL결의전표 헤더 — TEMP_GL_NO(TG+YYYYMMDD+4자리 채번) · TEMP_GL_DT · GL_TYPE='03' · GL_INPUT_TYPE='TG'(수기 결의) · INSRT_USER_ID(등록자, 이메일형) · CONF_FG='U'(미승인)gl_draft 헤더
A_TEMP_GL_ITEM분개 라인 — ACCT_CD·DR_CR_FG·ITEM_AMT·ITEM_DESC·BP_CD·COST_CDgl_draft_item
등록자가 왜 중요한가 — 그룹웨어 전자결재가 전표등록자를 기준으로 돌아갑니다. 그래서 포털은 등록자를 MS 계정(UPN)에서만 취득하고, ERP 사용자 마스터에 매핑되지 않으면 초안 생성 자체를 거부합니다. ERP 계정이 없는 사람 명의로 전표가 만들어지는 것을 막기 위해서입니다.

6. 지금 상태에서 주의할 점 테스트 전 반드시 인지

① 프로젝트 필수 검증(7종 중 5번)이 현재 동작하지 않습니다. 적재해 보니 계정과목 691행 전량 project_fg가 NULL이라, 프로젝트가 필요한 계정을 골라도 서버가 막지 않습니다. ERP 원천이 비어 있거나 다른 컬럼·체계로 관리될 가능성이 있어 A5·유니포인트 확인 대상입니다. 테스트에서 이 항목이 통과하더라도 정상 판정으로 오해하지 마세요.
② 마감월 통제가 비어 있습니다. gl_period_lock에 등재된 월이 0건이라 어떤 결의일자도 막히지 않습니다. 마감 기준은 A5에서 확정해 등재해야 합니다.
③ 전표형태는 실측 확정됐습니다(2026-08-03). A2 승인 조회 결과 2026년 2,947건 전량 GL_TYPE='03' 단일값이라 선택지가 아니라 상수입니다 — 화면도 03 · 일반전표 하나로 고정했습니다.
④ 권한은 전체관리자 한정입니다. 테스트 단계라 accounting 모듈을 어느 부서에도 부여하지 않았습니다(관리자 결정).
⑤ 회기입을 “잊는 것”은 시스템이 막지 못합니다. ERP에 등록해 놓고 포털에 전표번호를 적지 않으면 초안은 submitted로 남습니다. 화면이 미기입 초안을 목록 상단에 경고 표시하지만, 근본 해소는 운영 규칙(S6 회고에서 정할 사항)입니다.

#행위자동작기대 결과
1작성자화면 진입계정 드롭다운이 채워지고, 등록자가 본인 ERP ID로 자동 표기
2작성자차변·대변을 일부러 다르게 입력 후 저장차단 + 차액 표시(unbalanced)
3작성자금액 맞춘 뒤 저장 → 제출초안번호 DRAFT-… 발급, 상태 제출됨
4회계 담당자「회계 담당자」 탭에서 요약 확인·복사헤더·라인이 ERP 입력 순서대로 정확히 표시
5회계 담당자ERP 결의전표 화면에 동일 값 입력·저장ERP에 정상 등록, TEMP_GL_NO 채번
6회계 담당자전표번호 없이 확정 시도거부(erp_no_required)
7회계 담당자전표번호 회기입 → 확정상태 확정됨, 작성자 화면에도 전표번호 표시
8회계 담당자같은 전표번호를 다른 초안에 기입 시도거부(duplicate_erp_no) + 기존 초안번호 안내
9관리자화면을 거치지 않고 API 직접 호출 — ①차대 불일치 ②없는 계정코드 ③타인 UPN전부 거부. 프론트 검증만으로는 불충분하므로 필수 확인
10관리자gl_draft_log 확인bootstrap·save·submit·view·post가 전부 기록
