# 12 · 권한 설정 — 조직도 기반 페이지 공개·권한 설정 설계

> 관리자: 최동혁(dh.choi@jeilm.co.kr) · 기준일: 2026-09-23 · 상태: **Accepted — 1차 구현·배포 완료 2026-09-23 (ADR-107)** · 구현 결과는 §12
> 관련: [09 ADR](09_ADR_의사결정기록.md)(ADR-010 권한 코어 · ADR-014 권한 화면 일원화 · **ADR-107**) · [05 FE·BE](05_프론트엔드_백엔드_설계.md) · [04 DB설계](04_데이터베이스_설계.md) · [08 보안](08_보안_데이터안정성.md) · 목업 [`12_권한_조직도기반_공개설정_목업.html`](12_권한_조직도기반_공개설정_목업.html) · 백로그 REQ-0078 · `CLAUDE.md §5·§13·§15`

지금 권한 설정 화면(`/admin/permissions`)은 **부서를 글자로 적는 화면**입니다. 공유 부서는 쉼표로 타이핑하고, 소유 부서는 이름 목록에서 고릅니다. 조직 계층은 보이지 않습니다.
이 문서는 권한 설정을 **조직도 트리를 보면서 클릭으로 지정하고, 누가 실제로 보게 되는지 즉시 확인하는 화면**으로 바꾸는 설계입니다.

**결론부터**
1. 조직 원천은 이미 있습니다. ERP 부서 마스터가 중간DB 재귀 뷰 `erp_ro.v_dept_tree`로 들어와 있습니다(현행 조직 `20261`, 35개 부서).
2. 부서의 기준 키를 **부서명에서 부서코드(`dept_cd`)로** 바꿉니다. 상위 조직을 지정할 때는 노드마다 **「하위 포함」을 선택**할 수 있게 합니다(기본은 켜짐).
3. 판정은 지금처럼 **`perm_effective` 함수 하나**에서만 바꿉니다(ADR-010). 전환기에는 이름 판정과 코드 판정을 함께 둡니다.
4. 화면은 **좌 조직도 / 중 설정 / 우 영향 미리보기**의 3분할이고, 「페이지 → 조직」과 「조직 → 페이지」 두 방향 보기를 둡니다.

근거는 §1~§2, 설계는 §3~§7, 이관·단계·미결정은 §8~§11에 있습니다.

## 1. 현재 상태 (실측, 2026-09-23)

### 1-1. 화면: 부서를 글자로 적는다

`app/admin-permissions.html`의 「부서 권한」 탭은 두 표로 되어 있습니다.

| 영역 | 현재 입력 방식 | 문제 |
|---|---|---|
| 부서별 ERP 모듈(`#erpMatrix`, :355-399) | 부서 행 × 모듈 열 체크 매트릭스. 부서는 **이름을 가나다순으로 나열** | 계층이 없습니다. 본부·부문·팀이 같은 줄에 섞여 27행입니다. 상위에 한 번 주는 방법이 없습니다. |
| 페이지 공개 설정(`#pageRows`, :385-397) | 소유 부서는 드롭다운, **지정 공유 부서는 쉼표 텍스트 입력**(`pp-shared`) | 오타가 나도 그대로 저장됩니다. 누가 실제로 보게 되는지 알 수 없습니다. |

드롭다운 후보 `deptUniverse()`(:315-321)는 "ERP 계정 표기 부서 + 이미 설정에 들어간 이름"의 합집합입니다. 그래서 **유령 부서명도 선택지로 계속 다시 나타납니다.**

### 1-2. 데이터: 이미 유령 부서명이 저장돼 있다

라이브 값을 읽기 전용으로 조회한 결과입니다.

| 위치 | 유령 이름(현행 조직에 없음) | 영향 |
|---|---|---|
| `portal_page.shared_depts` | `재무회계팀`·`내부회계팀`(`finance_dashboard`·`finance_daily`), `회계`(`gl_draft`) | 아무에게도 적용되지 않습니다. `gl_draft`는 「지정 부서 공유」인데 공유 대상이 사실상 0명입니다. |
| `dept_erp_scope` | `재무회계팀`·`내부회계팀`·`영업팀`·`헝가리지원팀`·`회계` (5종) | 설정 행만 차지하고 효과가 없습니다. 부서명이 바뀐 흔적입니다(REQ-0032). |
| `portal_page` 조합 모순 | `finance_dashboard`: 「부서 전용」인데 공유 부서 4개 / `purchase_list_2026`: 공유 부서에 자기 부서 중복 | 공유 부서가 판정에서 **무시**되는데 화면에는 공유처럼 보입니다. |

`dept_erp_scope` 27행 중 **22행이 같은 기본 5모듈**(매출·매입·재고·품목·발주)입니다. 다른 점은 민감 모듈을 가진 4곳(인사팀 `payroll`, 자금팀·내부회계관리팀·재무회계팀 `finance`)뿐입니다. 조직도 상속을 쓰면 **최상위 1행 + 예외 3~4행**으로 줄일 수 있습니다.

### 1-3. 판정: 부서명 완전일치, 하위 조직 개념 없음

- `perm_effective`(라이브 정의, 정본 SQL `17_perm_core.sql`에는 계약만 있음)는 사용자 소속을 `v_erp_user_dept.dept_nm` 하나로 잡습니다. ERP 계정 표기 `부서명_이름`을 파싱한 값입니다. 여기에 개인 예외 `perm_grant(dept)`를 더합니다.
- 페이지 판정은 `p.dept_nm = any(v_depts)`, `sd = any(v_depts)`이고, 모듈 판정도 `dept_erp_scope.dept_nm = any(v_depts)`입니다. 전부 **문자열 완전일치**입니다.
- 서버 저장 `jeil-chat-admin`의 `save_page_perm`(:88-106)은 받은 이름을 **검증 없이 upsert**합니다.

**그래서** 부서명이 한 글자만 달라도 권한이 조용히 사라집니다. 오류 없이 0명이 됩니다. 조직개편으로 이름이 바뀌어도 같은 일이 일어납니다.

## 2. 조직 기준정보 원천

| 항목 | 원천 | 비고 |
|---|---|---|
| 부서 마스터 | ERP `B_ACCT_DEPT` → ETL → `erp_ro.dept_master_s` | 컬럼: `org_change_id`·`dept_cd`·`dept_nm`·`par_dept_cd`·`end_dept_fg`. **정렬·사용여부 컬럼은 없습니다.** |
| 계층 | `erp_ro.v_dept_tree`(정본 `sql/50_erp_role_matrix.sql:169-208`) | `lvl`·`path_cd[]`·`path_nm`·`sort_key`·`has_child`·`is_current`. 조직 버전은 7개이고 현행은 `20261`입니다. |
| 소속 인원 | `erp_ro.v_dept_member` | 1순위는 인사 `hr_emp_s.dept_cd`(부서 마스터와 87/87 일치, 유령 0), 폴백은 계정명 파싱입니다. `account_active`·`hr_active`를 함께 줍니다. |
| 구명칭 → 현행 코드 | `public.dept_map_legacy`(시드 `etl/seed/dept_map_legacy.csv`, 37종) | 규칙은 same·rename·merge·split·unmapped입니다. 이관 때 그대로 씁니다. |
| 그룹웨어 조직도 | **원천으로 쓰지 않습니다** | GW에는 `partName` 문자열만 있고 코드와 상위 부서가 없습니다. 계층은 ERP와 사실상 같습니다(`10_ERP_DB연계/22_그룹웨어_조직도_실측대사`). 대사 신호로만 씁니다. |

**현행 조직도 (org 20261, 활성 계정 수 기준)**

```
제일엠앤에스(0000)
├─ BDP본부(0200)
│  ├─ 품질부문(0100) ─ 품질팀(7400)
│  ├─ 사업부문(6700) ─ 구매팀(5200) · 사업운영팀(6110) · 사업관리팀(6120)
│  ├─ 설계부문(6900) ─ 제어설계팀(6210) · 공정설계팀(6220) · R&D팀(6910) · 기계설계팀(8100)
│  └─ 생산부문(7000) ─ 생산팀(7100) · 자재물류팀(7200)
├─ 경영기획부문(1000) ─ 경영기획팀(1100) · 내부회계관리팀(2400)
├─ 재무부문(2000) ─ 재무팀(2100) · 자금팀(2300)
├─ 경영지원부문(3000) ─ 총무팀(3200)
├─ 인사부문(3100) ─ 인사팀(3150)
├─ 공통예산(1300) · 제조공통(1310) · 연구공통(1320) · 판관공통(1330)   ← 원가부서(인원 0)
└─ 해외법인관리(9900) ─ 헝가리법인 · 스웨덴법인 · 미국법인 · 캐나다법인
```

**함정 (구현 시 필수 확인)**
- `dept_cd`는 `char(10)` 공백 패딩이고, 루트의 `par_dept_cd`는 공백 문자열입니다. `btrim` 없이 `is null`로 루트를 판정하면 트리가 **조용히 0행**이 됩니다.
- `dept_full_nm`은 경로가 아닙니다. 경로는 `v_dept_tree.path_nm`을 씁니다.
- `v_dept_member`에는 비활성·퇴사 계정 행도 들어 있습니다. 화면의 "인원"은 **`account_active` 기준**으로 셉니다(REQ-0033과 같은 이유).

## 3. 화면 설계 — 「조직도로 보고, 클릭으로 정하고, 결과를 먼저 본다」

목업은 [`12_권한_조직도기반_공개설정_목업.html`](12_권한_조직도기반_공개설정_목업.html)에 있습니다(라우트 `/docs/product/org-permission-mockup`).

### 3-1. 배치 — 3분할

```
┌ 보기: [페이지 → 조직] [조직 → 페이지] ─────────────────── 기준 조직 20261 · 활성 계정 기준 ┐
│ ① 조직도 트리          │ ② 설정                          │ ③ 영향 미리보기             │
│ 🔍 부서 검색           │ 페이지: 재고 입·출고 현황        │ 볼 수 있는 부서 6 · 인원 21 │
│ ▾ 제일엠앤에스   3     │ 소유 부서: 자재물류팀 [트리에서]  │  · 자재물류팀(소유)  3       │
│   ▾ BDP본부      2     │ 공개범위: ○부서전용 ○전사 ●지정  │  · 구매팀            2       │
│     ▸ 품질부문         │ 공유 부서(칩):                  │  · 사업관리팀        10      │
│     ▾ 사업부문    ☑    │  [사업부문 ⤵하위포함 ×]          │  · 사업운영팀        20 ←新  │
│        구매팀     ☑    │  [자재물류팀 ×]                  │ ⚠ 민감 모듈 아님            │
│        사업운영팀 ☑    │ ERP 모듈: 재고                   │ 변경 전 대비 +1부서 +20명   │
│        사업관리팀 ☑    │                                  │ [저장] [되돌리기]           │
└────────────────────────┴──────────────────────────────────┴──────────────────────────────┘
```

- **① 조직도 트리**
  - `v_dept_tree` 순서(`sort_key`)대로 표시하고 펼치기·접기를 지원합니다.
  - 검색하면 일치하는 노드의 경로를 자동으로 펼칩니다.
  - 노드마다 **활성 인원 수**와 **현재 권한 배지**(소유·공유·하위 포함으로 상속)를 표시합니다.
  - 체크는 3상태입니다: ☑ 직접 지정 / ◩ 상위의 하위 포함으로 상속됨 / ☐ 없음.
  - 상속된 노드는 따로 체크할 필요가 없으므로 흐리게 표시하고 "↑ 사업부문에서 상속" 툴팁을 답니다.
- **② 설정**
  - 기존 입력 칸(소유 부서·공개범위·공유 부서·ERP 모듈·활성)을 그대로 두되, 부서는 **트리에서 고른 칩**으로만 입력합니다. 자유 텍스트 입력은 없앱니다.
  - 칩마다 「⤵ 하위 포함」 토글이 있고, 기본은 켜짐입니다. 말단 부서에서는 토글을 숨깁니다.
  - 「전사 공개」를 고르면 공유 칩을 비활성화하고 "전사 공개에서는 공유 부서가 쓰이지 않습니다"라고 알립니다. `finance_dashboard` 같은 모순 조합을 **화면에서 원천 차단**합니다.
- **③ 영향 미리보기**
  - 저장 전에 **실제로 보게 되는 부서 목록과 활성 인원 합계**, 변경 전 대비 증감(+부서·+인원)을 보여 줍니다.
  - 민감 모듈(급여·자금·회계)이 걸린 페이지를 넓힐 때는 **빨간 경고와 확인 단계**를 둡니다.
  - 미리보기 계산은 화면 추정이 아니라 서버 `perm_preview`(§5)의 결과를 씁니다. 목업에서는 화면 계산으로 흉내 냅니다.

### 3-2. 두 방향 보기

| 보기 | 질문 | 좌 트리 | 중·우 |
|---|---|---|---|
| **페이지 → 조직** | "이 페이지를 누가 보나?" | 선택한 페이지의 공개 범위가 트리에 칠해짐 | 페이지 설정 + 영향 미리보기 |
| **조직 → 페이지** | "이 부서는 무엇을 보나?" | 부서 하나 선택 | 그 부서가 볼 수 있는 **페이지 목록(판정 사유 포함)** + **ERP 모듈**(직접·상속 구분) |

「조직 → 페이지」에서 ERP 모듈은 **트리 상속형 매트릭스**로 편집합니다. 최상위 「제일엠앤에스 ⤵하위포함」에 기본 5모듈을 한 번 지정하고, 인사팀 `payroll`·자금팀 `finance` 같은 예외만 따로 추가합니다.
**민감 모듈은 상속을 허용하지 않습니다.** 말단 부서에 직접 지정할 때만 유효합니다. 상위에 급여를 걸면 하위 전원이 급여를 보게 되는 사고를 구조적으로 막기 위해서입니다.

### 3-3. 조직 기준정보 패널

트리에서 노드를 클릭하면 아래에 패널이 열립니다.

| 항목 | 출처 |
|---|---|
| 부서코드 · 부서명 · 상위 부서 · 경로(`path_nm`) · 레벨 · 말단 여부 | `v_dept_tree` |
| 활성 인원 / 인사 재직 인원 / 전체 계정 | `v_dept_member`(`account_active`·`hr_active`) |
| 이 부서가 소유한 페이지 · 공유받은 페이지 · ERP 모듈(직접/상속) | `portal_page`·`portal_page_scope`·`dept_module_scope` |
| 경고 | 인원 0(원가부서) · 계정 표기 부서와 인사 부서 불일치 수 · 그룹웨어에만 있는 하위팀 |

이름은 실명으로 표시해도 됩니다(CLAUDE.md §1.7, 관리자 전용 화면). 인원 목록을 펼치면 `v_account_recon` 카드(ADR-014)로 연결합니다.

### 3-4. 유령·미매핑 처리 화면

화면 상단에 **「정리 필요」 배지 영역**을 두고, 저장된 값 중 현행 트리에 없는 것을 모아 보여 줍니다.
- 예: "`재무회계팀`(finance_dashboard 공유) — 현행 조직에 없음 → [재무팀으로 바꾸기] [삭제]"
- 후보는 `dept_map_legacy`에서 제안합니다.
- 버튼이 실제로 동작하는 것은 이관 단계(§8)부터이고, 그 전에는 목록만 보여 줍니다.

## 4. 데이터 모델 (ADR-107 제안)

### 4-1. 키 = `dept_cd`, 범위 = `(dept_cd, include_sub)`

```sql
-- 페이지 공개 범위(공유 부서) — shared_depts text[] 를 대체
create table public.portal_page_scope (
  page_key     text   not null references public.portal_page(page_key) on delete cascade,
  dept_cd      text   not null,            -- btrim 된 코드. 현행 v_dept_tree 존재 검증(서버)
  include_sub  boolean not null default true,
  org_change_id text  not null,            -- 지정 당시 조직 버전(개편 감지용)
  updated_by   text, updated_at timestamptz default now(),
  primary key (page_key, dept_cd)
);
alter table public.portal_page add column owner_dept_cd text;   -- dept_nm 과 병행(전환기)

-- 부서 ERP 모듈 — dept_erp_scope(dept_nm, module_key) 를 대체
create table public.dept_module_scope (
  dept_cd      text not null,
  module_key   text not null references public.perm_module_catalog(module_key),
  include_sub  boolean not null default true,   -- 민감 모듈은 check 로 false 강제
  org_change_id text not null,
  updated_by text, updated_at timestamptz default now(),
  primary key (dept_cd, module_key)
);
```

- 민감 모듈의 상속 금지는 **DB 제약**(트리거 또는 check + 카탈로그 조인)으로 강제합니다. 화면 검증만으로는 부족합니다(CLAUDE.md §5.4).
- 기존 `portal_page.dept_nm`·`shared_depts`·`dept_erp_scope`는 **전환기 동안 남겨 둡니다.** 삭제는 §8 5단계에서 합니다.

### 4-2. 사용자 소속

| 순위 | 원천 | 이유 |
|---|---|---|
| 1 | `hr_emp_s.dept_cd`(인사) — `v_dept_member.dept_src='hr'` | 코드 원천이고 유령이 0건입니다. 부서 이동이 인사 발령으로 반영됩니다. |
| 2 | ERP 계정 표기 파싱 → `dept_map_legacy`로 코드 변환 | 인사 행이 없는 계정(외부·공용)용 폴백입니다. |
| 3 | 개인 예외 `perm_grant(scope_type='dept')`의 `scope_key` | 전환기에는 코드와 이름을 모두 허용합니다(`erp_role_org_tree`:603 선례). |

계정이 비활성(`account_active=false`)이면 소속을 부여하지 않습니다(REQ-0033 해소 방향).

### 4-3. 판정 (`perm_effective` 단일 수정)

```
user_path  := 사용자 소속 dept_cd 의 v_dept_tree.path_cd   -- 예) {0000,0200,6700,5200}
페이지 허용 :
  is_admin
  or 전사 공개
  or owner_dept_cd = any(user_depts)
  or (지정 부서 공유 and exists(
        select 1 from portal_page_scope s
        where s.page_key = p.page_key
          and ( s.dept_cd = any(user_depts)                      -- 그 부서 자체
             or (s.include_sub and s.dept_cd = any(user_path)) ))) -- 상위 지정 + 하위 포함
  or 개인 예외(page) allow, 단 deny 가 최우선
```

- 우선순위 **차단 > 개인 허용 > 부서**(ADR-010)는 그대로입니다.
- 전환기에는 기존 이름 판정 결과와 **OR**로 합칩니다. 이관이 끝나고 두 판정의 차이가 0건임을 확인하면 이름 판정을 제거합니다.
- 반환 값의 `pages[].reason`에 "사업부문(하위 포함)에서 공유" 같은 **판정 사유**를 넣어, 「유효 권한」 화면과 미리보기가 같은 문장을 쓰게 합니다.

## 9. 조직개편 대응

- 판정은 항상 **현행 org**(`is_current`)를 따릅니다.
- scope 행의 `org_change_id`가 현행과 다르면, 그 코드가 현행 트리에 **여전히 있는지** 확인합니다.
  - 있으면: 조용히 현행으로 갱신합니다(코드가 유지된 개편).
  - 없으면: 「정리 필요」 배지(§3-4)에 올리고 판정에서 **제외(fail-closed)** 합니다. `dept_map_legacy`에 매핑이 있으면 후보로 제안합니다.
- ETL이 새 `org_change_id`를 적재하면 관리자 콘솔에 "조직개편 감지 — 권한 재확인 N건"을 알립니다.
