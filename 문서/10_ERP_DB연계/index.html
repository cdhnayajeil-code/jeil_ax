ERP DB 연계 관제 허브

ERP(UNIERP) DB ↔ AI 포털·사내 타부서 연계의 현재상태·기획·진행상태 단일 출처 · 관리: 최동혁

현재 위치(2026-10-08): 구매 로드맵 P1 1차 — 구매 건 추적·진행판의 중간DB 연계 객체 5종과 포털 카드 2행을 라이브 적용했다(REQ-0116, 정본 SQL 95) — 번호 하나로 구매 한 건(요청→발주→입고→매입→대장)을 읽기 전용으로 보는 화면 2종(/work/purchase-trace·/work/purchase-board)의 바탕이다: 뷰 v_erp_pur_board(발주 1건 = 1행 · 8단계 상태를 실적 문서로 판정) · 함수 pur_case_round·pur_case_chain·pur_case_round_fin(security invoker) · 함수 pur_proposal_links()(security definer 유일 예외 — 기안↔발주 연결 사실만). 추가 ETL·기존 뷰 변경·권한 확대는 없고(결정 C-15 유지 — 사내 사용자의 전표·계산서 칸은 「열람 범위 밖」) 사내 역할 실측은 통과했다(뷰 1,054행 0.52초). 직전(2026-10-07 오후) 상태 — 서버 러너 r1.12 교체(15:22) · 발주 전량 재적재(15:52) · 기안서 대장 적재 재가동(15:52~16:03)으로 발주 사본 원값≠실효값 줄 439 → 5줄(남은 5줄과 유령 발주 1줄은 발주·입고 미러 삭제 정합 부재 — 범위 밖·결정 전), 서버 실행본 r1.12 · 릴레이 v1.10 — 은 그대로 유지된다. 그 아래 단계(erp_ro RLS InitPlan 17/17 통일(REQ-0040)·ERP 권한 조직별 현황(REQ-0057/0065)·계정 통합관리·대사(REQ-0018)·기안서 대장 ↔ ERP 전표·전자세금계산서 대사(REQ-0081/0082)·결의전표 운영 전송(D-113)·연동 러너 단일 통합 등)는 그대로 유지된다. 상세는 02 진행상태 §1(현재 위치 요약)·00 현재상태 스냅샷 §4(연계 현황 표) 참조 · 관리자 대기: 구매 건 추적·진행판 라이브 실측(로그인 세션에서 두 화면 열기 · 포털 구매팀 카드 2종 확인 — REQ-0116 done 조건). 남은 확인은 pur_req --full 필요 여부(미확인)와 결의전표 운영 전송 후속(서버 교체가 끝나 착수 가능) · 결정 대기: 구매 로드맵 P0 의 마지막 항목 「대장에 발주번호 칸」(D-122), 전표·계산서 열람 범위(C-15) 확대 여부(구매 P1 은 넓히지 않고 「열람 범위 밖」으로 표시 — 열린 질문 유지), 발주·입고 미러 삭제 정합(수집함 기록, REQ-0041 과 묶음), 구매 ERP 추가 연결 후보 4종(REQ-0109, 결정 전), REQ-0068·0069 본 문서 소급 등재 여부, 유니포인트 협의(P1, 읽기전용 계정·뷰 스펙), 자금(F 모듈) 경영 승인, 정본 SQL 50·51의 라이브 정합 승격 여부(REQ-0065 조사 중 발견), 그룹웨어 겸직 정보 확장 방법(벤더 뷰 확장 vs 스크레이프), ENTRA_CLIENT_SECRET 조기 회전 여부(정기 만료 2026-12-09)
