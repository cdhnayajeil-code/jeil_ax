# 22. 그룹웨어 조직도 실측 대사

> **작성일 2026-09-18 · v0.2(실측 완료) · 관리: 최동혁 · 요청: REQ-0057**
> 신규 「ERP 권한(role) 조직별 현황」 운영페이지(`/work/erp-roles`)는 **ERP `org_change_id='20261'`(35부서) 조직**만 반영했다.
> 이 문서는 그 ERP 조직과 **그룹웨어(ONUL Ware) 실제 조직도**를 대사해, 두 조직 체계가 가리키는 부서가
> 같은 조직을 뜻하는지 확인하는 전용 관리 문서다. **2026-09-18 실측 완료** — 결론은 §1.
> 관련: `00_현재상태_스냅샷`(v0.57 §1·§4·§6) · `02_진행상태.md`(§2·§4) · `05_사용자부서_매핑대사.md`(ERP↔사용자 대사, 이 문서와 대상이 다름)

---

## 1. 상태 — 실측 완료 (2026-09-18)

**결론: 그룹웨어 조직도와 ERP `org_change_id='20261'` 의 계층은 사실상 동일하다.**
부문 구성과 팀 배치가 한 곳도 어긋나지 않았다. 따라서 화면(`/work/erp-roles`)이 ERP 부서 마스터 트리를
쓰는 것은 「그룹웨어 조직도 기준」 요구와 어긋나지 않는다.

차이는 네 가지뿐이고, 모두 성격이 분명하다.

| # | 차이 | 성격 | 화면 처리 |
|---|---|---|---|
| 1 | **원가부서 4종**(공통예산·연구공통·제조공통·판관공통)이 ERP 에만 있다 | 예산 집계용 더미 부서. 그룹웨어 조직도에 없다 | 인원 0이라 기본 숨김 — **실측으로 근거 확인됨** |
| 2 | **영업자문**(BDP본부 하위)이 그룹웨어에만 있다 | 그룹웨어 현직 1명. ERP 부서 마스터·ERP 계정 부서 표기 어디에도 없다 | ERP 계정이 없어 화면에 나타나지 않는다 |
| 3 | **해외법인 하위 팀**이 그룹웨어에만 있다(헝가리 지원팀·기술팀 / 스웨덴 관리팀·기술팀·개발팀) | 그룹웨어가 한 단계 더 세분화. ERP 는 법인 단위까지만 | 법인 단위로 접어서 본다(ERP 트리 기준) |
| 4 | **법인 명칭 표기**가 다르다 | GW `제일엠앤에스 미국`↔ERP `미국법인` 등 4건, GW `해외법인`↔ERP `해외법인관리` | `dept_map_legacy` 에 rename 으로 등재 완료 |

**실측 방법**: 관리자 화면의 「기본정보관리 → 부서관리」는 이 계정에 권한이 없어 열리지 않았다
(관리자 메뉴가 게시판·커뮤니티·설문조사·자원 4종뿐). 대신 **주소록의 조직도 트리**(`.GroupListOutWrap`)를
전부 펼쳐 38개 노드를 읽었다 — 같은 조직 마스터를 보여주는 화면이라 계층 확인에는 충분하다.
조회만 했고 쓰기 버튼은 누르지 않았다.

## 2. 실측한 그룹웨어 조직도 (38노드, 2026-09-18)

```
㈜제일엠앤에스
├─ 제일엠앤에스
│  ├─ BDP본부
│  │  ├─ 품질부문 ─ 품질팀
│  │  ├─ 설계부문 ─ 기계설계팀 · 공정설계팀 · 제어설계팀 · R&D팀
│  │  ├─ 사업부문 ─ 구매팀 · 사업운영팀 · 사업관리팀
│  │  ├─ 생산부문 ─ 생산팀 · 자재물류팀
│  │  └─ 영업자문                      ← ERP 에 없음
│  ├─ 경영기획부문 ─ 경영기획팀 · 내부회계관리팀
│  ├─ 재무부문 ─ 재무팀 · 자금팀
│  ├─ 경영지원부문 ─ 총무팀
│  └─ 인사부문 ─ 인사팀
└─ 해외법인                            ← ERP 「해외법인관리」
   ├─ 제일엠앤에스 헝가리 ─ 지원팀 · 기술팀      ← ERP 「헝가리법인」(팀 없음)
   ├─ 제일엠앤에스 스웨덴 ─ 관리팀 · 기술팀 · 개발팀  ← ERP 「스웨덴법인」(팀 없음)
   ├─ 제일엠앤에스 미국                       ← ERP 「미국법인」
   └─ 제일엠앤에스 캐나다                     ← ERP 「캐나다법인」
```

**재측정 규칙**: 그룹웨어 원천 뷰(`GW_TABLE_NAME`)에는 부서명 문자열 1칸(`partName`)만 있고 부서코드·상위부서가
없다. 계층은 화면에서만 얻을 수 있으므로 **조직개편 때 사람이 다시 읽어야 한다.** 자동 수집 스크립트를 새로
만들지 않는다 — 쓰기 화면을 건드릴 위험 대비 얻는 게 없다(조직개편은 드물고, ERP 부서 마스터가 계층을 갖고 있다).

## 4. 미확인 사항

- **인원 집계가 화면마다 다르다 — 원인 미확인.**
  주소록 임직원 **123명** / 직원관리 화면 「사용중」 **112명** / 미러 `public.acct_groupware` 사용 **104명**.
  주소록에는 겸직이 별도 행(`(겸)`)으로 나타나고, 미러는 이메일이 PK 라 이메일 없는 계정(실측 46건)이 빠진다 —
  이 둘이 차이의 유력한 후보지만 **확인하지 않았다.** 조직 계층 확인이 이번 실측의 목적이었고, 인원 대사는
  계정 통합관리(REQ-0018) 소관이라 임의로 조치하지 않았다.
- **부서관리 화면 자체는 열지 못했다.** 이 계정의 관리자 메뉴에 「기본정보관리」가 없다(게시판·커뮤니티·설문조사·자원 4종뿐).
  부서별 인원 수·부서코드까지 보려면 `gw_offboard.py` 가 쓰는 관리자 계정으로 다시 열어야 한다.
