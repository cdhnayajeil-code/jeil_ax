## 운영 메모


- **2026-10-06 오후 — 현재 워커 n1.6 · 구매 에이전트에 NAS 도구 켬(설정 v3)** — 도구 4종(파일 목록·본인 과거 대화·문서 검색·문서 읽기)이 구매 에이전트 화면에서 동작(`jeil-chat-lab` v21 · 중계 v6 · 회귀 157건). 수정: N-2 과거 대화 일시 한국시간 · N-3 목록 카드 `undefined` 해소 · 파일 목록 `folder` 인자 · 저장 직후 색인. 한계: 문서 검색은 본문만(파일 이름 불가) · 엑셀 날짜가 일련번호로 색인 · `docs`/`nas` 문서 도구 선택 갈림(N-4).
- **재빌드 함정 ① 이미지 꼬리표** — 꼬리표가 그대로(`:n1`)면 Container Manager 가 옛 이미지를 다시 써 옛 버전이 계속 돈다. 워커를 고칠 때 꼬리표도 올린다(지금 `jeil-nas-worker:n1.6`). **② 끊긴 재빌드** — 다시 만들다 끊기면 컨테이너 이름 앞에 ID 가 붙고 화면의 중지·정리가 무반응 → SSH `docker ps -a` 에서 실제 ID 를 찾아 `docker rm -f` 후 재빌드(절차 `10_ERP_DB연계/etl/deploy/nas/README.md` §7.1).
- **2026-10-06 P4 — 첨부 원본·생성 자료 부서 폴더 저장(REQ-0108)** — 사용자가 [🗄 NAS 저장]을 누른 것만 부서 폴더 `AI저장/<연도>/` 에 보관(보존 3년 · 만료 뒤 `nas_save_policy.after_expiry` 초기값 keep · NAS 외부 백업 없이 적용 = D-104 비선행, D-115). 정본 SQL 89 · `jeil-nas-bridge` v6 · `jeil-chat-lab` v19 · 워커 n1.5. **지금 상태: 컨테이너 재빌드 완료(10-06 오후, n1.5 → n1.6) — 저장이 컨테이너에서 실제 동작**(엑셀 3건 구매팀 폴더 `AI저장/2026/` 보관 · 건당 약 2초).
- **2026-10-06 접속 장애·복구(REQ-0102)** — 서울사무소 PC 에서 NAS 가 전부 무응답이던 원인은 컨테이너 전용 네트워크가 Docker 자동 배정으로 172.20.0.0/16 을 차지해 사내 대역과 겹친 것. `compose.yaml` 의 `network_mode: bridge` 로 해결(절차 `10_ERP_DB연계/etl/deploy/nas/README.md` §8, 이유 §3.1). 복구 뒤 `jeil-nas-worker` 심박 정상 = NAS 컨테이너 워커 가동. 교훈: Docker 새 네트워크는 172.17~172.31 을 차례로 배정하므로 NAS 의 다른 프로젝트(itasset 등)도 사내 대역과 겹치는지 점검한다.
