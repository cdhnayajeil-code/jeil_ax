## 단일 출처

- **구매업무 프로세스의 정본은 `01_구매업무_프로세스_도식.html`** 이다. 번호(PR·PU·PO)의 정의와 실측은 `문서/12_에이전트관리/04_구매도메인_발주통합LIST.md`(에이전트용 지식)를 따른다.
- 02·03 은 `.md` 가 원본이고 `.html` 은 생성본이다(손으로 고치지 않는다).
- 단계의 이름·순서·번호 사슬을 바꾸면 01 을 고친다. 예시 화면의 도식은 01 의 표식 블록(`pur:style`·`pur:flow`·`pur:chain`)을 그대로 떠 가므로 표식을 지우지 않는다.

## 공개 범위 — 이 폴더는 전부 공개물로 다룬다

문서 센터(`/docs`)는 로그인 없이 열리고, 이 폴더의 파일은 라우트에 없어도 주소로 열린다.
**실제 거래처명·금액·문서번호·결재자 이름을 이 폴더의 어떤 파일에도 적지 않는다**(html·md·py·sql 모두).
번호는 가상 표기(`PR2026MMDD0001`), 수치는 전체 합계만 쓴다.

실거래 자료가 든 「구매 건 추적」 예시는 git 제외 폴더(`doc/` 아래 사례 폴더)에 둔다.

```
python 문서/14_구매업무시스템/_build_case.py "<사례 폴더>"            # case.json → 구매건_추적.html
python 문서/14_구매업무시스템/_build_case.py "<사례 폴더>" --check    # 점검만
```

빌더는 사례 폴더를 인자로만 받고, 출력 위치가 저장소 안인데 git 제외 대상이 아니면 쓰기를 거부한다.

## 갱신 규칙

- 프로세스가 바뀌면(단계·담당·양식·번호) → 01 을 고치고, 예시 화면을 다시 만든다.
- 01 의 「확인 필요」 표에 답이 달리면 → 01 본문과 03 의 「가정」을 고친다.
- 기존 화면·데이터 상태가 바뀌면(결함 수정, 적재 재가동) → 02.
- 결정이 나거나 로드맵 단계가 착수·완료되면 → 03. 구축은 단계마다 별도 요청(REQ)으로 올린다.
- `.md` 를 고친 뒤 `python 문서/14_구매업무시스템/_build_html.py`. 문서를 추가하면 루트 `_routes.py` 에 한 줄 넣고 `python _build_routes.py --write`.
- 의미 있는 변경은 `문서/00_관리체계/03_변경관리_CHANGELOG` 에 한 줄.
