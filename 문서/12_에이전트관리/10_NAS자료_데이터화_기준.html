10 · NAS 업로드 자료 데이터화 기준 — 부서 에이전트 공통

기준: 2026-10-08 · 상태 검토 기획(기준 확정 단계 S0) · 관리자 최동혁 · 코드·DB 무변경 · 2026-10-08 관리자 결정 2건 반영(D-144 저장 위치 · D-147 대상 범위 — §9) 이 문서는 공개 문서 센터에 올라가므로 실제 거래처·금액·문서번호와 NAS 주소·경로는 적지 않는다. 적용 대상은 구매 에이전트만이 아니라 앞으로 만들 모든 부서 에이전트다. 부서가 달라져도 이 기준은 같고, 부서마다 달라지는 것은 「문서 종류 등록」뿐이다.

1. 한 줄 요약

에이전트 보관함(부서 NAS 의 AI저장/)에 올린 PDF·엑셀·문서에서 필요한 값만 뽑아 표로 쌓고, 사람이 확인한 값만 「확정」으로 쓰게 한다. 정답은 언제나 ERP 데이터다 — 문서에서 뽑은 값은 ERP 값을 고치지도 채우지도 않고, 다르면 「차이」로만 보여 준다.

2. 결론 먼저

질문 답
에이전트가 NAS 자료를 읽을 수 있나 글자는 이미 읽는다(낱말 검색·이어 읽기). 표·숫자를 항목별로 뽑아 쌓는 기능은 없다 — 이번 기획의 대상
ERP 데이터가 훼손될 수 있나 없다. 기존 규칙으로 ERP 운영 DB 쓰기는 막혀 있다. 다만 「섞여 보이는」 위험을 막는 규정이 비어 있어 §4 로 메운다
뽑은 값은 어디에 두나 본문은 지금처럼 사내 NAS 에만, 등록된 필드 값만 포털 DB 전용 구역에 둔다(결정 D-144 · 2026-10-08)
어떤 파일을 읽나 부서마다 정해 둔 기본 적용 폴더는 넣기만 하면 자동으로 읽고, 그 밖은 사용자가 지시하거나 고른 폴더·파일만 읽는다(결정 D-147 · 2026-10-08)
틀린 값은 어떻게 막나 검수 4겹 — 규칙 검수 → 검수 에이전트(독립 재추출) → ERP 대조 → 사람 확정(§6)
다른 부서는 어떻게 쓰나 엔진·검수 화면은 공용. 부서는 문서 종류를 등록하는 것으로 합류한다(§7)
지금 하는 일 기준·규칙 확정과 결정 요청까지. 구현은 단계마다 별도 요청으로 승인받는다(§8)

3. 지금 상태 (2026-10-08 · 사실)

되는 것

  • 보관함: 대화에 붙인 파일·만든 자료를 [NAS 저장]으로 부서 폴더 AI저장/ 에 보관 · 폴더 만들기 · 내려받기 · 삭제(저장 대장 etl_meta.nas_save).
  • 읽기: 허용 폴더 문서의 본문을 낱말로 검색(발췌 320자) · 문서 번호로 이어 읽기(1회 약 6천 자) · 파일 목록 조회.
  • 색인: 저장 직후 수 초~수십 초 안에 사내 색인(SQLite)에 들어간다. 색인은 사내에만 있다(D-95).

안 되는 것

항목 내용
값 추출 추출 결과가 평문 한 덩어리다. 엑셀은 열 머리글·셀 위치가 사라지고 빈 칸 때문에 열이 밀린다. 날짜가 일련번호로 읽힌다
쌓는 곳 추출 값을 담는 표·쓰기 도구·검수 절차가 없다. 에이전트 도구는 전부 읽기용이다
못 읽는 형식 스캔본 PDF·이미지(글자 인식 없음) · 구형 .hwp·.xls·.doc · .xlsm. 저장은 되는데 읽히지 않는 형식이 있고, 그 사유가 화면에 보이지 않는다
화면 구매 화면에서는 보관함 파일을 대화로 다시 불러올 수 없다(DRI 화면에만 있다)
모델 현재 예비 모델이 응답 중이라 PDF 를 판독하지 못한다 — 크레딧 충전으로 해결 예정(관리자 · 2026-10-08)

4. 기본 규칙 확인 — ERP 데이터 보호

이미 있는 규칙으로 막혀 있는 것

규칙 내용 판정
작업 규칙 §1.2 · §4.1 ERP 운영 DB 는 읽기 전용, 포털은 중간 DB 만 본다(전표 전송 예외 1건뿐) 추출 데이터가 ERP 운영에 닿을 경로가 없다
§4.3 포털 전용 쓰기 데이터는 별도 표에 두고 ERP 키로 매핑만 한다 추출 표의 근거 규칙
§1.6 실거래 액션을 사람 대신 실행하지 않는다 추출 값으로 발주·등록 자동화 금지
게이트웨이 도구 유형 읽기·초안·요청 3종뿐 — 모델이 직접 쓰는 도구가 없다 모델이 임의로 데이터를 바꾸지 못한다

비어 있던 것(이번에 정한다)

  • ⓐ 중간 DB 의 ERP 미러(erp_ro)와 추출 데이터를 물리적으로 나눈다는 규정
  • ⓑ 같은 항목(단가·금액·수량)이 ERP 와 문서에 둘 다 있을 때 어느 쪽이 정답인지
  • ⓒ 에이전트 답변·화면에서 두 출처를 구분해 표기하는 규정

5. 기준 — 원칙 9개

  1. 정본 서열 — ERP(미러) > 사람이 확정한 포털 기록 > 문서 추출 값. 추출 값은 ERP 값을 덮지 않고, ERP 의 빈 칸을 채우지도 않는다. 어긋나면 고치는 것이 아니라 「차이」로 보여 준다.
  2. 물리적 분리 — 추출 데이터는 전용 구역(가칭 스키마 doc_data)에만 둔다. erp_ro 에는 표·열·뷰를 만들지 않고, 추출 쪽 함수는 erp_ro 를 읽기만 한다. ERP 키는 외래키가 아니라 연결 표(후보·근거·확정자)로 잇는다. 「추출 함수에 erp_ro 쓰기 권한이 없다」를 회귀 테스트로 잠근다.
  3. 표기 분리 — ERP 조회 도구와 문서 데이터 도구는 별개 도구이고, 결과에 출처가 반드시 붙는다: ERP 기준 / 문서 추출·미확인 / 문서 추출·확인됨. 한 표에 섞지 않고, 추출 값을 ERP 집계에 더하지 않는다.
  4. 원본 추적 — 모든 추출 값은 원본 파일(저장 대장 번호·지문)·위치(쪽·시트·셀)·원문 인용·추출기 판·모델·시각을 갖는다. 원본은 고치지 않는다 — 파일이 바뀌면 새 판이고, 옛 추출은 「대체됨」으로 남는다.
  5. 수명주기 — 접수 → 판독 → 분류 → 추출(초안) → 자동 검수 → 확정 / 반려 → 폐기. 원본을 지우거나 보존 기한이 끝나면 추출 데이터도 함께 폐기한다.
  6. 대상 범위(결정 D-147) — 두 갈래다. ① 기본 적용 폴더: 부서 NAS 폴더 안에 정해 둔 폴더로, 여기에 넣은 파일은 지시가 없어도 항상 판독·데이터화 대상이 된다. ② 그 밖: 사용자가 지시하거나 고른 폴더·파일만 한다. 어느 쪽이든 허용 폴더 등록 범위 안이어야 하고, 기안서 스캔본 폴더(D-102 — 내용을 읽지 않는다)와 민감 종류는 기본 적용 폴더로 지정할 수 없다. 기본 적용 폴더가 어디인지는 코드가 아니라 DB 등록표가 정한다(부서별). 자동으로 읽더라도 결과는 초안까지다 — 확정은 검수(§6)를 거친다.
  7. 허용 필드만 — 문서 종류에 등록된 필드만 저장한다. 본문·전체 글자는 계속 NAS 에만 둔다(D-95). 급여·인사평가 종류는 등록할 수 없고, 기존 민감 이름·주민등록번호 꼴 차단은 그대로 둔다.
  8. 종류는 설정, 코드가 아니다 — 문서 종류·필드·검사 규칙·검수 수준·ERP 대조 방식은 등록표가 정한다. 새 부서는 종류를 등록해 합류하고, 추출·검수 엔진은 하나를 같이 쓴다.
  9. 실거래 금지 — 추출·확정 값으로 ERP 등록·발주·결재를 대신 실행하지 않는다. 조회·대조·초안까지만.

6. 검수 체계 — 4겹

겹 누가 무엇을 확인하나 권한
L1 규칙 검수 프로그램(항상 같은 결과) 필수 필드 · 형식 · 합계 = 수량×단가의 합 · 부가세 · 날짜 범위 · 사업자번호 검증 · 원문 대조(뽑은 값이 판독한 글자에 실제로 있는가) 불합격 필드 표시
L2 검수 에이전트 공용 검수 프로필(부서 없음) 추출 결과를 보지 않고 처음부터 다시 뽑아 필드별로 비교. 추출과 다른 지시문·모델 등급을 쓴다 판정만(일치/불일치). 고치거나 확정하지 못한다
L3 ERP 대조 DB 함수(읽기) 업체·품목·발주번호로 ERP 후보를 찾아 차이를 표시 참고 정보. ERP 는 바뀌지 않는다
L4 사람 확정 부서 담당자 불일치·차이 필드를 중심으로 확인·정정 후 [확정] 유일한 확정 권한. 확정자·시각이 남는다

종류별 검수 수준(등록표에서 정한다)

수준 대상 방식
human 금액·단가·수량이 든 종류(견적서·명세서 등) 사람 확정 필수. 확정 전에는 「미확인」
sample 목록·대장처럼 규칙으로 읽히는 종류 L1·L2 통과 시 자동 확정 + 주기 표본 검사
auto 분류·요약·꼬리표만 다는 일반 문서 자동 확정. 표본 검사
  • 표본 검사 오류율이 기준을 넘으면 그 종류는 자동으로 human 으로 내려간다.
  • 품질 관리 — 종류마다 정답 추출본(골든셋)을 두고, 추출기 판(지시문·필드·모델)을 바꾸면 회귀를 통과해야 지정한다. 검수 에이전트도 같은 버전 체계(초안 → 회귀 → 지정)로 관리한다.
  • 에이전트는 미확인 값을 말할 때 항상 「미확인」을 붙이고, 보고서·CSV 에는 확정 값만 쓴다.

7. 구조 (권고안)

어디에 두나 — 혼합

무엇 어디 이유
원본 파일 · 본문 글자 · 색인 사내 NAS(지금과 같음) D-95 유지
등록된 필드 값 · 검수 결과 · 확정 이력 포털 DB 전용 구역 검수 화면·ERP 대조·에이전트 조회가 빠르고 안정적이어야 한다(NAS 왕복은 시간 상한이 있고 NAS 외부 백업이 아직 없다)

처리 흐름

기본 적용 폴더에 파일이 들어옴(자동) / 사용자가 폴더·파일을 고르거나 지시함
  ├ PDF·이미지 → NAS 에서 임시로 꺼내 대화 모델이 직접 판독(NAS 에 글자 인식기를 두지 않는다)
  └ 엑셀·문서  → NAS 워커가 표 구조를 살려 판독(시트 이름·머리글·셀 위치·날짜)
→ 종류 분류 → 종류에 등록된 필드대로 추출 → 초안 저장 → 검수 4겹 → 확정
  • 모델 호출은 게이트웨이 한 곳에서만 한다. NAS 컨테이너는 판독만 하고, 모델 키·관리 키를 두지 않는다.
  • 한 번에 한 건씩 처리하고, 시간 상한·하루 건수·비용 한도를 건다(기본 적용 폴더의 자동 처리도 같은 한도 안에서 — 한도를 넘으면 대기로 두고 사유를 보여 준다). 멈추더라도 ERP 조회·기존 보관함 기능에는 영향이 없다.

표 구성(가칭) — 문서 종류 등록 doc_type · 파일별 상태 doc_item · 필드 값 doc_field · 검수 결과 doc_check · ERP 후보 연결 doc_erp_link. 전부 직접 접근을 막고 서버 함수로만 다루며, 부서 범위는 DB 가 계산한다.

부서가 합류할 때 준비할 것

  • [ ] 담당자 2명 이상 등록(확정할 사람이 없으면 시작하지 않는다)
  • [ ] 문서 종류와 필드 정의(무엇을 뽑을지 — 최소한으로)
  • [ ] 종류별 검수 수준과 ERP 대조 기준
  • [ ] 정답 추출본 10건 이상
  • [ ] 그 부서 자료를 AI 모델에 보내도 된다는 승인(구매는 D-88 로 승인됨)
  • [ ] 허용 폴더 등록 · 기본 적용 폴더 지정(무엇을 넣는 폴더인지 부서에 안내) · 민감 종류 제외 확인

8. 단계

단계 내용 선행
S0 기준 확정 이 문서 · 결정 요청 · 작업 규칙 고정 — (2026-10-08)
S1 읽기 기반 보관함에 판독 상태·못 읽은 사유 표시 · 엑셀 표 구조 판독 · 보관함 파일을 대화로 불러오기 · 저장 형식과 판독 형식 맞추기 새 결정 불필요 · 크레딧 충전(PDF)
S2 데이터화 틀 전용 구역·종류 등록·기본 적용 폴더 등록과 자동 접수·추출·L1 검수·검수 화면. 첫 종류는 구매 견적서 결정 ⓑ · 담당자 등록(D-136) · (ⓐⓓ 는 결정됨)
S3 검수 강화 검수 에이전트(L2) · ERP 대조(L3) · 골든셋 S2 · 결정 ⓒ
S4 에이전트 활용 문서 데이터 조회·대조 도구 · 출처 표기 지시문 S3
S5 부서 확대 합류 준비 목록으로 타 부서 종류 등록 결정 ⓔ

단계마다 별도 요청으로 승인받고 착수한다. 구매 로드맵의 포털 기록(P2)·견적 비교 초안(P3)은 S2~S4 위에 올린다(문서/14_구매업무시스템/03).

9. 관리자 결정이 필요한 것

# 결정 왜 필요한가 권고
ⓐ (D-144) 추출 필드 값을 포털 DB 에 둘지 D-95 는 「문서 내용 색인은 사내에만」이다. 필드 값이 여기에 해당하는지 범위를 정해야 한다 ✅ 결정(2026-10-08 · 권고안 채택) — 본문·색인은 사내 NAS, 등록 필드 값만 포털 DB 전용 구역. D-95 는 본문·색인에 대한 결정으로 유지된다
ⓑ (D-145) 정본 서열·표기 분리 규칙 ERP 와 문서 값이 다를 때의 기준 원칙 1~3 채택(ERP 우선 · 구역 분리 · 출처 표기)
ⓒ (D-146) 검수 방식 누가 확정하나, 검수 에이전트의 권한 4겹 · 종류별 수준 · 검수 에이전트는 판정만
ⓓ (D-147) 대상 범위 어디까지 읽을지 ✅ 결정(2026-10-08 · 권고안 수정) — 부서 NAS 폴더 안에 기본 적용 폴더를 두고 그 폴더는 항상 읽는다. 그 밖은 사용자가 지시하거나 폴더를 골라 진행한다. 기안서 스캔본(D-102)은 그대로 제외
ⓔ (D-148) 부서별 모델 전송 승인 절차 부서마다 자료 민감도가 다르다 합류 준비 목록의 승인 항목으로 부서별 1회 결정

관련 기존 결정: D-95(색인 사내) · D-102(스캔본 미열람) · D-115(버튼 누른 것만 저장) · D-88(구매 자료 모델 전송) · D-125(본 모델 — 크레딧 충전으로 해결 예정) · D-136(담당자 등록) · D-104(NAS 외부 백업).

10. 가정과 위험

관점 위험 대응
데이터 정합 추출 값이 ERP 값처럼 쓰인다 원칙 1~3 · 도구·구역 분리 · 권한 회귀
정확도 모델이 잘못 읽거나 지어낸다 원문 대조 · 독립 재추출 · 사람 확정 · 골든셋
보안·개인정보 민감 정보가 클라우드로 올라간다 허용 필드만 저장 · 민감 차단 유지 · 본문 사내 유지 · 부서별 전송 승인
운영 안정 NAS 지연·워커 중단·비용 급증 건별 처리 · 시간·건수·비용 한도 · 실패 사유 기록
사용성 절차가 번거로워 쓰지 않는다 보관함 한 화면에서 종류·상태·검수·확정 · 못 읽은 사유 표시
확장성 부서마다 따로 만든다 종류 등록제 · 공용 엔진·화면 · 합류 준비 목록
감사 누가 무엇을 확정했는지 모른다 판·확정자·정정 이력 보존 · 폐기 연동
자동 접수 기본 적용 폴더에 엉뚱한 파일·대량 파일이 들어온다 등록된 종류로 분류되지 않으면 추출하지 않고 「종류 미정」으로 둔다 · 건수·비용 한도 · 민감 이름·주민등록번호 꼴은 판독 전에 제외 · 결과는 초안까지

가정 — 기본 적용 폴더의 이름·위치는 부서 합류 때 정한다(구매는 보관함 AI저장/ 아래 한 폴더를 권고 — 화면에서 올리기 쉽고 워커가 쓰는 범위 안이다 · 확인 필요) · 구매팀이 견적서 등 자료를 그 폴더에 실제로 넣는다 · 크레딧 충전 뒤 본 모델이 PDF 를 판독한다 · 한글 PDF·hwpx 실문서 판독 품질은 S1 에서 실측한다.
