1. 한 줄 요약

사내규정 정본은 그룹웨어 규정 게시판이다. 사내 PC 수집기가 매일 아침 게시물·첨부를 NAS 00_전사공유/사내규정/ 에 개정 이력째 누적하고(정본 미러), 조문을 규칙으로 나눠 포털 DB public.reg_* 에 사본으로 적재한다. 전 직원은 조회 화면 /work/regulations 와 운영 챗봇·부서 에이전트의 규정 도구 2종으로 규정명·조문 번호·시행일을 근거로 답을 받는다.

2. 결정(2026-10-08 · 관리자)

5. 데이터 구조(정본 SQL 103)

표 역할 비고
reg_source 수집할 게시판 등록표(단일 출처) — board_key·list_path(상대경로만)·selectors(기본 프로필을 덮는 부분 JSON)·category·last_result 코드에 URL·선택자를 심지 않는다. 활성 0건이면 수집 안 함
reg_post · reg_post_history 게시물 원장(본문 Markdown·해시·첨부 서명·NAS 상대경로·판·status active/removed) · 이전 판 요약 삭제된 게시물은 removed 표시만(파일 보존)
reg_attachment 첨부 메타·판독 상태 readable/unreadable/blocked/skipped·사유·is_article_source blocked = 주민등록번호 꼴(NAS 에도 없음)
reg_document 규정 단위(게시물당 1건) — reg_key·제정/개정/시행일·개정차수·주관부서·parse_status(ok/partial/fallback)·text_source·is_current 현행 판은 DB 가 시행일·게시일로 계산(reg_recalc_current) — 제목만으로 합치지 않는다
reg_article 조문(장·절·조·제목·본문 ≤20,000자·개정 꼬리표) · pg_trgm GIN 검색은 ILIKE+유사도(한국어 조사 때문에 tsvector 대신)

RPC: 적재(service_role 전용) reg_source_list · reg_ingest_upsert(jsonb) · reg_mark_removed(절반 안전장치) · reg_recalc_current / 조회(definer · is_internal() · 사내 전원) reg_list · reg_get · reg_search(낱말 ≤6 AND · 최대 30 · 발췌 ±160자) · reg_status(전원: 기준시각·건수·판독 불가 수·마지막 실패 / 전체관리자: 게시판별·판독 불가 목록). 표는 RLS 전면차단·정책 0개 — RPC 만이 읽기 경로. 응답마다 source 상수가 실린다.

6. 수집기 운영

  • 게시판·선택자는 reg_source 가 정한다. 벤더 UI 가 바뀌면 selectors JSON 만 고친다(코드 무변경). 사전 점검은 python gw_board_collect.py --probe --headed(선택자 0건이 하나라도 있으면 rc 1 · 스크린샷 _gw_shots/).
  • 증분 판정: 게시물 번호 + 목록 수정일 + 본문 해시 + 첨부 서명. 목록에 수정일 열이 있으면 같은 게시물은 열지 않고, 없으면 최근 3페이지만 본문 해시를 비교한다. --nightly 는 변화 없는 게시물이 연속 20건이면 멈춘다(최소 2페이지). --full 완주 때만 삭제 판정(본 건수가 활성의 절반 미만이면 거부).
  • 원자 쓰기: .tmp-<pid>/ 에 전부 쓴 뒤 옛 판을 history/<판>_<시각>/ 로 옮기고 교체. 중단되면 다음 회차가 다시 가져온다. 제목이 바뀌어 폴더 이름이 달라지면 폴더를 옮긴다.
  • 첨부: 링크가 URL 로 환원되면 page.request(상태·Content-Type 검사 — HTML 응답은 로그인 만료로 판정), 아니면 다운로드 이벤트. 50MB 상한 · 실행 파일 형식 거부 · 파일명은 화면 표시 이름 우선.
  • 민감: 주민등록번호 꼴이 든 첨부·본문은 NAS 에 쓰지 않고 DB 에 글자를 넣지 않는다(blocked·사유). _SENSITIVE_NAME(급여·인사평가…)은 제목에 적용하지 않는다 — 「급여규정」은 정상 규정. 단 NAS 색인은 이름 규칙으로 그 파일을 빼므로 그 규정은 DB reg_search 로만 찾힌다(알려진 한계).
  • 세션: 자격증명 오류는 재시도하지 않는다(계정 잠금). 시크릿키 칸(다른 세션 사용 중)이면 그 회차를 건너뛴다(rc 0 · 표시 안 남김). 끝나면 로그아웃(프로필 login.logout_path).
  • DB 적재: 게시물 단위 meta.json 을 20건씩 reg_ingest_upsert 로. 실패해도 회차를 실패로 만들지 않고 db_synced:false 만 남겨 다음 회차에 재전송(멱등). 배치 이력 erp_etl_batch(job_name='gw_board').
  • 하루 1회: logs/gw_board_nightly.json 날짜 표시(실패 0건·완주 때만). 문서 루트(.claude/nas_docs.path)가 안 보이면 미룬다.
  • 개정 반영 지연: 화면 배너가 마지막 수집이 48시간을 넘거나 그 뒤 실패가 있으면 「그룹웨어 원본 확인」을 안내한다. 챗봇도 「수집 뒤 개정됐을 수 있음」을 덧붙인다.
  • 규정 폐지: 게시판에서 내리면 removed + is_current=false(파일 보존). 되살아나면 다시 활성.
