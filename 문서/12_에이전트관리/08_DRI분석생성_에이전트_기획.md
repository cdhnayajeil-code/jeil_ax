# 08 · DRI 분석·생성 에이전트 기획 — 사업운영팀

> 기준: 2026-10-07 · REQ-0112 · 관리자 지시로 착수(준비 단계) · 이 문서는 공개 문서 센터에 올라가므로 실제 고객사·도면 내용·금액은 적지 않는다.
> 「DRI」의 정확한 뜻과 자료 구성은 **사업운영팀 확인 대기**다(§8 열린 질문 ①). 아래 기획은 관리자가 답한 세 가지를 전제로 한다:
> **자료 = 이미지·도면 / 산출물 = AI 가 새로 그리는 이미지 / 사용자 = 사업운영팀 파일럿.**

## 1. 한 줄 요약

사업운영팀이 사내 NAS 의 **DRI 폴더**에 모아 둔 이미지·도면을 에이전트가 **읽고 분석**하고, 그 분석을 바탕으로 **새 이미지를 만들어** 다시 NAS 에 보관하는 부서 에이전트다.
지금은 **D1 까지** — 폴더·에이전트·화면이 열려 있고, NAS 폴더의 이미지·도면을 화면에서 골라 분석하고 보관할 수 있다(2026-10-07). **AI 이미지 생성(D2)** 은 아직 연결하지 않았다.

## 2. 지금 준비된 것 (D0 · 2026-10-07)

| 항목 | 상태 |
|---|---|
| NAS 폴더 | `부서/6110_사업운영팀/` 와 그 아래 `DRI/` 생성 · 허용 폴더 등록(`biz_ops` — 사업운영팀만 조회) |
| 에이전트 | `dri` 「DRI 분석·생성 에이전트」 · 상태 **pilot** · 사업운영팀 · 설정 v1(현재) · 도구 묶음 `nas · common` |
| 화면 | `/work/bizops-dri` 「DRI 분석 및 생성」 — 대화 · 파일 첨부 · 자료함 · 부서 NAS 보관함(관리 창 포함) · 준비 단계 안내 |
| 구성원 | 관리자 1명(reviewer). 사업운영팀 담당자는 `/admin/agents?agent=dri` 「구성원」에서 추가한다 |
| 한도 | 1인 1일 30회 · 월 예산 $50 · 기록 보존 180일(구매 에이전트와 같은 원칙 — 조정 가능) |

**지금 되는 일**

- 대화에 **붙인** 이미지·도면 분석(무엇이 보이는가 → 특이사항 → 제안) · 여러 장 비교 · 생성 지시문 초안 작성
- DRI 폴더의 **파일 목록**(이름·수정일·크기) 조회 · 본인 과거 대화 찾기
- 붙인 원본·만든 자료를 **🗄 NAS 저장**으로 사업운영팀 폴더(`AI저장/`)에 보관 · 폴더 만들기 · 내려받기 · 삭제

**아직 안 되는 일(에이전트도 그렇게 답하도록 설정해 두었다)**

- NAS 폴더 안의 이미지를 에이전트가 **직접 열어 보기** — 지금은 이름만 보인다
- **이미지 생성** — 생성 모델이 연결돼 있지 않다. 요청하면 「아직 못 한다」고 답하고 지시문 초안만 쓴다

## 3. 목표 흐름

```
① 자료 넣기        사업운영팀이 NAS 「사업운영팀 › DRI」 폴더에 이미지·도면을 넣는다(공유폴더 또는 화면의 보관함)
② 고르기           화면에서 DRI 폴더의 파일을 고른다(썸네일 목록)                          ← D1
③ 분석             에이전트가 고른 이미지를 읽고 「보이는 것 → 특이사항 → 제안」으로 정리     ← D1 (붙인 파일은 지금도 됨)
④ 생성 지시문       분석 결과로 생성 지시문 초안을 만들고, 사람이 고친다                      ← 지금 됨
⑤ 생성             사람이 [생성]을 누르면 AI 가 이미지를 만든다(한 번에 1~4장)               ← D2
⑥ 검토·보관         마음에 드는 것만 골라 NAS 「사업운영팀 › AI저장 › (폴더)」에 저장           ← 지금 됨(저장 버튼)
```

원칙은 구매 에이전트와 같다 — **사람이 누른 것만 저장하고, 사람이 누를 때만 생성한다.** 자동 저장·자동 생성은 넣지 않는다.

## 5. 관리자 결정이 필요한 것 (D2 전에)

| # | 결정 | 왜 필요한가 | 권고 |
|---|---|---|---|
| **G-1** | **이미지 생성 모델·공급사** | 지금 카탈로그에는 글 모델뿐이다. 생성 모델을 하나 정해 어댑터를 붙여야 한다 | 이미 계약·키가 있는 공급사의 이미지 모델부터(새 계약·새 키 없이 시작) — 그 계정에서 이미지 모델을 쓸 수 있는지는 확인이 필요하다 |
| **G-2** | **외부 전송 승인 범위** | 생성하려면 지시문이, 참조 생성(D3)을 하려면 **도면·이미지 원본**이 공급사로 나간다. 도면은 고객 기술자료일 수 있다 | D2 는 **지시문(글)만** 전송으로 시작 · 원본 전송(D3)은 「고객 도면 제외」 등 범위를 정해 따로 승인 |
| **G-3** | **예산·한도** | 이미지 생성은 글 대화보다 건당 비용이 크다(해상도·품질에 따라 달라진다) | 파일럿 월 상한을 따로 두고(대화 예산과 분리) 1인 1일 생성 장수를 제한 — 단가는 결정 시점의 공급사 공식표로 확인 |
| **G-4** | **생성물의 쓰임새** | 사내 보고용인지, 고객 제출·대외 자료에 쓰는지에 따라 검수·표기 기준이 달라진다 | 파일럿은 **사내용 초안**으로 한정 · 대외 사용은 사람이 검수한 뒤에만 · 파일 이름에 생성물임을 표기 |

## 6. 구조 (기존 것 재사용)

| 계층 | 쓰는 것 | 새로 만들 것 |
|---|---|---|
| 자료 | 사내 NAS `부서/6110_사업운영팀/DRI/`(원본) · `AI저장/`(보관) — 허용 폴더·권한은 DB 가 정한다 | — |
| 통로 | 역방향 큐(NAS 는 밖으로만 연결) · 중계 함수 · 워커 n1.7 의 내려받기 경로 | D1: 이미지 가져오기(크기 제한·형식 검사·축소본) |
| 대화 | 공용 게이트웨이 `jeil-chat-lab` · 에이전트 프로필+버전(ADR-109) · 파일 첨부(이미지 판독) | D1: 도구 `view_company_image` 1종 |
| 생성 | — | D2: 이미지 생성 어댑터 · 생성 대장 · 비용 집계 |
| 화면 | `/work/bizops-dri`(구매 에이전트 화면 기반) · 부서 NAS 보관함·관리 창 | D1: 썸네일 선택기 · D2: 생성 패널(지시문·결과·저장) |

**지켜야 할 것**

- 볼 수 있는 폴더는 DB(`nas_folder_scope`)가 계산한다 — 사업운영팀 폴더는 사업운영팀(과 관리자)만. 화면·도구에서 범위를 넓히지 않는다.
- 이미지 원본을 **클라우드 DB 에 쌓지 않는다.** 분석·생성에 쓰는 사본은 임시 버킷에 잠깐 머물고 지워진다(내려받기와 같은 방식).
- 주민등록번호·급여 등 민감 자료가 든 파일은 저장·색인에서 거부한다(기존 기준 그대로).
- 실거래 액션(메일 발송·대외 제출)은 하지 않는다 — 초안까지만.

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 고객 도면·기술자료가 외부 모델로 나감 | G-2 로 범위를 먼저 정한다. D1(분석)은 이미 승인된 대화 모델만 쓰고, D2 는 글 지시문만 보낸다. 원본 전송(D3)은 별도 승인 |
| 도면의 글자·치수를 모델이 잘못 읽음 | 답변 원칙에 「읽히지 않으면 판독 불가」 · 수치는 사람이 원본과 대조 · 평가 과제에 치수 판독 문항 포함 |
| 생성 이미지가 사실과 다른 설비·구조를 그림 | 생성물은 **초안**으로만 · 파일 이름·보관함에 생성물 표기 · 대외 사용 전 사람 검수(G-4) |
| 비용 급증 | 대화 예산과 분리한 생성 상한(G-3) · 1일 장수 제한 · 생성 대장으로 사용량 추적 |
| NAS 외부 백업 없음 | 보관 자료는 NAS 장애 시 복구되지 않는다(D-115 와 같은 위험) — 원본은 DRI 폴더에 그대로 두고 AI저장은 사본·산출물로만 쓴다 |
| 화면이 구매 에이전트 화면의 복사본 | 공통 부분을 고칠 때 두 화면을 함께 고쳐야 한다 — 에이전트가 3개째가 되기 전에 공통 화면으로 합친다(후속) |

## 8. 열린 질문

1. **「DRI」의 뜻과 자료 구성** — 어떤 이미지·도면이 얼마나, 어떤 폴더 구조로 있는가. 에이전트 역할 안내와 평가 과제를 여기에 맞춘다(사업운영팀 확인).
2. 만들려는 이미지의 **대표 사례 3~5개**(무엇을 넣고 무엇이 나와야 하는가) — 이것이 D2 의 완료 조건이 된다.
3. 도면 형식 — 이미지(PNG·JPG)·PDF 는 읽는다. **CAD 원본(dwg·dxf)** 은 읽지 못한다. 필요하면 변환 절차를 정해야 한다.
4. 파일럿 구성원(사업운영팀 담당자) 명단.
5. 포털의 사업운영팀 운영페이지 카드 등재 — 카드 소유 부서 코드를 확인한 뒤 올린다.
