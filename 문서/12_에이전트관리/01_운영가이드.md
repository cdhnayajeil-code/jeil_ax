# 01 · 운영가이드 — 역할별 사용법

> 대상: 구매팀(사용자·담당자) · 관리자. 화면 두 개만 쓴다 — **사용 화면** `/work/purchase-agent`, **관리 화면** `/admin/agents?agent=purchase`.

## 1. 역할 — 누가 무엇을 하나

| 역할 | 누구 | 할 수 있는 일 |
|---|---|---|
| 사용자(user) | (운영 전환 후) 권한 있는 직원 | 대화 · 카드 CSV/자료함 · 📄 보고서 · 👍👎 |
| **담당자(operator)** | 구매팀 2명 — **실작업** | + 설정 **초안** 저장 · 시험 대화 · 개선 대장 분류·반영 · 용어집 · 골든셋 · 회귀 실행 · 대화 기록 열람 |
| **관리자(reviewer)** | 관리자 3명(+포털 전체관리자) — **확인·점검** | + 초안을 **「현재」로 지정** · 개선 항목 **「검증 완료」** · 상태·한도·예산·보존 · 구성원 추가/제외 |

역할은 **서버가 판정**한다. 화면에 버튼이 보여도 권한이 없으면 서버가 거부한다.

## 2. 사용자 — 대화하기

1. `/work/purchase-agent` 접속(포털 로그인 상태여야 한다. 아니면 로그인 후 자동으로 돌아온다).
2. 질문하거나 아래 「자주 쓰는 질문」 칩을 누른다. 예) *이번 달 납기 지난 미입고 발주 거래처별로*
3. 답변 카드마다 **⬇ CSV**(엑셀로 열림) · **📁 자료함에 저장**.
4. **📄 보고서로 만들기** → AI 가 위 표로 해설(요약·특이사항·조치)을 쓰고 → **📄 이 해설로 보고서 저장** 을 누르면 인쇄용 보고서가 새 창에 열리고 자료함에 저장된다. **표 숫자는 조회 결과 그대로, 문장만 AI** 가 쓴다.
5. AI 가 HTML 을 코드로 쓰면 코드 위 **👁 바로 보기 · ↗ 새 탭 · ⬇ 내려받기 · 📁 자료함 저장**. (스크립트는 실행되지 않는 격리 창에서 보여 준다.)
6. 답이 아쉬우면 **👎** + 한 줄 의견 → 담당자의 개선 대장으로 바로 들어간다.
7. **파일 첨부** — 입력창 왼쪽 **📎**, 또는 파일을 대화 상자에 **끌어다 놓기**, 캡처 이미지는 **Ctrl+V**.
   - 엑셀·CSV·워드·PDF·이미지·텍스트, 한 번에 5개. 첨부하면 **📊 요약 · 🔎 ERP와 대조 · 📄 보고서 초안** 버튼이 나온다.
   - 예) 협력사가 보낸 발주 확인 엑셀을 올리고 「🔎 ERP와 대조」 → 발주번호별 입고·매입 진행과 다른 점을 알려 준다.
   - 질문을 비우고 보내면 자동으로 "자료 요약"을 요청한다. 이어지는 질문에서도 같은 첨부를 기억한다.
   - PDF 는 Claude 연결(키 등록) 후에 읽힌다. 옛 엑셀(.xls)·한글(.hwp)은 xlsx·PDF 로 저장해 올린다.
   - **개인정보(주민번호 등)가 든 파일은 올리지 않는다** — 주민번호 형식이 보이면 서버가 거부한다. 첨부 파일은 자동 저장되지 않는다(필요하면 아래 [🗄 NAS 저장]).

알아 둘 것
- 번호는 세 가지 — **PR**(구매요청, 품목 1줄) · **PU**(구매요청결재, 그룹웨어 결재 1건) · **PO**(발주서 1건). 어떤 번호로 물어도 연결된 나머지 번호와 진행상태를 알려 준다(자세히: 04 구매도메인).
- 발주 확정·결재·메일 발송 같은 **실거래는 하지 않는다**. 초안까지만.
- 질문과 답변은 품질 개선을 위해 기록된다(180일). 조회된 금액 목록 자체는 기록하지 않는다.
- 자료함은 본인만 보고 30일 뒤 자동 삭제 — 보관하려면 내려받는다.
- **부서 NAS 보관(REQ-0108)** — 보낸 메시지의 첨부 또는 자료함 항목의 **[🗄 NAS 저장]** 을 누르면 부서 NAS 폴더(`AI저장/<연도>/`)에 보관되고 부서원이 같이 쓴다(문서 검색에도 잡힘). 오른쪽 **「🗄 부서 NAS 보관함」** 에서 상태·저장한 사람을 보고 삭제한다(본인 것만, 담당자·관리자는 전부, 10분 안에 NAS 에서 삭제). 8MB 한도 · 급여·인사평가·주민등록 이름 파일·주민등록번호 꼴 글자 파일은 거부 · 같은 내용은 중복 저장 안 함 · 보존 3년. 에이전트에게 「저장해줘」라고 해도 직접 저장하지 못한다 — 버튼을 쓴다.
- 1인 하루 50회까지.

## 3. 담당자 — 에이전트를 고치는 루프

```
 대화 기록 ──▶ 개선 대장 inbox ──▶ 분류(🤖 AI로 묶기) ──▶ 반영
   ▲                                                   │
   │                                ┌──────────────────┼──────────────────┐
   │                            용어집 추가      답변 원칙·역할 안내 수정     새 도구·데이터 필요
   │                           (즉시 반영)        = 새 버전(초안) 저장      = 백로그 REQ 로
   │                                                   │
   └──── 관리자 「현재로 지정」 ◀── 골든셋 회귀 ◀── 시험 대화 ◀┘
```

### 3-1. 매일(10분)
1. 관리 화면 **개선 대장** 탭 — 붉은 숫자(inbox)를 확인.
2. inbox 가 여러 건이면 **🤖 AI로 묶어 분류** — 비슷한 원인끼리 묶어 분류·조치 제안을 달아 준다.
3. 항목을 **열기** → 오른쪽 「근거 대화」에서 실제 질문·답을 보고 분류·상태를 정한다.

| 분류 | 뜻 | 담당자가 할 일 |
|---|---|---|
| 용어집 | 부서 용어를 AI 가 몰랐다 | **용어집** 탭에 추가 → 즉시 반영(버전 불필요) → 항목 「반영됨」 |
| 프롬프트 문구 | 답 방식이 틀렸다(형식·단위·순서) | **설정·버전**에서 답변 원칙 한 줄 추가 → 새 버전 초안 |
| 새 조회 기능 필요 | 도구가 없어 답을 못 했다 | 조치 제안에 필요한 자료를 적고 「반영 예정」 + 관리자에게 백로그 REQ 요청 |
| ERP 데이터 미적재 | 중간DB 에 없는 자료 | 동일(ETL 작업 — 백로그 REQ) |
| 좋은 예시 | 잘한 답 | **골든셋**으로 승격 |
| 모델 한계 · 조치 불필요 | — | 「보류」 또는 관리자 판단 요청 |

### 3-2. 설정을 바꿀 때(새 버전)
1. **설정·버전** 탭 → 현재 버전 행 **편집 기준** → 아래 편집기에서 수정.
   - 답변 원칙: 한 줄에 하나. 예) `- 금액 합계는 반드시 도구의 합계 값을 그대로 쓴다`
   - 도구 묶음: 도메인 체크, 뺄 도구 체크 해제.
   - 모델·예비 모델·추론강도·최대 토큰(모델을 바꾸면 비용이 바뀐다 — 관리자와 상의).
2. 「변경 메모」에 무엇을 왜(예: `IMP-12 반영 — 미입고 정의`), 「반영한 개선 항목」에 번호.
3. **💾 새 버전(초안)으로 저장** → v(n+1) 초안. 사용자에게는 아직 적용되지 않는다.
4. **프롬프트 미리보기**로 실제로 들어가는 문장을 확인.
5. 오른쪽 **시험 대화**에서 버전을 고르고, 문제가 됐던 질문을 다시 해 본다(🔧 도구·토큰·비용 표시).
6. **골든셋** 탭 → 회귀 실행(그 버전) → 통과율 확인.
7. 관리자에게 「v(n+1) 지정 요청」.

### 3-3. 골든셋 만들기
- 대표 질문 10~20개부터. **대화 기록**에서 좋은 답을 골라 「골든셋으로」 누르면 질문·사용 도구가 채워진다.
- 「답 요건」은 채점 기준 — 짧고 확인 가능하게. 예) `발주번호별 총액 기준 · 상위 5건 · 원 단위 콤마`
- 회귀 1회 비용 ≈ 문항 수 × 질문 1건(문항 20개면 약 $1 이하).
- **표준 문항은 「📐 관리 포인트·템플릿」 탭에서 한 번에 등록**한다(빠진 문항 등록) — 부서 세트의 골든셋 표준(구매 18문항)이 기준이고, 대화 기록에서 승격한 문항은 그 위에 더한다.

### 3-4. 템플릿과 대조하기(「📐 관리 포인트·템플릿」 탭)
- 위쪽 **관리 포인트** 표는 이 에이전트의 지금 값을 기준값과 비교해 **정상·주의·경고**로 보여 준다. 경고가 있으면 「조치」 열대로 한다(기준·조치·주기의 정본은 [06](06_에이전트_템플릿_관리포인트.md) §3).
- 아래 **템플릿 반영 현황**은 공통 기준 세트 + 부서 세트를 실제 설정과 대조한다.
  - 용어집·골든셋: 「빠진 … 등록」 버튼으로 **바로 등록**(용어는 즉시 프롬프트 반영, 골든셋은 다음 회귀에 포함).
  - 답변 원칙·칩: 바로 저장되지 않는다 — 버튼이 **편집기/운영 설정 칸에 채워 주면** 담당자가 「새 버전(초안)」, 관리자가 「운영 설정 저장」으로 확정한다.
- **표준 테스트 시나리오**의 「시험 대화로」를 누르면 그 질문이 시험 대화 칸에 들어간다. 실측 결과는 [05](05_품질테스트_대화검증.md) 형식으로 남긴다.

## 4. 관리자 — 확인·점검·승인

| 할 일 | 어디서 | 기준 |
|---|---|---|
| 새 버전 **현재로 지정** | 설정·버전 → 행의 「현재로 지정」 | 회귀를 돌렸고 통과율이 이전 버전 이상인가(안 돌린 버전은 한 번 더 누르라고 경고) · 변경 메모가 있는가 |
| 개선 항목 **검증 완료** | 개선 대장 → 상태 「검증 완료」 | 반영 후 실제로 좋아졌는가(대화 기록·👍 비율) |
| **관리 포인트 점검** | 📐 관리 포인트·템플릿 → 위쪽 표 | 경고(빨강)가 하나라도 있으면 「조치」 열대로. 특히 **예비 모델 전환 비율**이 높으면 키·벤더 상태(`/admin/api-setup`)부터 — 09-30 실측처럼 100% 예비 전환은 키 종류 문제였다 |
| 비용 점검 | 개요 → 이번 달 비용/예산 | 80% 넘으면 원인(사용량·모델) 확인. 100% 넘으면 자동으로 예비 모델 |
| 상태·한도 | 개요 → 운영 설정 | 파일럿 → 운영(live) 전환은 파일럿 2주 결과를 보고 |
| 구성원 | 구성원 탭 | 담당자=operator, 관리자=reviewer |

되돌리기: 문제가 생기면 **이전 버전 행의 「현재로 지정」** 을 누르면 즉시 돌아간다(버전은 지워지지 않는다).

## 5. 처음 설정(한 번)
1. **Anthropic API 키 등록**(관리자): Anthropic Console(회사 조직)에서 키 발급 → Supabase 대시보드 › Edge Functions › Secrets 에 이름 `ANTHROPIC_API_KEY` 로 등록. 재배포 불필요 — 다음 질문부터 Sonnet 5 로 답한다(관리 화면 오른쪽 위 「연결된 AI」에 anthropic 이 보이면 성공).
   - ⚠ 키는 **운영 워크스페이스 안에서 발급한 일반 API 키**(`sk-ant-api…`)여야 한다. 워크스페이스에 묶이지 않은 조직 단위 키나 Admin 키(`sk-ant-admin…`)를 넣으면 「연결된 AI」에는 보여도 **매 호출이 400 으로 거부**돼 예비 모델로만 답한다(09-30 실측). 확인은 관리 화면 시험 대화의 추적 줄 `fallback 400 …` 본문, 또는 개요 KPI 「예비 모델 전환」 비율.
2. **구성원 등록**(관리자): 구성원 탭에서 구매팀 2명 operator · 관리자 reviewer 추가.
3. **골든셋 기준선**(담당자): 10~20문항 → v1 회귀 → 기준 통과율 기록.

## 6. 비용 감각
- Sonnet 5: 입력 $2 / 출력 $10 (100만 토큰당). 질문 1건 ≈ $0.02~0.04(캐싱 시 절반 가까이).
- 예비 gpt-4.1-mini: 질문 1건 ≈ $0.004 (현재 11턴 누적 약 $0.05).
- 월 $150 기준 Sonnet 5 로 대략 4,000~7,000 질문.
