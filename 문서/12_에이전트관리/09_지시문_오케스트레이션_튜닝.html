09 · 지시문 개편 · 오케스트레이션 튜닝 (REQ-0114 · 2026-10-07)

요약 — 사내 챗봇의 지시문(시스템 프롬프트)이 세 곳(운영 DB 평문 · 실험실/에이전트 코드 상수 · 에이전트 버전의 답변 원칙)에 따로 살면서 서로 어긋나 있었다. 이번에 한 조립 규칙(core/prompt.ts)으로 통일하고, 평문 한 덩어리를 절(■)+번호 규칙 구조로 바꿨다. 엔진의 라운드 마무리 규칙 3가지도 함께 고쳤다. 적용은 세 경로(게이트웨이 배포 · 구매 에이전트 v5 초안 → 회귀 → 지정 · 운영 DB 지시문 SQL 94)로 나뉜다. 2026-10-07 저녁 관리자 승인으로 A(게이트웨이 v26)·C(SQL 94 · D-137)를 적용했고, B(v5 회귀 → 지정 · D-138)만 남았다(§4·§5). 작성: Claude(AX 설계 관점) · 검토: 최동혁 · 정본 코드 supabase/functions/jeil-chat-lab/core/prompt.ts

3. 오케스트레이션 변경(엔진 core/engine.ts · 어댑터)

# 전 후 왜
① 마지막 라운드 tools: null 로 호출 도구 정의는 그대로 + tool_choice: none + 사용자 메시지 「[안내] 도구 호출 한도 … 지금까지의 결과로 답하세요」 Claude 400 예방 · 모델이 「조회하겠습니다」로 끝나지 않게
② 같은 조회 반복 조용히 break(빈 답) 「[안내] 같은 조회를 반복했습니다 …」 넣고 도구 없이 한 라운드 더(마지막 라운드였으면 +1회) 사용자가 빈 답을 보지 않게
③ 결과 잘림 12,000자에서 무표시 절단 …[결과 잘림: 전체 N자 중 앞 12,000자만 전달됨 — 건수·합계는 요약 값만 쓰고 목록은 일부만 보인다고 밝힐 것] F-4 유형(잘린 표를 총량처럼) 재발 방지
④ 라운드 수(구매 v5) 4 5 「찾기 → 상세 → 확인」 3단 체인 + 마무리 라운드가 들어갈 자리 · 템플릿 기본값도 5
⑤ 실험실 날짜 없음(모델 지식의 연도) 오늘 날짜 주입(에이전트와 같게) 「이번 달」 해석을 서버 날짜 기준으로

운영 jeil-chat 코드(OpenAI 전용 · MAX_ROUNDS 4)는 이번에 손대지 않았다 — OpenAI 는 tools 를 빼도 400 이 나지 않는다. 날짜 주입·tool_choice none 사본 적용은 후속(§7). 어댑터 인터페이스에는 toolChoice?: "auto"|"none" 한 칸이 늘었다(llm/types.ts). 두 벤더 모두 구현.
