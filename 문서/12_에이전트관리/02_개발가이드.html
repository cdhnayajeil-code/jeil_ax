2. 새 도구(모듈) 추가

  1. supabase/functions/jeil-chat-lab/modules/<domain>/<tool_id>.ts 작성 — manifest + run(ctx). - manifest.id 는 영구 불변(모델이 부르는 이름). domain 이 에이전트 도구 묶음 단위. - 권한: perm_module + perm_mode:"gate"(ERP 모듈 권한) 또는 partial(모듈 안에서 판정 — 예: 기안서는 페이지 권한). - sensitivity: "personal" 이면 그 턴의 답변은 저장되지 않는다. - 결과에 __view(뷰 5종: series·ranking·record·list·notice — ADR-008)를 붙이면 카드로 나간다. 새 뷰 타입은 만들지 않는다. - 사용자·모델 입력을 PostgREST 필터에 넣을 때는 modules/purchase/_agent_util.ts 의 clean() 을 거친다(or() 필터 주입 방지). - 읽기 전용. ERP 운영 DB 직접 접근 금지 — 중간DB 뷰만(CLAUDE.md §4). - 목록형 도구 계약(09-30 실측 P1 3건이 전부 이 계약 부재에서 나왔다): ① limit 으로 잘랐으면 전체 건수 또는 잘림 표시를 결과에 넣는다(search_pur_list 방식) ② .order() 에 2차 정렬키(번호·seq)를 둔다 — 단일 날짜 정렬은 같은 조회가 다른 행을 돌려준다 ③ 사용자가 좁힐 만한 조건(거래처·기간·상태)은 인자로 받고, 못 받는 조건은 안내 로 돌려준다 ④ 여러 라인이 있는 문서(발주)는 합계·라인 수를 함께 준다 ⑤ 화면 제목에 내부 상태값(unordered)을 그대로 쓰지 않는다.
  2. modules/extra.ts 에 import 한 줄 + 배열에 추가.
  3. 에이전트 도구 묶음에 그 도메인이 켜져 있으면 자동으로 쓰인다(끄려면 관리 화면에서 체크 해제 → 새 버전).
  4. 검증 → 배포(§4).

3. 새 에이전트(부서) 추가

  1. 정본 SQL 새 번호로 행 추가: ai_agent(agent_key·이름·부서·status='pilot'·suggestions) + ai_agent_version v1(state='current', 모델·역할 안내·답변 원칙·modules.domains) + ai_agent_member. 역할 안내·답변 원칙은 템플릿 06 §2-2 공통 원칙 + 부서 추가 원칙을 그대로 붙인다. 1-1. app/agent-templates.json 의 domains 에 부서 키를 추가한다(_candidates 골격 복사 → 칩·용어·골든셋·시나리오). 콘솔 「📐 관리 포인트·템플릿」 탭이 이 키로 부서 세트를 찾는다(없으면 공통만 대조).
  2. 필요한 도구가 없으면 §2 로 만든다.
  3. 사용 화면: pages/구매_AI에이전트_2026.html 을 복사해 const AGENT = "<key>" 와 제목만 바꾼다(로직은 공용 모듈). _routes.py 에 /work/<dept>-agent 한 줄 → python _build_routes.py --write.
  4. 관리 화면은 공용 — /admin/agents?agent=<key>. 4-1. 사용 화면의 「🧪 검증·테스트」 탭(REQ-0106)은 세 곳을 읽는다 — 자동 회귀는 서버 op golden_runs, 실측 회차는 app/agent-quality.json 의 agents.<key>, 표준 시나리오는 app/agent-templates.json(부서 + 공통). 새 부서는 두 JSON 에 키만 더하면 탭이 채워진다(없으면 「기록 없음」). 4-2. 포털 카드 등재는 정본 SQL 로(선례 88 — erp_module 은 null, 부서 전용). 에이전트 화면은 접근 게이트를 쓰지 않고 서버가 구성원을 판정하므로, 카드 공개 범위와 사용 권한은 별개다.
  5. 이 폴더 00_현재상태 · 03_진행상태_변경이력 갱신.

4. 검증과 배포

  • 타입 검사: 이 PC 에 Deno 가 없어 TypeScript strict 로 대신한다(스크래치에 typescript·@anthropic-ai/sdk·@supabase/supabase-js 설치, Deno 전역과 npm:/jsr: 모듈은 shim 선언). 자동생성 모듈 2건(get_erp_pur_req·get_erp_receipt_pending 암시적 any)은 알려진 경고. 빠른 길: npx -y -p typescript@5.6 tsc --noEmit --target es2022 --module esnext --moduleResolution bundler --allowImportingTsExtensions --skipLibCheck --lib es2022,dom <파일들> — TS2307(npm:/jsr:)·Deno 전역 외 오류가 없으면 된다(가져오기 누락이 운영 도구 오류로 터진 v20 사례).
  • 지시문 회귀: node _test_prompt_assembly.mjs — 안내 문장의 도구 이름 전수 존재 · 조립 순서 · needs 필터 · 템플릿 key⊂text · 엔진/어댑터 마무리 규칙 · 정본 SQL 94 동기화(REQ-0114). core/prompt.ts·agent.ts·engine.ts·llm/*·app/agent-templates.json 을 고치면 반드시 돌린다. OpenAI 400 적응 사본은 node _test_oa_shape.mjs.
  • 화면 스크립트: <script type="module"> 을 뽑아 node --check.
  • 렌더 모듈: jsdom 으로 renderMd·attachCodeActions·stripActive 동작 확인.
  • 배포: python supabase/_deploy_function.py jeil-chat-lab --multi(폴더 안 .ts 전부 업로드 · .env 는 Python 으로만 읽는다 — CLAUDE.md §1.8).
  • 화면: main 푸시 → Vercel 자동 배포(약 1분).

⚠ 편집 주의: Bash heredoc 안의 Python 문자열에 백슬래시-n 을 쓰면 실제 줄바꿈으로 들어가 TS/JS 문자열이 깨진 사례가 있다(2026-09-28, 2회). 코드 편집은 Edit 도구를 쓰거나 chr(92) 로 백슬래시를 만든다.

4-1. 첨부 파일 흐름(REQ-0089)

  • 화면: filein.readAttachment(file) → part(text·image·pdf) → 사용자 메시지에 attachments:[part] 로 붙여 보낸다. 대화가 이어지면 이전 첨부도 그 메시지와 함께 다시 보낸다.
  • 서버: core/agent_api.ts checkAttachments() — 형식·크기·개수·주민번호 형식 검사, 최신 질문부터 예산(글자 15만·base64 14MB)을 채우고 넘치는 옛 첨부는 안내 문구로 바꾼다. 기록은 agent_turn.attachments 에 이름·종류·크기만.
  • 어댑터: ChatMsg 사용자 메시지의 parts → Anthropic 은 document(PDF)·image·text 블록, OpenAI 는 image_url·text(PDF 는 안내 문구).

4-2. 기안서 스캔 목록 자동 갱신(REQ-0092)

  • 10_ERP_DB연계/etl/proposal_scan.py — 탐색기 창(Shell COM) 경유로 파일 이름·크기·수정일만 읽는다(os.listdir·Get-ChildItem·Shell.Namespace 직접 접근은 문서중앙화가 거부). 복사·열람 동사는 쓰지 않는다.
  • 러너: 작업 종류 proposal_scan(기본 꺼짐 · 30분 간격 · 능력 proposal_scan = Windows + C:\Cyberdigm + .env PROPOSAL_SCAN_DIR), 서브커맨드 jeil_runner scan, 빌드 hidden 등록. 회귀 test_proposal_scan.py 12건.
  • 이 PC 는 러너 전체를 띄우지 않고 예약작업 JEIL_AX_ProposalScan 하나만 둔다(etl/deploy/register_scan_task.ps1) — 러너 기본 작업(결의전표 전송·요청 처리)이 ERP 서버 러너와 중복되지 않게.
  • ⚠ 경로에 \11·\04 같은 부분이 있어 Bash heredoc 속 Python 문자열로 쓰면 8진 이스케이프로 깨진다(09-29 실제 발생). .env 편집은 chr(92) 로.

5. 보안 원칙(바꾸지 말 것)

  • 권한은 서버에서: 역할(roleOf) · 도구 주입(visibleTo) · 실행 직전 재판정(gateDeny) 3중.
  • 에이전트 테이블은 RLS 켜고 정책 없음 — 브라우저에서 직접 읽지 않는다. 새 테이블도 같게.
  • AI 가 쓴 HTML 은 sandbox iframe(srcdoc)에서만 그린다 — 같은 출처에서 그리면 그 스크립트가 localStorage 의 로그인 토큰을 읽는다. 저장·내려받기 본은 stripActive 로 스크립트·on*·javascript: 를 걷어내고, 서버(artifact_save)도 같은 기준으로 거부한다.
  • 턴 기록에 조회 결과 행을 넣지 않는다(도구 요약은 건수·결과 유형만). 보고서 해설 요청에 붙는 표는 기록 전에 잘라낸다.
  • 시험 대화(버전 지정)는 담당자 이상만. 1인 1일 한도·월 예산은 서버가 강제한다.
  • 첨부 파일은 자동 저장하지 않는다(사용자가 [🗄 NAS 저장]을 누른 것만 NAS 부서 폴더에 — REQ-0108, Storage·DB 에는 남기지 않는다. 임시 버킷 nas-outbox 는 NAS 가져간 뒤 삭제). 주민번호 형식이 보이면 거부. 새 형식을 추가할 때도 이 원칙을 지킨다.
  • Anthropic 키는 Supabase 시크릿 ANTHROPIC_API_KEY 로만 둔다. 코드·문서·대화에 값을 적지 않는다.

6. 알려진 한계·후속

  • LLM 오류 본문 보존(v13) — engine.ts 가 예비 전환·오류를 console.error 로 남기고 ConverseResult.fallbackNote 로 돌려주며, agent_api.ts 가 agent_turn.tools 에 {tool:"_llm", outcome:"fallback"|"error", status, detail} 항목을 덧붙인다(스키마 변경 없음 · 판정 flags 계산 뒤에 넣어 tool_error 로 오판되지 않는다). 대화 기록 화면의 도구 열에 _llm 로 보인다.
  • Anthropic 키 — 워크스페이스 키(09-30 교체)가 기본. 조직 단위 키를 써야 하면 시크릿 ANTHROPIC_WORKSPACE_ID 를 넣으면 llm/anthropic.ts 가 anthropic-workspace-id 헤더를 붙인다(없으면 안 붙임).
  • 히스토리 창(v13) — 서버가 max_messages 로 자른 뒤 첫 user 메시지부터 시작하도록 보정(Anthropic 은 user 로 시작해야 함). 남은 잠재 400: 마지막 라운드에 tools:null 로 보낼 때 convo 에 tool_use 가 남아 있는 경우 · 실험실 경로의 마지막 메시지 user 검사 없음(프리필).
  • 정본 전환 모듈(v13) — _port_modules.py HAND_TUNED 4종은 재이식 때 파일을 덮어쓰지 않고 등록 목록에만 넣는다. 운영 jeil-chat 원본의 같은 도구가 바뀌면 손으로 맞춘다.
  • 템플릿은 파일(app/agent-templates.json)이 정본이고 DB 계층이 없다 — 여러 부서로 늘어 파일 한 곳으로 부족해지면 ai_agent_template 표 + agent_create/clone op(REQ-0094 2단계 4항).
  • 실험실 화면(app/chat-lab.html)은 렌더 코드 사본을 아직 갖고 있다 → chatview.js 로 이전 예정.
  • 월 예산 80% 알림(Teams)·엑셀/워드 원본 생성·포털 카드 등재는 미구현.
  • 게이트웨이 이름이 아직 jeil-chat-lab — 파일럿 검증 후 운영 이름(jeil-agent)으로 승격하고 운영 jeil-chat 을 흡수(별건).
