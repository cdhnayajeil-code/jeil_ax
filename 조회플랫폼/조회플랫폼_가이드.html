표준 조회 플랫폼 가이드

부서 운영페이지 상단의 조회조건·기준 표시·새로고침을 화면마다 새로 만들지 않는다. app/lib/querybar.js 한 곳에서 만들고, 화면은 그 결과를 받아 그리기만 한다. 이 문서가 단일 출처다. 데모는 조회플랫폼/index.html, 규칙 정본은 CLAUDE.md §16.

1. 왜 만들었나

같은 개념을 화면마다 다른 모양·다른 코드로 만들고 있었다.

화면 이전 상태
영업·구매·인사·자금일보·자재 기준일이 정적 텍스트. 기간을 바꿀 방법이 없다
외주발주 진행현황 자체 .query 블록(검색·발주일 from~to·체크박스) + 자체 ↻ 새로고침(실은 재조회가 아니라 재필터)
자금현황(실연동) 자체 <select id="fy">/<select id="fm"> 를 대시보드 HTML 안에서 매번 다시 그림

ERP 실연계로 넘어가면 화면 수만큼 조회 계약을 다시 짜야 한다. 그래서 상단을 컴포넌트 하나로 못 박았다.

2. 조회 플랫폼이 보장하는 것

모든 대시보드·현황 화면 상단에 같은 자리, 같은 모양으로 아래가 있다.

[기간] [2026년 ▾] [연간(전체) ▾]  [당월][전월][연간]   …   기준일 2026-06-12 · 확정 전표 기준  [🔄 새로고침]  최종 조회 15:41:02 (방금 전)
  1. 기간(연·월) — 월을 고르면 화면이 그 월로 좁혀진다. 연간(전체) 이 기본.
  2. 빠른 기간 칩 — 당월·전월·연간. "당월"은 기준일(asOf)의 월이지 오늘이 아니다(마감 데이터 기준).
  3. 기준 표시 — 기준일 + 전표 기준 + 데이터 성격 배지(목업 데이터 / ERP 실데이터).
  4. 새로고침 — 조회 중에는 버튼이 돌고 입력이 잠긴다. 끝나면 최종 조회 시각이 갱신된다.
  5. 상태 유지 — 주소(?y=2026&m=5)와 localStorage 에 남는다. 링크를 그대로 공유할 수 있고, 다시 열면 마지막 기간이 복원된다.
  6. 추가 조회조건 슬롯(extras) — 화면별 검색어·날짜·체크박스를 같은 줄에 붙인다.

3. 역할 분리 (그리드 표준 §13.3 과 동일)

querybar.js 는 UI·기간 상태만 담당한다. 데이터 조회/집계는 onQuery 콜백에서 호출측이 한다. 컴포넌트 안에 DB·Edge Function 호출을 심지 않는다. 데이터 접근은 app/lib/api.js 로 모은다.

[조회 플랫폼]  기간·조건을 소유 → onQuery(q, ctx)  ──▶  [화면]  api.js 로 조회 → 그리기
      ▲                                                      │
      └──────────── setYears/setMonths/setMeta ◀─────────────┘   (서버가 알려준 기간을 되먹임)

4. 붙이는 법 (4단계)

1) <head> 에 CSS

<link rel="stylesheet" href="/app/lib/querybar.css">

경로는 루트 절대경로다. 클린 URL(/work/…)은 파일보다 경로 깊이가 달라 상대경로가 깨진다(CLAUDE.md §15.4).

2) 제목 옆 기간 배지 + 조회바 자리

<div class="head">
  <div>
    <h1>📈 수주현황 대시보드<span class="qbar-period" data-qbar-period>2026년 연간</span></h1>
    <div class="sub">영업팀 운영 페이지 · <span class="badge b">부서 전용</span></div>
  </div>
  <div class="right">데이터 원천: 매출/수금 확정(S_BILL)</div>
</div>

<div id="qbar"></div>

.head .right 에 기준일을 다시 쓰지 않는다. 기준일·전표기준은 조회바가 소유한다.

3) 월에 반응할 요소에 data-m 표시

<div class="chart" id="mChart">
  <div class="cbar" data-m="1"><span class="val">2.2</span>…</div>
  <div class="cbar" data-m="2"><span class="val">24.1</span>…</div>
</div>

<table data-m-off="hide">
  <tr data-m="1"><td>1월</td>…</tr>
  <tr data-m="2"><td>2월</td>…</tr>
  <tr data-m-empty class="qbar-hide"><td colspan="5">선택한 월의 데이터가 없습니다.</td></tr>
</table>
표시 뜻
data-m="5" 5월 요소. data-m="1,2" 처럼 여러 월도 가능
data-m-off="dim" (기본) 선택 월이 아니면 흐리게. 데이터가 사라지지 않아 맥락이 유지된다
data-m-off="hide" 선택 월이 아니면 숨김. 월별 표처럼 행이 곧 월일 때
data-m-empty hide 그룹에서 남는 행이 없을 때만 보이는 안내 행(빈 표 방지)
data-qbar-period 기간 라벨(2026년 5월)이 자동으로 채워지는 자리
data-qbar-asof 기준일이 자동으로 채워지는 자리

4) 조회바 생성

<script type="module">
  import { createQueryBar, readMonthSeries, numOf } from "/app/lib/querybar.js";

  const SERIES = readMonthSeries("#mChart");            // 화면에 이미 있는 월별 수치를 읽는다
  const TOTAL  = Object.values(SERIES).reduce((a,v)=>a+numOf(v), 0);

  createQueryBar("#qbar", {
    years:[2026], year:2026,
    months:[1,2,3,4,5,6], monthLabels:{ 6:"6월(진행)" },
    asOf:"2026-06-12",
    basis:"매출/수금 확정(S_BILL)",
    mode:"mock",
    onQuery: (q, ctx) => {
      // q.year · q.month(null=연간) · q.ym · q.from · q.to · q.label · q.extras
      // ctx.reason: "init" | "change" | "quick" | "refresh" | "auto"
    },
  });
</script>

5. 옵션

옵션 기본 설명
years [올해] 연도 목록. 서버가 정하면 setYears() 로 나중에 채운다
year 올해 초기 연도
months 1~12 조회 가능한 월. false 면 기간 축 자체를 감춘다(검색형 화면)
month null 초기 월. null = 연간(전체)
monthLabels {} {6:"6월(진행)"} 처럼 월 표기 재정의
allowAll true "연간(전체)" 옵션 노출
quick true 당월·전월·연간 칩
asOf null 기준일. "당월" 판정 기준이기도 하다
basis null 전표·집계 기준 문구
mode null "mock" | "live" → 데이터 성격 배지
modeLabel 자동 배지 문구 직접 지정
extras [] 추가 조회조건. {id,label,type,options,value,placeholder,width,title,debounce} · type: text|select|date|checkbox
reset false "조건 초기화" 링크
refreshLabel "새로고침" 버튼 문구
autoRefreshSec 0 자동 재조회 주기(초). 0 = 사용 안 함. 탭이 숨겨져 있으면 건너뛴다
urlSync true 주소 ?y=&m=&<extra id>= 동기화
persist window.PAGE_KEY localStorage 키. null 이면 저장 안 함
scope document data-m 자동 강조 대상 루트
autoApply true data-m·data-qbar-* 자동 반영
runOnInit true 생성 직후 1회 조회
onQuery null (q, ctx) => void \| Promise

인스턴스 API

호출 용도
bar.value() 현재 조회 조건
bar.refresh() 새로고침과 동일(reason "refresh")
bar.setYears([2026,2025]) 서버가 알려준 연도로 목록 교체. 이때 URL 의 연도를 뒤늦게 받아준다
bar.setMonths([1,2,3], {3:"3월(진행)"}) 실제 데이터가 있는 월로 교체
bar.setMeta({asOf, basis}) 기준 표시 갱신
bar.setPeriod(y, m, silent) 기간을 코드로 지정. silent=true 면 조회하지 않는다
bar.applyPeriod() 화면을 다시 그린 뒤 강조를 재적용
bar.setLoading(bool) / setError(msg) 로딩·오류 표시 직접 제어
bar.destroy() 타이머 정리 + 비우기

보조 함수

함수 용도
readMonthSeries(sel, valueSel=".val") data-m 요소에서 화면에 이미 그려진 수치를 {월:"문자열"} 로 읽는다. 목업 화면이 숫자를 스크립트에 중복 기입하지 않게 한다
numOf(s) "1,284"·"+430"·"−118" 에서 숫자를 뽑는다(유니코드 마이너스 정규화 포함)

6. 실연동 화면에서 주의할 것

  1. 연 단위로 받아 월은 화면에서 계산하는 RPC(erp_finance_overview)라면, 연도가 바뀔 때만 재조회한다. ctx.reason 과 마지막 조회 연도를 비교해 불필요한 왕복을 막는다.
  2. 재렌더 뒤에는 bar.applyPeriod() 를 부른다. innerHTML 로 새로 그린 DOM 에는 강조가 없다.
  3. 조회바를 재렌더 영역 밖에 둔다. $("app").innerHTML = … 안에 있으면 매번 날아간다.
  4. 조회 가능한 연·월은 데이터에서 뽑아 setYears/setMonths 로 채운다. 없는 기간을 고르게 두지 않는다.
  5. 권한 게이트에 걸리면 조회바도 함께 감춘다(hidden). 못 보는 화면에 조회 UI 만 남기지 않는다.

7. 규약

  1. 전역 셀렉터를 만들지 않는다. CSS 는 .qbar__ 스코프만 쓴다(같은 화면의 다른 표·폼 오염 금지). 호스트 :root 팔레트(navy/accent/line/muted/green/red/soft…)를 재사용하되, 팔레트가 없는 화면에서도 깨지지 않도록 var(--x, 기본값) 형태로 쓴다.
  2. 외부 라이브러리·CDN 금지. 자기완결 바닐라 ESM(의존성 0).
  3. 비즈니스 로직을 컴포넌트에 심지 않는다. DB·Edge Function 호출은 onQuery 안, api.js 경유.
  4. 기준일을 두 곳에 쓰지 않는다. asOf 가 유일한 출처이고, 화면은 data-qbar-asof 로 받아 쓴다.
  5. 없는 데이터를 만들어내지 않는다. 월 선택으로 KPI 를 바꿀 때는 화면에 이미 있는 값(readMonthSeries)이나 서버 응답만 쓴다. 마감 전이면 — 로 두고 사유를 적는다.
  6. 새 조회 화면은 이 표준으로 통일한다. 예외를 두려면 사유를 CLAUDE.md §16 에 적는다.
