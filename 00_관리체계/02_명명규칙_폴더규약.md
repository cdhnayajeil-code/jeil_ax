# 02. 명명규칙 · 폴더규약

> **기준일: 2026-06-30** · 관리: 최동혁
> 파일·폴더·문서의 명명과 배치 규칙. 신규 산출물은 이 규칙을 따른다(`CLAUDE.md §7` 계승·구체화).

## 1. 파일 명명 규칙

### 1.1 기본형 — `NN_주제_설명.확장자`
- `NN` = 2자리 정렬 번호(`00`은 폴더 인덱스/종합문서 예약).
- 단어 구분은 언더스코어(`_`), 한국어 우선.
- 예: `01_AI_관리시스템_도입_기획서.html`, `00_니즈조사_홈.html`.

### 1.2 날짜 표기
- `YYYY-MM-DD`(문서 본문·이력) 또는 `YYYYMMDD`(파일명). 예: `2026-06-30`, `20260514`.

### 1.3 정당한 예외 (리네임 대상 아님)
| 패턴 | 예 | 사유 |
|---|---|---|
| 진입점 | `index.html` | 웹 표준 진입점 |
| 도메인 | `CNAME` | GitHub Pages 규약 |
| 브랜드 도구 | `JEIL_AX_비용계산기.html` 등 | 제품 브랜딩(현재 `09_비용_호스팅/`로 묶음) |
| 부서 운영페이지 | `영업_수주현황_2026.html` | **§2 부서 페이지 규칙** |
| 프로젝트 산출물 | `2025-095-SUL-EC_원가현황_20260514.html` | 프로젝트코드 우선 식별 |
| 통합 산출물 | `JEIL_AX_포털데모_통합본.html` | 빌드 산출물(`_build_bundle.py`) |

## 2. 부서 운영페이지 규칙 (`pages/`)

- 형식: **`[부서]_[기능]_[연도].html`** (예: `구매_거래처별매입집계_2026.html`).
- 부서명은 `01_기준정보_레지스트리 §1` 표준 표기를 따른다(인사팀 등).
- `pages/` 파일은 `04_챗봇_포털_데모UI.html`·통합본·`이관/00_현황스냅샷`이 **경로를 직접 참조**한다 → **리네임 시 참조처 동반 갱신 + 통합본 재빌드 필수**(함부로 바꾸지 않는다).

## 2.5 공개 URL 라우트 (파일명 ≠ 주소)

**사용자에게 보이는 주소는 파일명과 분리한다.** 파일은 한글·번호 접두 그대로 두고,
웹 주소만 영문 클린 URL로 제공한다 — 한글이 `%EC%9E%90…`로 깨져 보이는 문제와
확장자 노출이 함께 해소된다.

| 구분 | 예 |
|---|---|
| 파일(저장소) | `pages/자금_결의전표_입력_2026.html` |
| 공개 주소 | `https://ai.jeilm.co.kr/work/voucher` |

- **단일 출처**: 저장소 루트 **`_routes.py`**. 여기 한 줄 추가 후 `python _build_routes.py --write`
  → `vercel.json` 리라이트 재생성 + 문서·화면의 내부 링크를 클린 URL로 일괄 치환한다.
- **네임스페이스**: `/main`(포털) · `/work/…`(부서 운영페이지) · `/admin/…`·`/vendor/…`(관리·협력사)
  · `/survey/…`(니즈조사) · `/docs/…`(기획·관리 문서) · `/demo/…`(데모) · `/tools/…`(도구).
- **슬러그는 영문 소문자·하이픈**. 연도는 붙이지 않는다(`/work/sales-orders`, `/work/sales-orders-2026` ✗).
- **기존 `.html` 주소도 계속 동작**한다(파일 그대로 + Vercel `cleanUrls` 자동 리다이렉트) →
  기존 북마크·외부 링크 무효화 없음. 리네임이 아니라 **주소 계층 신설**이다.
- 빌더(`_html_builder.py`·`_build_bundle.py`·`08/03`·`그리드`)는 이 표를 참조하므로
  **재생성해도 클린 URL이 유지**된다.
- 라이브 포털의 부서 카드 경로는 **DB `public.portal_page.path`** 가 정본 → 라우트 변경 시
  같이 갱신한다(정본 SQL: `실제구축준비 자료/이관/sql/28_portal_page_clean_url.sql`).

## 3. 배포본 vs 데모본 구분 (의도적 중복)

같은 화면이 두 위치에 존재하는 것은 정당하며 정리 대상이 아니다.

| 용도 | 위치 | 예 |
|---|---|---|
| **기획/데모본** | `08_협력사발주포털/02_데모/` | `협력사_모바일_포털.html` |
| **배포본**(라이브·포털 연결) | `pages/` | `협력사_모바일_포털.html`, `외주발주_검사진행현황_2026.html` |

변경 시 **배포본을 정본**으로 삼고, 데모본은 기획 스냅샷으로 유지한다.

## 4. MD ↔ HTML 쌍 규칙 (단일 출처)
- 기획·관리 문서는 **`.md`가 단일 출처**, `.html`은 `_build_html.py` **자동 생성본**(손으로 고치지 않음).
- 적용 폴더: `00_관리체계/`, `실제구축준비 자료/이관/`, `08/03_실구축기획/`.
- 공통 빌드 로직: `00_관리체계/lib/_html_builder.py`. 각 폴더 `_build_html.py`는 문서 목록·라벨만 정의.
- `index.html`(허브)은 자체완결 대시보드 → 빌드 제외, 직접 관리.

## 6. README 표준 템플릿

새 폴더/영역을 만들 때 아래 골격으로 `README.md`(또는 `00_*` 인덱스)를 둔다.

```markdown
# [영역명]

> 관리: [담당] · 기준 규칙: 루트 CLAUDE.md
> 한 줄 목적.

## 폴더 구조
(트리 + 각 파일 한 줄 역할)

## 단일 출처
(이 영역의 정본 문서 = 무엇)

## 갱신 규칙
(언제 무엇을 갱신하는가 + 변경 시 03_변경관리_CHANGELOG 기록)

## 관련 문서
(상위/연관 문서 링크)
```
